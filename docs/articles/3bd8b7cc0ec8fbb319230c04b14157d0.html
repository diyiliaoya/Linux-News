Intel 为 Linux 7.5 准备变更以更好地处理大显存多 GPU 配置

Intel 工程师提交变更，将内核图形驱动中 GEM/TTM 缓冲对象的 mmap 范围从 1TB 扩大到 8TB，以解决多 GPU 系统大显存下跨设备 dma-buf 导入耗尽 1TB 偏移空间导致缓冲创建失败的问题。该变更已进入 drm-misc-next 拉取请求，预计随 Linux 7.5 内核合入。

Intel 为 Linux 7.5 准备变更以更好地处理大显存多 GPU 配置

2026 年 11 月 20 日下午 2:41（美国东部时间）。

一项将随即将到来的 Linux 7.5 内核周期合入的变更集，将内核图形驱动中 GEM/TTM 缓冲对象的 mmap 范围大小从 1TB 扩大到最高 8TB。

将上限从 1TB 提高到 8TB 是为了支持拥有大量显存的多 GPU 配置。该变更由 Intel 完成，从补丁的时间点推测，可能是为每卡最高 160GB LPDDR5X 的配置做准备。

Intel Linux GPU 驱动工程师 Matthew Auld 解释称：

“每个 GEM/TTM 缓冲对象（包括导入的 dma-buf）都会从每设备的 drm_vma_offset_manager 分配一个伪造的 mmap 偏移。在拥有大显存的多 GPU 系统上，跨设备和跨进程的点对点 dma-buf 导入可能耗尽当前 1 TiB 的 64 位范围，导致缓冲对象创建或 PRIME 导入失败并返回 -ENOSPC。跳过为导入的 sg 缓冲分配 mmap 偏移并不简单，且可能带来用户空间回归风险，因为现有用户空间（如 Intel compute-runtime）在直接映射 dma-buf fd 时仍会查询导入的主机 dma-buf 的 mmap_offset。

在 64 位内核上增大 DRM_FILE_PAGE_OFFSET_SIZE，使伪造偏移范围最高可达 8 TiB（SZ_8T）。这仍严格低于 panthor 的 DRM_PANTHOR_USER_MMIO_OFFSET_32BIT（1ULL << 43）保留区，并处于 32 位兼容 mmap2 的 pgoff 限制（4K 页时为 16 TiB）之内。”

将 DRM_FILE_PAGE_OFFSET_SIZE 上限提高到 8TB 的变更通过本周的 drm-misc-next 拉取请求进入 Linux 7.5。
