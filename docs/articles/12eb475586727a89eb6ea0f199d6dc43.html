Linux 7.3 TPM 为 TrenchBoot 进行清理准备工作

发布于 2026年8月28日 下午3:05（美国东部时间）

Linux 7.3 内核的可信平台模块（TPM）子系统变更主要集中在代码清理和改进上，这些工作是 TrenchBoot 支持的前奏。

TrenchBoot 是一个历时多年的开源项目，旨在通过利用硬件支持的动态信任根测量（DRTM）来增强启动安全性和完整性。多年来，Oracle 一直是 TrenchBoot 的主要支持者之一，用于保护启动过程。

TrenchBoot 利用了 AMD 和 Intel 的安全技术，并且还需要对 GRUB 引导加载程序和 Linux 内核等进行更改。Linux 内核补丁尚未上游化，但为 Linux 7.3 合并的 TPM 更改对于使 TrenchBoot 有可能进入主线内核是必要的。

Jarkko Sakkinen 在补丁中解释道：

“这部分的大部分是 Ross Philipson 为 TrenchBoot 提供的 TPM 支持。它暴露了 TPM 常量，并解耦和增强了 tpm_buf 的健壮性，以便实现一个最小的早期 TPM 驱动。

早期启动代码将在跳转到内核入口点之前调用 AMD 的 SKINIT 或 Intel 的 GETSEC[SENTER]。它们会重新初始化 TPM PCR，但将测量 initrd、boot_params 和 TrenchBoot 相关元数据的任务留给早期启动代码。

这里的动机只是希望在未来的系列迭代中，将我们的全部精力集中在 x86 部分的审查上，而 TPM 更改则就此告一段落。此外，即使 TrenchBoot 最终被证明是空头彩票，TPM 驱动最坏的结果也只是进行了一些清理。”

因此，无论如何这都是一个胜利。虽然 TrenchBoot 本身不会在 Linux 7.3 内核周期中到来，但那些想了解这一启动安全功能的人可以在此了解更多。
