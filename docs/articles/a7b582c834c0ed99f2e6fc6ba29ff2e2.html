Linux 7.3 有望成为多年来最注重性能的内核版本之一

Linux 7.3 的合并窗口仍在开放，但已确认多项性能优化：存储方面，EXT4 和 XFS 文件系统通过 IOmap 反弹缓冲、日志与 fsync 修复、缓存 v2 等改进，大幅提升吞吐量；调度器方面，针对 AMD GPU 的调度优化和 Intel 混合 CPU 的集群感知调度修复，减少了卡顿；内存管理方面，修复了反向映射和 zsmalloc 的锁延迟问题；实时工作负载的延迟显著降低；RISC-V 新增多个 ISA 扩展支持。这些改进使 7.3 成为近年来最注重性能的版本。

Linux 7.3 有望成为多年来最注重性能的内核版本之一

合并窗口仍然开放，但更快的文件系统、更智能的调度器和实时延迟修复已经就位。

几天前我们在 X 上发帖，称 Linux 7.3 是多年来最注重性能的版本之一。现在，回顾自那以来合并窗口中实际落地的内容，这一说法似乎确实成立。

本版本的合并窗口在 7.2 发布后立即开启，除非有最后一刻的变动导致关闭时间推迟，否则将持续到本月底。

以下是目前确认将进入 7.3 版本的内容。

存储性能大幅提升

EXT4 一次性获得了多项更改。直接 I/O 现在通过 IOmap 反弹缓冲区运行，而不是回退到缓冲 I/O，将原本最高只能达到理论最大吞吐量一半的工作流程提升到接近 95% 的理论最大值。

日志和 fsync 路径中的两个独立修复各自带来了约 5 倍的提升：一个修复移除了多个日志任务同时运行时的不必要延迟，另一个修复在完整 fsync 期间跳过了对包含大量 extent 但没有空洞的文件进行不必要的空洞检测。

EXT4 缓存也从 v1 迁移到 v2，这是一个更安全且更快的选项，之前尚未成为默认。

XFS 也进行了一系列工作。并行直接 I/O 写入现在被允许，而此前文件系统过于严格；多块分配器通过批量分配跳过了不必要的工作。

在这两个文件系统之下，是一个重新设计的块层，基于单个迭代器回调构建，编译器可以内联该回调，而无需进行间接分发。

你无需为这些做任何事。一旦升级到 7.3，它们就会自动生效，而 IOmap 更改在快速 NVMe 上收益最大，将 EXT4 从 192 万 IOPS 提升到 219 万 IOPS。

重要的调度器工作

调度器现在围绕单个就绪队列进行调度，取代了旧的、容易出问题的设计。Peter 在一台老旧的 Sandy Bridge 机器上搭配 AMD Radeon RX 580 进行了测试，帧率和帧时间一致性都有显著提升。

如果你在性能不佳的硬件上玩游戏，这一改进应该会减少卡顿感。

Intel 混合 CPU 也得到修复。集群感知调度此前未能正确处理集群间的唤醒，而这一修复填补了 Alder Lake、Lunar Lake 和 Panther Lake 上的这一空白。

实际上，这意味着当你的笔记本电脑在处理繁重任务（如源码编译、游戏或视频导出）时，后台任务争夺小核资源，卡顿会减少。

内存管理修复

ZTE 工程师发现了一个反向映射中的 bug，该步骤在内核接触合并页之前检查哪些内存区域指向该页。在高负载下，一个内部锁可能卡住数百毫秒，冻结其他尝试使用它的操作。

延迟从约 700ms 降至 2ms 以下。简单来说，这意味着服务器和容器在内存压力下随机冻结的情况会减少。

小米工程师 Wenchao Hao 在 zsmalloc 中发现了类似的减速问题，zRAM 和 Zswap 使用 zsmalloc 来存储压缩内存。

在测试中，一个 20 核 Intel 系统上的性能提升高达 1.83 倍。通俗地说，在 Raspberry Pi 等低端板上你会感受到更快的响应，而在更强大的硬件上也有较小但真实的提升。

实时工作负载的更低延迟

每当一个 CPU 核心使用内核的 IPI 代码要求其他核心立即执行某项操作（如刷新内存缓存）时，内核过去会冻结该 CPU 上的所有其他任务，直到所有其他核心响应。

现在，其他任务可以继续运行，而不是被冻结。在繁忙的系统上，这种冻结等待可能会拉长并阻塞高优先级任务。

在使用 DPDK（一个为快速网络而构建的框架）的集群测试中，最慢请求的最坏情况延迟从约 17ms 降至约 1.5ms。大多数桌面用户不会注意到这一点，但对于网络和实时软件来说，这是一个重要的修复。

RISC-V 增加了对十一个更新的 ISA 扩展的支持。

EFI 运行时调用现在会超时，而不是无限期挂起。
