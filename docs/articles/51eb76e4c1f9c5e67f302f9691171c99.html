Systemd 希望引入 Rust，但其核心部分仍需等待

Systemd 已合并支持用 Rust 编写其程序，但 Rust 仍为可选，且仅限新的独立程序。共享库 libsystemd 仍保留在 C 中，因为 Rust 缺乏共享库支持。文件系统访问也是障碍，systemd 依赖文件描述符路径查找。Systemd 表示愿意与 Rust 社区合作，将 Rust 引入核心。Linux 内核和 Ubuntu 也在接纳 Rust，表明其采用将加速。

Systemd 希望引入 Rust，但其核心部分仍需等待

Rust 化正在进行中，现在允许使用 Rust 编写的程序，现有 C 代码不会被移植。

大多数主流 Linux 发行版使用的初始化系统和服务管理器 systemd，已合并了用 Rust 编写其程序的支持。该支持通过一个拉取请求进入了主分支，取代了早先的提案，并遵循维护者在最近柏林黑客松上商定的规则。

第一个使用它的程序是 systemd-keyring-setup，它在启动时、锁定内核密钥环之前，将 X.509 证书添加到内核密钥环中。

如果你还记得，我们最近谈到了 Amutable 为其新产品提供的东西。总之，让我们看看他们现在在做什么。

Rust，但按 systemd 的规则来

按照他们遵循的方法，Rust 保持可选，systemd 仍然可以在没有它的情况下构建。Rust 代码的范围仅限于新的独立程序，不依赖其他任何东西，而所有构建都不包含它。只允许使用特定的 crate，这排除了标准库和 alloc。程序将使用 systemd 自己的类型，分配失败将返回错误而不是 panic。Rust 程序还必须像其 C 对应程序一样行为，对于声明相同命令的程序，有测试检查这一点。

构建 Rust 程序需要拥有工具链。启用所有功能构建 systemd 的发行版，如 Arch 和 openSUSE OBS，将不得不安装 Rust 工具链或关闭 Rust 支持。

共享库问题

systemd 程序共享的库 libsystemd 目前仍保留在 C 中。将 Rust 放入其中需要 Rust 本身提供适当的共享库支持，而该语言仍然没有。Rust 程序像 C 程序一样使用该 C 库，将 Rust 放入其中会在库和许多 systemd 二进制文件之间重复相同的代码。

文件系统访问是另一个障碍，因为 systemd 通过文件描述符查找路径以保持该步骤安全，并且不接受 Rust 的标准路径处理用于其敏感组件。它希望 Rust 也能支持这种方法。

systemd 仍然希望将 Rust 引入其核心，并表示愿意与 Rust 社区合作。

systemd 并不是 Linux 栈中唯一为 Rust 腾出空间的部分。这种内存安全语言随着 6.1 进入 Linux 内核作为探索性努力，内核维护者在去年年底宣布实验已经结束。Ubuntu 一段时间以来在其核心工具中也采取了同样的路线，当时它成为默认体验。

所有这些都强烈表明，随着我们进入非常繁忙的 2027 年，Rust 的采用只会加速。
