Canonical 开始向 Ubuntu Pro 用户推送 AI 编写的安全补丁

Canonical 推出名为 Surge 的多智能体 AI 系统，用于自动分类漏洞并编写 Ubuntu 软件包的安全回溯补丁。该系统采用多个竞争性 AI 模型生成候选补丁，再由评审模型达成共识，低置信度案例转交人工处理。生成的补丁不会自动进入常规更新，而是先发布到需用户主动选择的 Edge 归档库，经人工测试后才进入正式更新。此举旨在应对 AI 辅助漏洞发现导致的 CVE 数量激增问题。

Canonical 开始向 Ubuntu Pro 用户推送 AI 编写的安全补丁

Canonical 构建了一个 AI 系统来修补 Ubuntu 的 CVE。该系统名为 Surge，它使用相互竞争的 AI 模型编写并验证安全回溯补丁。修复补丁会进入一个单独的、需用户主动选择的“Edge”归档库，而不会进入你的常规 Ubuntu 更新。

如果你关注了今年的安全新闻，就会知道已报告漏洞的数量急剧上升。AI 辅助的漏洞挖掘意味着缺陷被发现的速度超过了维护者的修补速度，每个发行版都感受到了压力。

Canonical 的应对策略是以毒攻毒。他们打算用 AI 来修复 AI 发现的问题。在最近结束的 Ubuntu Summit 26.10 上，Canonical 介绍了 Surge——一个多智能体 AI 系统，用于对漏洞进行分类并为 Ubuntu 软件包编写回溯修复补丁。

别担心。这些都不会自动进入你的常规 Ubuntu 安全更新。Surge 的修复补丁会进入一个名为 Edge 归档库的新可选仓库，只有在经过人工主导的测试后才会进入常规更新。

Canonical 试图解决的 CVE 问题

这一消息是在峰会开幕致辞的安全环节中宣布的，由工程副总裁 Pierre Guillemin 介绍。

他从数字开始。根据幻灯片，Ubuntu 的“修复速度”在一年内提高了 119%。“按季度修复量”图表显示，2025 年初约有 1,400 个修复，到 2026 年中期每季度约有 3,100 个。

还不止这些。Canonical 表示，仅 2026 年 10 月的 CVE 数量就几乎与 2025 年全年相当。

而且 Canonical 预计这不会放缓。Guillemin 表示，公司预计 2027 年 CVE 将带来“又一个数量级的增长”。

如何在坚持稳定 Ubuntu 版本所著称的审查和测试标准的同时跟上这一步伐？招聘和更努力地工作实际上无法与这种速度竞争。

Surge 是“一个用于修复 Ubuntu 漏洞的多智能体编排框架”。

简而言之，它是一个流水线，多个专业化的 AI 智能体处理修复 CVE 的不同步骤，从确定 Ubuntu 是否受影响，到生成补丁。

Guillemin 表示，它建立在 Canonical 20 多年的 Ubuntu 安全工作基础上。既定目标是吸收大量涌入的 CVE 而不产生积压。或者，正如他所说，“用 AI 对抗 AI”。

Surge 仅覆盖 Ubuntu 用户空间软件包，即归档库中的应用程序和库。内核 CVE 不在其范围内，因为内核修复需要不同的回溯方法，并遵循自己的发布周期。

该流水线有六个阶段，有趣的是它不信任单一的 AI 模型。

它从接收和溯源开始，接收漏洞报告，将其映射到软件包，并检查受影响的软件包是否在 Ubuntu 中。然后代码取证获取上游补丁，分析源代码，并尝试复现漏洞以确认 Ubuntu 的版本确实受影响。

在回溯引擎中，不是由一个模型编写补丁，而是由多个竞争模型各自生成候选修复。

这些候选修复随后进入共识评审，由一个单独的“评审”模型小组进行评估，并且必须就正确的补丁达成一致。如果置信度低或评审陷入僵局，案例将转交人工升级处理，由 Ubuntu 安全工程师手动审查。

最后，补丁经过与其他 Ubuntu 软件包相同的构建、验证和发布流程，包括确定性测试，然后才发布。

Edge 归档库：AI 修复，但仅在你主动要求时提供

Surge 生成的修复不会通过常规安全更新推送到你的系统。相反，Canonical 正在推出 Edge 归档库，这是一个仍在开发中的修复的可选预览。

Edge 让你在机器生成的补丁经过 Canonical 全面通用可用性（GA）资格认证之前就能获得它们。因此你可以在“机器可……”阶段获得修复。
