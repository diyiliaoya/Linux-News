Rhythmbox 3.5 让你跨应用同步播客收听进度

Rhythmbox 3.5.0 发布，这是该音乐播放器九个月来的首次更新。新版本引入了播客插件，支持通过自托管同步服务器（如 Nextcloud）在 Rhythmbox 与其他应用之间同步播客订阅和收听进度。播客页面也经过重新设计，显示已收听集数，并重新设计了通知。此外，歌词功能得到增强，默认从 lrclib.net 获取歌词，并支持读取 .lrc 文件或嵌入在 .ogg 文件中的歌词。最重要的变化是默认启用多流（multistream）后端，取代了 xfade，利用现代声音系统（如 PipeWire）进行混音，减少代码维护负担。同时修复了 2038 年时间问题。用户可通过 Flatpak 安装体验。

Rhythmbox 3.5.0 已发布，现在它允许你在不同应用之间同步播客订阅和收听进度。

这款音乐播放器九个月来的首次更新增加了一个新的播客插件，该插件与自托管同步服务器（如 Nextcloud）集成，因此你的订阅和播放计数可以在 Rhythmbox 和你使用的其他应用之间同步。

播客页面本身也经过了刷新，剧集列表会显示你已经听过的内容，这样你就不会产生似曾相识的感觉。更新说明还提到，播客通知也经过了重新设计。

Rhythmbox 3.5.0 还关注了歌词功能。该插件默认从 lrclib.net 获取歌词，播放器可以读取与曲目一起保存的 .lrc 文件或嵌入在 .ogg 文件中的歌词（但后者需要 GStreamer 1.25.90 或更高版本）。

但这里最大的变化，也是值得在十多年的 3.4.x 版本之后开启 Rhythmbox 3.5.x 系列的原因，在于后端。

Tributary 是 Rhythmbox 的“现代”版本

Rhythmbox 3.4.9 于去年年底发布，带有可选的“多流”播放器后端。该后端在 3.5.0 中默认启用，取代了 xfade。

为什么会有这个变化？为了现代化。

Xfade 构建了一个音频管道，并在启用交叉淡化时自行混合音轨。

多流则让每条音轨通过自己的管道运行，并让现代声音系统（如 PipeWire）处理混音——据说它们在这方面做得更好。

此外，将任务卸载给系统声音服务器意味着 Rhythmbox 需要维护的代码更少（也不会被那些推测性的 AI 安全报告所困扰）。

除了这些变化，Rhythmbox 3.5.0 还修复了臭名昭著的“2038”问题中的 32 位时间处理，解决了一些小问题，并更新了一些打包元数据。

想试试吗？你可以从源码构建 Rhythmbox 3.5.0——尽管我在 Ubuntu 26.04 LTS 上构建失败了——或者，为了省事，你可以安装 Flatpak 版本。目前该 Flatpak 尚未验证，但那是另一回事。

提醒 Ubuntu 用户，上游 Rhythmbox 看起来与仓库中的版本略有不同，因为发行版应用了一些 UI 修改，使其与桌面其他部分更匹配。
