Ubuntu 26.10 在安全启动下放弃 Btrfs、XFS 和 ZFS 的 /boot 支持

Canonical 调整了 Ubuntu 26.10 在启用安全启动时的引导方式，其签名的 GRUB 不再支持从 Btrfs、XFS、ZFS、LVM、LUKS 加密或软件 RAID 等文件系统读取 /boot，仅保留 ext4、FAT、ISO9660 和 squashfs。此举旨在减少引导链中的解析器数量，降低安全启动绕过漏洞的风险。禁用安全启动则不受影响，普通用户通常也不会受影响。

Ubuntu 在安全启动下放弃 Btrfs、XFS 和 ZFS 引导支持

Canonical 改变了 Ubuntu 26.10 在启用安全启动的系统上的引导方式，目的是减少引导过程的攻击面。

Ubuntu 26.10 中签名的 GRUB 构建版本（仅在系统开启安全启动时使用）不再支持从 Btrfs、XFS、ZFS、LVM、LUKS 加密或软件 RAID（RAID1 除外）读取。HFS+、Apple 分区表支持以及 JPEG 和 PNG 图像加载也已被移除。

由于 GRUB 需要读取 /boot 目录来加载内核并引导 Ubuntu，如果这些文件位于受影响的文件系统上，GRUB 将无法访问它们，系统也就无法启动。

Ubuntu 26.10 在启用安全启动时仍然支持从 ext4、FAT 和 ISO9660（用于从 CD/DVD 启动）读取 /boot，当然也支持用于 snap 的 squashfs。

如果禁用安全启动，则会加载 GRUB 的完整功能集，这意味着特殊的 /boot 配置以及任何 GRUB 自定义调整（例如图像背景）都能正常工作。

Canonical 为何做出这一改变？

Canonical 今年早些时候分享了精简 GRUB 的计划。客气地说，反馈相当激烈，因为一些使用定制引导设置的用户——其中一些是通过操作系统安装程序中的“实验性”功能创建的——听说自己可能无法启动后并不高兴。

这就是为什么 Canonical 在 LTS 版本之后才做出这一改变；那些需要安全启动下完整 GRUB 功能的用户可以继续使用 Ubuntu 26.04 LTS。该版本在 Ubuntu Pro 下支持到 2036 年，在 Ubuntu Pro 加 Legacy Add-on 下支持到 2041 年。

安全是这里的目标。

GRUB 是 Ubuntu 引导链中最早的部分。在标准的安全启动设置中，设备固件加载一个名为 shim 的程序，由它验证并加载 GRUB。随后解析器会探测文件系统和分区布局以进行读取，找到内核并加载它。

但近年来，这些解析器已成为众多安全启动绕过漏洞的来源——LLM 正在使漏洞被发现乃至被利用的速度加快。

Canonical 的理由是，在内核加载之前运行的解析器越少，破坏保障引导安全的“信任链”的机会就越少。

大多数用户不会受到影响

尽管这听起来变化很大，但它只影响在启用安全启动的设备上引导 Ubuntu 26.10，而且只影响引导路径本身。

在启用安全启动的系统上，LVM、RAID、LUKS、Btrfs 和 ZFS 在 Ubuntu 26.10 中仍然可用和可访问——只是要在系统启动之后。

如果你担心这会影响到你，请在下个月升级到 26.10 之前，检查任何自定义的 /boot 布局是否属于上述支持类型列表。

然而，大多数 Ubuntu 用户不会受到影响，因为标准的操作系统安装程序会以标准且对安全启动友好的方式进行设置。
