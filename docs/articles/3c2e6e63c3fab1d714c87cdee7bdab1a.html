Kmorph 旨在提供无需重启的 Linux 内核崩溃恢复

Kmorph 是一个新的开源项目，旨在为 Linux 系统提供无需重启的内核崩溃恢复。它基于多内核（Multikernel）技术，通过预先启动一个备用内核，在主内核崩溃时快速接管，实现约 2 秒的 Nginx 等服务恢复。该系统支持 x86_64 和 ARM64，并计划支持 RISC-V。目前 Kmorph 无法在主线内核上运行，其广泛采用取决于多内核代码能否进入主线。

Kmorph 旨在为 Linux 系统提供无需重启的内核崩溃恢复，在内核崩溃的情况下，恢复 Nginx Web 服务器或其他重要服务可能仅需约 2 秒的停机时间。

这个名为 Kmorph 的开源项目于周五宣布，用于实现这种无需重启的内核崩溃恢复，它基于过去一年在树外进行的工作。因此，至少目前，Kmorph 无法在主线 Linux 内核上运行，多内核代码何时能进入主线还有待观察。

多内核（Multikernel）提供多个独立的内核实例在同一物理系统上共存，由此开辟的一个用例是：当一个内核崩溃时，能够快速过渡到另一个内核，实现相当快的恢复。借助 Kmorph，系统可以在不重启的情况下经受内核崩溃：

“使用多内核，每个内核拥有自己的 CPU、内存和设备，内核之间通过 vsock 通信。kmorph 利用这一点，用接管取代两次重启。第二个内核（后继者）提前在一个或两个 CPU 以及运行中的内核（前任者）旁边的一块内存上启动，并监视它。当前任者发生 panic 或挂起时，后继者隔离其 CPU，接管并重置其设备，恢复网络身份，可选地保存 kdump 兼容的 vmcore，然后热添加剩余的 CPU 和内存，成为机器的内核。检测到运行中的后继者大约需要一秒钟，无需重启、无需固件、无需操作员。

同样的接管也提供了实时内核更新：‘kmorph upgrade’ 将健康的机器移交给运行更新内核的后继者。无论哪种方式，新内核都可以武装自己的后继者，一代又一代。

所有新颖的工作都在多内核内核中：隔离、设备和 IOMMU 交接，以及从主机设备树热添加 CPU 和内存。kmorph 是其接口之上的纯 C 编排，并像 kdump 一样通过 dracut、initramfs-tools、kernel-install 和 systemd 服务与发行版集成。它目前可在 x86_64 和 ARM64 上运行，RISC-V 支持正在进行中。”

Kmorph 还支持在回退内核上以待机方式运行重要 systemd 服务的概念，以便服务恢复可以非常快。以 Nginx 为例，在内核崩溃时，它可以在短短两秒内恢复在线，随后其他不太重要的服务启动。

主线 Linux 内核确实具有 Kexec Handover (KHO) 和 Live Update Orchestrator (LUO) 功能，但目前不支持类似的内核崩溃恢复，内核更新仍然需要 Kexec 重启，也无法承受内核崩溃。

Kmorph 是一个有趣的概念，具有很大潜力，尽管其广泛采用取决于多内核进入主线的未来。
