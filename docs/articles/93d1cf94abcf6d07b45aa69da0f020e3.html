Linux 7.3 的 IOmap 改进进一步提升 EXT4 与 XFS 性能

Linux 7.3 开发内核已合并 VFS 拉取请求，其中包含对 IOmap 框架的改进。IOmap 现已完全转换为迭代器模型，采用单一的 iomap_next() 回调，减少了间接调用，使编译器能生成直接且可内联的调用，从而提升性能。该改进尤其对 EXT4 文件系统的小型 I/O 操作带来显著提升，在 PCIe Gen5 NVMe SSD 上，4K 随机读性能从约 1.92M IOPS 提升至 2.19M IOPS，提升幅度在 4% 至 10% 之间，具体取决于 I/O 模式。此外，该更新也惠及 Btrfs、F2FS、XFS 等多个文件系统。

IOmap 改进为 Linux 7.3 带来 EXT4 与 XFS 性能进一步提升

发布于 2026 年 8 月 18 日下午 1:25（美国东部时间）

作为已合并至 Linux 7.3 开发内核的 VFS 拉取请求的一部分，IOmap 框架得到了改进。该框架被多种文件系统用于将内存中的逻辑文件字节偏移映射到存储上的物理位置。借助现已合并的代码，这一现代块映射框架至少为 EXT4 文件系统带来了更好的性能。

在 Linux 7.3 中，IOmap 已完成向迭代器模型的转换，并迁移至单一的 iomap_next() 回调。通过这一改动，每次迭代不再需要间接调用，编译器可以将其转换为直接调用，从而支持内联。

这一 IOmap 拉取请求还克服了 PCIe Gen5 NVMe SSD 存储上小型 I/O 的瓶颈。

对于最终用户而言，令人兴奋的是最终结果，正如拉取请求中关于 EXT4 性能影响的说明所述：

“这还为小型读取添加了一个简单的直接 I/O 路径。在 Gen5 NVMe 上，__iomap_dio_rw() 主导了 4K 随机读取。相同的单核 io_uring 轮询模式工作负载在原始块设备上可达到约 3.2M IOPS，但通过 ext4 或 XFS 仅约 1.92M。

在原始工作负载中，这使 ext4 从 1.92M 提升至 2.19M IOPS。fio 显示大约：

* 在 libaio 队列深度为 64 及以上时提升约 4%

* 对于 io_uring 提升约 5%

* 对于 io_uring 轮询模式在深度 256 时提升高达 10%

在 ext4 和 xfs 上均如此。”

虽然仅展示了 EXT4 和 XFS 的这些数字，但此次 IOmap 更新也已更新至 Btrfs、EXT2、EROFS、F2FS、GFS2、HPFS、FUSE、exFAT、ZoneFS、NTFS 和 NTFS3 文件系统。
