Ubuntu 宁愿先杀掉你的应用，也不愿让会话崩溃

Ubuntu 26.10 调整了内存耗尽时的处理策略：将 GNOME Shell 和两个 D-Bus 服务等 39 个维持会话的服务设置为 OOM 分数 -500，使其更不容易被内核杀死，而浏览器等占用大量内存的应用则更可能被优先终止。同时，Canonical 关闭了 systemd-oomd 中可能因内存压力直接终止整个会话的设置，改为在 50% 压力时仅作用于用户会话。该策略已随 ubuntu-settings 26.10.1 发布。

Ubuntu 26.10 将带来一项改动，旨在内存耗尽时保持桌面环境存活。

Ubuntu 26.10 正在改变内存耗尽时系统会杀掉什么。应用程序应当首先被终止，而维持会话的服务现在则排在它们后面。其中 39 个服务被移至 OOM 分数 -500，包括 GNOME Shell 和两个 D-Bus 服务。

这使得它们被 OOM killer 选中的可能性大大降低。相反，像浏览器这样占用机器大部分内存的程序，则更可能成为被清理的对象。

Canonical 还关闭了仅因内存压力就可能终止整个会话的设置。不过这一改动附带一个限制：当内存耗尽时，应用仍可能被终止。

该策略已通过 ubuntu-settings 26.10.1 实施，并已发布到相关仓库。

内核看到了什么？

在内存压力下，内核会列出每个进程的清单。它根据每个进程可计入的内存进行评分，然后再加上一个数字。这第二个数字就是 Ubuntu 可以为你设置的。它的范围从 -1000 到 1000，停留在该范围的最低端意味着进程会被踢出候选顺序。

Canonical 引用的一份报告显示了 2024 年 Ubuntu 24.10 桌面上该列表的样子。GNOME Shell 为 100，Firefox 也是 100，它生成的每个内容进程同样是 100。

系统守护进程的分数则低得多，为 -250。造成内存紧张的原因是报告者自己代码中的一个逻辑错误，它触发了一连串虚拟机，导致机器内存耗尽。

结果，OOM killer 选择了一个小应用并将其杀死，而虚拟机则毫发无损。

分数只是一半原因

内核并不是桌面上唯一会执行终止操作的东西。systemd-oomd 会监控内存压力，并且比内核更早采取行动，而且完全不看这些分数。

Ubuntu 将其设置为在用户会话压力达到 50% 时采取行动，因此仅靠 -500 的数值本身并不能挽救任何东西。同一个 ubuntu-settings 补丁也处理了 oomd 方面。

ManagedOOMMemoryPressure 现在被设置为 50%，而之前是 systemd-oomd 的“默认”设置。在 Canonical 自己的测试中，没有该修复时，十个会话中有七个死亡；有了该修复后，一个都没有死亡。

如果你想现在就查看新行为，该改动已经在相关仓库中。Canonical 正在请求人们在内存或交换空间不足的机器上，用消耗内存的工作负载来测试它。

如果你遇到任何意外行为，例如突然终止或会话崩溃，可以通过相关渠道报告。
