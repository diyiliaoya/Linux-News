Btrfs 为 Linux 7.3 准备更多性能改进：部分场景提升约 3 倍至 5 倍

SUSE 的 David Sterba 提交了针对 Linux 7.3 合并窗口的 Btrfs 文件系统更新，包含多项性能改进。Btrfs 现使用 IOmap 反弹缓冲区处理直接 I/O，性能从理论最大值的约 50% 提升至约 95%，几乎翻倍。同时，用本地 LRU 列表替代 XArray 跟踪受抑制的 extent 缓冲区，性能提升约 3 倍；在非 SSD 模式下移除不必要的 jiffy 延迟，吞吐量提升约 5 倍；全 fsync 跳过空洞检测逻辑也带来 5 倍提升。此外，Btrfs 默认禁用 free-space v1 代码，改用 v2，并包含多项错误修复。

SUSE 的 David Sterba 今天提交了针对 Linux 7.3 合并窗口的 Btrfs 文件系统特性更新。除其他更改外，此版本 Linux 内核还包含更多性能改进。

Linux 7.3 中的 Btrfs 现在使用 IOmap 反弹缓冲区进行直接 I/O，而不是回退到缓冲 I/O。合并请求指出，过去正确性与速度之间的权衡使性能降至理论最大值的约 50%，而现在则提升至约 95%。换句话说，性能实际上翻倍了。

Btrfs 还使用本地 LRU 列表替换了 XArray，用于跟踪受抑制的 extent 缓冲区，这可以带来约 3 倍的性能提升。通过移除非 SSD 模式下多个日志任务中不必要的 jiffy 延迟，延迟降低，同时示例工作负载的吞吐量提升约 5 倍。另一个 5 倍提升来自全 fsync 期间对无空洞但具有大量 extent 的文件跳过空洞检测逻辑。Btrfs 还在锁定等方面进行了其他性能改进。

Btrfs 现在还默认禁用 free-space v1 代码，转而使用多年来一直是默认的 free-space v2。此外，还有大量错误修复和其他代码改进。
