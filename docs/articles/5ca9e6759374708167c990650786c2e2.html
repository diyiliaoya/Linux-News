Rust 1.98 新增代数浮点方法，类似“-ffast-math”

发布于 2026 年 8 月 20 日下午 1:29（美国东部时间）。

Rust 1.98 今日发布，其亮点是引入了新的代数浮点方法。

Rust 1.98 引入了代数浮点方法，类似于在其他语言/编译器中使用“--fast-math”选项。Rust 1.98 的发布公告解释了这些优化的代数方法：

“浮点类型 f32 和 f64 现在拥有用于加法、减法、乘法、除法和取余的“代数”方法。这些方法允许利用实数的代数性质对这些运算进行优化，尽管这些性质在浮点表示的局限性下并不成立。具体的优化集合未作规定，但可能类似于其他语言中 -ffast-math 选项所提供的优化。

例如，浮点加法不满足结合律，因此像 a + b + c + d 这样的和必须按照解析时的左结合顺序计算，即 ((a + b) + c) + d。如果你将同样的和写成一系列 algebraic_add 调用，编译器就可以自由地重新排序，或许可以像 (a + b) + (c + d) 那样同时计算部分和。使用这些代数方法通常还能实现更广泛的循环向量化。

这些方法是非确定性的，因为编译器可以自由选择不同的优化，但它们绝不会导致未定义行为。”

类似于在其他地方使用 -ffast-math，公告还指出：

“由于编译器优化的不可预测性，即使在同一程序运行中，相同的输入也可能产生不同的结果。不安全代码不得依赖返回值的任何属性来保证健全性。然而，实现通常会尽力在性能与结果准确性之间做出合理的权衡。”

这些代数方法的出现源于一个性能问题：在现代 x86_64 CPU 上，由于编译器不重新排序浮点运算以进行更好的向量化，Rust 中简单点积运算的速度比 C++ 慢最多 8 倍。

Rust 1.98 还带来了缓冲整数格式化及其他更改，详见公告。
