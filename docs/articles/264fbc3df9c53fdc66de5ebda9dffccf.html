Linux 开始为富士通 MONAKA CPU 缺陷引入规避措施

富士通正式发布面向 AI 基础设施的 144 核 Arm 服务器处理器 MONAKA 后，Linux 内核本周出现多个针对该 CPU 缺陷的规避补丁。这些补丁引入了 MONAKA 的 CPU 类型检测，并分别解决 TLB 失效、PMU 溢出误判以及 CPU 核心挂起三类问题。

Linux 开始为富士通 MONAKA CPU 缺陷引入规避措施

2026 年 10 月 4 日 06:31 EDT。

富士通正式宣布其 MONAKA CPU，这是一款面向 AI 基础设施的 144 核 Arm 服务器处理器。此前两年间，我们已经看到针对 GCC 编译器和其他开源组件的各种补丁。如今 MONAKA 正式发布，我们看到更多 Linux 内核补丁浮出水面，本周就出现了多个针对 MONAKA CPU 缺陷的规避措施。

作为一款 ARM64 CPU 设计，富士通 MONAKA 在 Linux 支持方面总体状况良好——尤其是在服务器领域符合标准，无需为 MONAKA 服务器处理系统设备树之类的问题。本周的补丁引入了 Linux 内核中的 MONAKA CPU 类型检测，以便为不同缺陷提供规避措施。

MONAKA 的第一个规避措施针对的是：基于范围的 TLBI 操作在针对 VA 或 IPA 时，在某些情况下可能无法使 TLB 条目失效。因此 Linux 内核需要发出额外的 TLBI 指令，以确保正确的 TLB 失效发生。这仅在 MONAKA 使用 64K 内核时存在，但出于性能原因，无论如何都推荐使用 64K 内核。

还有一个针对另一个缺陷的规避措施：PMU 溢出可能被错误检测。这反过来可能导致 MONAKA 上出现中断风暴。

本周针对 Linux 上 MONAKA 的第三个规避措施是处理可能的 CPU 核心挂起。问题在于，当 SGI 生成时，如果该操作与 CPU 处理更高优先级中断、更新待处理中断或 PE 转换到睡眠状态发生竞争，SGI 可能会丢失。在这种情况下，系统寄存器写入无法完成，可能导致发出请求的 CPU 核心挂起。

有兴趣的读者可以通过这个 MONAKA 补丁系列了解更多。
