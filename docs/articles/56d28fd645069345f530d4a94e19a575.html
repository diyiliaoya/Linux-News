F2FS 在 Linux 7.4 中新增可选的多粒度时间戳及其他改进

Linux 7.4 为 F2FS 文件系统合并了多项改进，包括引入专用的元数据缓存基础设施、动态参数化磁盘块布局和几何宏，并将元数据、节点和压缩块移出 VFS 页缓存，为未来支持大 folio 和页大小不等于块大小铺路。此外，F2FS 新增可选的多粒度时间戳支持，加入异步 write_end_io 完成的 bio 条目数节流，并通过 sysfs 暴露 resizable_tail 特性。同时修复了压缩、mmap 写缺页、检查点/关机、文件系统冻结等场景的竞态条件，并增强了磁盘健全性检查。

F2FS（Flash Friendly File-System）的改进已为 Linux 7.4 合并，进一步增强这一面向闪存优化的解决方案。

Linux 6.4 中的 F2FS 带来了专用的元数据缓存，有助于允许页大小与块大小不同，类似于其他 Linux 文件系统中正在进行的工作。同时为未来支持更大的 folio 打开了大门。

F2FS 现在还提供可选的多粒度时间戳支持。多粒度时间戳允许混合使用粗粒度和细粒度时间戳，用于增强 NFS 缓存一致性等场景，而不会损害性能。EXT4、Btrfs、XFS 等已经支持多粒度时间戳。

此外，为 Linux 7.4 合并的代码还包含各种 F2FS 错误修复和其他改进。

“在这一轮中，关键增强集中在引入专用的元数据缓存基础设施，并动态参数化磁盘块布局和几何宏。将元数据、节点和压缩块移出 VFS 页缓存，消除了元数据的页 == 块大小假设，这与动态块布局描述一起，为未来支持大 folio 和页 != 块铺平了道路。我们还选择启用多粒度时间戳，为异步 write_end_io 完成添加 bio 条目数节流，并通过 sysfs 暴露 resizable_tail 特性。

除了这些特性，关键错误修复解决了压缩、mmap 写缺页、检查点/关机和文件系统冻结中的竞态条件，防止顺序分区设备上的写 bio 拆分和 GC 空洞，并加强对 SIT/NAT 位图、只读 curseg 条目和设备别名的磁盘健全性检查。额外的稳定性补丁解决了在线调整大小、前滚恢复、原子文件操作、配额处理和脏 inode 同步活锁问题。”

总而言之，这是一轮不错的增量改进。
