Denial WM：全新 Wayland 合成器，直接嵌入 Flutter

2026年8月5日 下午12:10 EDT。

最新值得讨论的 Wayland 合成器是 Denial，它专注于 Arch Linux 的优化集成，并将 Flutter 引擎直接嵌入代码库。Denial 使用 Rust 编程语言，并借助 Smithay 处理合成器职责。

Denial 目前被视为 alpha 软件，是一款 Flutter 原生的 Wayland 合成器。Denial 的首席开发者致信 Phoronix，并解释了其设计：

“Denial 并非将 Flutter 作为应用运行在其他合成器之上：它直接嵌入 Flutter 引擎，而 Rust 和 Smithay 合成器负责处理 Wayland 协议状态、输入、DMA-BUF、DRM/KMS 呈现以及原生资源生命周期。

基于 Wayland DMA-BUF 的应用缓冲区通过 EGL_EXT_image_dma_buf_import 作为 GPU 纹理导入 Flutter 场景，无需 CPU 回读、像素拷贝或纹理上传。

Flutter 直接渲染到用于 KMS 呈现的 GBM 缓冲区。没有中间渲染目标、最终 blit 或第二次合成器传递。

Denial 已成为我的日常桌面：

- 原生 Wayland 应用（如 Chromium、Firefox、Blender、Discord）

- Steam 和要求较高的 Proton 游戏（我测试了《明日方舟：终末地》《鸣潮》《无限暖暖》和《最终幻想 XIV》）在我的测试中均完美运行

- 多显示器配置，为 nwg-displays 实现了专用 Denial 后端，并已准备好提交上游

- 音频，支持按窗口音量控制

- 屏幕锁定和 DPMS

- 屏幕共享（已用 OBS 测试）

- 带 CI/CD 的签名 Arch 包

该项目还保留了正常的 Flutter 开发工作流：一个可选的开发包提供 Flutter Inspector、DevTools 和热重载，用于实时桌面外壳，无需重启合成器或关闭运行中的应用。在 Denial 运行时，可以启用或禁用性能分析和调试模式。

Denial 使用定制的 Flutter 引擎和 Skia 构建，带有合成器特定优化，包括外部纹理损伤跟踪、专门的帧调度以及消除热绘制依赖路径中的堆分配。优化在桌面合成器中至关重要，因此大部分工作都花在优化低且一致的帧时间上。”

这看起来是一个有趣的项目，至少比一些其他 Wayland 合成器有更多原创目标。

想了解更多关于 Denial 的信息，可以访问其官方网站，GPLv3+ 代码托管在 GitHub 上。
