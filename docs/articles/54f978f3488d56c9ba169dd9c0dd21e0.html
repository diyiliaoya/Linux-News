Mold 高速链接器正在用 Rust 重写，有望成为 Linux 默认链接器

高性能链接器 Mold 正在从 C++ 重写为 Rust，并计划在 3.0 版本中实现成为 Linux 系统默认链接器 /usr/bin/ld 的目标。主要开发者 Rui Ueyama 表示，将补齐链接脚本功能、进行广泛兼容性测试，并与发行版开发者合作推动采用。同时也在探索增量链接支持。

Mold 高性能链接器通常性能优于 LLVM lld、GNU LD、Wild 等，目前正在用 Rust 编程语言重写，并设定了成为 Linux 系统默认链接器的雄心目标。

Mold 2.42.1 于今天发布，是该开源链接器的新补丁版本。但 Mold 2.42.1 公告中最引人关注的是关于其继任者 Mold 3.0 的计划。Mold 一直在从 C++ 重写为 Rust。如今 Rust 语言经过多年发展已足够成熟，Mold 计划利用其强大的安全保障以及其他特性，这些特性对首席开发者 Rui Ueyama 颇具吸引力。此前已有另一个性能导向的链接器是用 Rust 编写的。

Rui 希望用 Rust 编写的 Mold 3.0 在高速链接方面能与 Mold 2.xx 表现一样出色。除此之外，Rui 还希望看到 Mold 成为 Linux 系统上的默认链接器：

“过去 20 年里，出现了多个快速链接器，包括 gold、lld 和 mold。然而，大多数 Linux 发行版上的系统链接器 /usr/bin/ld 仍然是 GNU ld。结果，mold 可以在几百毫秒内完成的链接任务，使用默认链接器仍可能需要几秒、几十秒甚至几分钟。我认为这对 Linux 社区来说是一种不幸的局面。

作为 lld 和 mold 的原始作者，我认为我对这种情况负有一定责任。我花费了大量精力让链接器更快，但在兼容性工作上投入不够，而这是让快速链接器适合作为系统链接器直接替代品所必需的。通过 mold 3.0，我们打算改变这一点。mold 3.x 系列的主要目标之一，是让 mold 适合被 Linux 发行版采用为 /usr/bin/ld。

为实现这一目标，我们首先需要实现缺失的链接脚本功能，使 mold 不仅能链接用户空间程序，还能链接内核和固件。然后我们将进行广泛的兼容性测试，并与 Linux 发行版开发者密切合作，使他们能够实际采用 mold 作为 /usr/bin/ld。实现这一目标是 mold 3.x 的最高优先级之一。”

Mold 也在考虑最终支持增量链接，这是该链接器迄今为止尚未支持的功能：

“话虽如此，如果我们能找到一种简单的方法为 mold 添加增量链接，我们会很乐意去做。它仍可能显著改善某些工作负载。我们目前正在探索既能提供这些好处，又能保持 mold 简洁性和可靠性的设计。”

有兴趣了解 Mold 链接器项目这一重大转变更多细节的人，可以在 Mold 2.42.1 公告中找到。
