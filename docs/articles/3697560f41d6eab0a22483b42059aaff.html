Canonical 为 Launchpad 添加 FIDO2 硬件密钥支持

Canonical 为其开发者平台 Launchpad 增加了 FIDO2 硬件安全密钥支持，用于保护 API 访问。开发者现在可以使用 USB 安全密钥来限制 API 访问，即使登录凭证被盗，没有物理密钥也无法使用。该功能通过将存储的令牌替换为需要物理密钥才能使用的长期 OAuth 刷新授权来实现，每次登录需触摸密钥并输入 PIN 码，从而生成短期令牌用于日常请求。

现在可以使用 USB FIDO2 安全密钥来限制 API 访问，这使得任何被盗的登录凭证在没有密钥的情况下变得毫无用处。

Launchpad 是 Canonical 构建 Ubuntu 软件包、托管代码、PPA 以及许多最终出现在用户系统上的其他内容的地方，我相信你知道这一点。

开发者工具（如）使用保存的令牌登录，这些令牌通常以文本文件形式保存在开发者的机器上或桌面密钥环中。任何获取到它的人（包括恶意软件）都可以冒充他们，并拥有其携带的权限。

“对大多数人来说，这是可接受的风险”。对于核心发行版开发者、工程师和软件包上传者呢？嗯，他们有更多损失，可能成为坏人的“诱人目标”（不是 Tommy Wiseau 那种）。

这就是 Launchpad 添加对硬件绑定 API 令牌支持的原因。

这些令牌将存储的令牌替换为“长期 OAuth 刷新授权”，如果没有连接物理安全密钥，该授权几乎无法做任何事情。登录需要触摸密钥并输入其 PIN 码。这会颁发一个短期令牌用于日常请求。

密钥保护存储的授权，因此以开发者登录状态运行的恶意软件仍然可以在其（短暂的）生命周期内使用任何短期令牌，但它无法请求新的令牌。
