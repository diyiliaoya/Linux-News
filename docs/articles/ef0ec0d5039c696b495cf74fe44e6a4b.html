Linux 网络子系统将 50 多项修复推迟至下一内核，仍受 AI 驱动的变更洪流冲击

在 Linux 7.3-rc7 发布前，网络子系统维护者将 50 多项修复推迟到 Linux 7.4，因为 AI/LLM 驱动的补丁和错误报告持续激增，导致维护者不堪重负。尽管已要求各子树大幅精简提交，本周的拉取请求规模依然庞大，包含以太网驱动回归修复、联发科 MT76 WiFi 驱动修复等。

在定于周日发布的 Linux 7.3-rc7 内核之前，本周的一批网络修复已提交并合并。有线和无线驱动以及各种其他网络功能组成的庞大网络子系统，由于 AI 驱动的错误报告和补丁，继续呈现出大量活动。

由于 Linux 7.3 周期已进入后期，且 AI/LLM 驱动的世界仍带来大量补丁活动，一些网络修复开始被推迟到 Linux 7.4。因此，那些并非特别紧迫的修复开始被排入 net-next，而不是匆忙塞进 Linux 7.3。Linux 网络维护者此前已经表示，他们被所有的 AI 活动“彻底淹没”。他们还一直面临着 AI 垃圾补丁带来的挑战。

在本周的网络拉取请求中，有人指出他们现在已将 50 多个补丁转移到 net-next 以供 Linux 7.4 使用，而不是硬塞进 Linux 7.3。然而，本周为 7.3-rc7 提交的内容仍然是一个巨大的拉取请求。Jakub Kicinski 评论道：“很确定你不会对这个 PR 的规模感到满意，但这是在我们削减了 50 个修复到 net-next 并要求各子树大幅精简其 PR 之后的结果。情况就是这样。”

在明天发布的 Linux 7.3-rc7 中，可以找到各种以太网驱动回归修复、联发科 MT76 WiFi 驱动修复，以及各种其他“类似 LLM”的修复。
