Zapscape：Linux KVM 客户机到宿主机逃逸及本地提权的最新漏洞

Zapscape 是一个影响 Linux KVM x86 代码的客户机到宿主机逃逸漏洞，自 2020 年内核变更引入，影响范围达六年。该漏洞源于影子 MMU 模拟代码中的释放后使用问题，攻击者可通过客户机操作使宿主机内核崩溃（DoS）或执行任意代码（RCE）。在 RHEL 等发行版中，/dev/kvm 为全局可写，非特权用户可利用此漏洞进行本地提权。该漏洞已于 7 月 21 日修复，并公开了概念验证代码。

Zapscape 是影响 Linux KVM x86 代码的客户机到宿主机逃逸漏洞，该漏洞已存在六年。今天早些时候，该漏洞被公开。2020 年对 KVM x86 的内核变更也可被用作本地提权（LPE）漏洞，因为在某些 Linux 发行版（如 RHEL）中，/dev/kvm 是全局可写的。

Zapscape 是一个 KVM 逃逸漏洞，允许 KVM x86/x86_64 客户机逃逸到宿主机，并以 root 权限在宿主机上执行命令。该漏洞围绕 x86 代码路径中基于内核的虚拟机（KVM）的影子 MMU 模拟代码中的释放后使用漏洞展开。

随着今天的公告、漏洞的炫酷图形和相关信息的发布，还公开了一个概念验证（PoC）示例，尽管并非武器化形式。

受影响的 Linux 内核版本从 2020 年年中到 7 月 21 日，该问题通过检查 MMU 页面可用后的无效/过时根目录而得到修复。

仅通过客户机侧操作，攻击者就可以破坏运行其虚拟机的宿主机。例如，攻击者只需在公共云上租用一个实例，就可以使宿主机内核崩溃，从而击垮同一物理机器上的所有其他租户虚拟机（DoS），或者以 root 权限在宿主机上运行代码，从而接管宿主机及其上的所有客户机（RCE）。

在 RHEL 等发行版中，/dev/kvm 是全局可写的（0666），因此非特权用户也可以利用此漏洞作为本地提权（LPE）来获取 root 权限。当用作 LPE 时，宿主机侧的 VMM ioctl 可用，因此漏洞利用变得更加容易和稳定。

关于 Zapscape 的更多详细信息，请参阅 Zapscape GitHub 仓库。
