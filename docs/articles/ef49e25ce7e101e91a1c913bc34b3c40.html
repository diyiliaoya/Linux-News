Linux 7.4 减少 AI 噪音的新功能因 VFIO 子系统中的“疯狂野兽”已被回退

2026 年 10 月 31 日 08:15 AM EDT 发布。

上周为 Linux 7.4 合并的一项新功能——旨在减少由无效/不相关测试配置产生的 AI/LLM 噪音——现已因 VFIO 子系统中的“疯狂野兽”而被回退。

Greg Kroah-Hartman 早在 9 月就设计了 TAINT_FORCED_BIND 选项，用于在 Linux 的 bind/unbind sysfs 接口被使用时污染正在运行的内核。该接口允许将硬件任意绑定/解绑到给定驱动。在 AI/LLM 时代，该接口被 Syzbot 及其同类滥用，试图将硬件绑定到彼此不相关的驱动上。这导致这些工具/机器人提交的无关错误报告产生噪音，而这些报告并不匹配任何合法的内核使用场景。

因此，有了 TAINT_FORCED_BIND，内核开发者就能在错误报告中清楚地看到使用了 sysfs bind/unbind，从而帮助快速推断这可能不是合法的错误报告。

该功能上周为 Linux 7.4 合并，Greg KH 将其描述为针对内核的近期大规模模糊测试“攻击”。

然而在 TAINT_FORCED_BIND 合并之后，人们才意识到 VFIO 代码在合法实践中依赖 bind/unbind 行为。Greg 在描述中称 VFIO 的用法为“疯狂野兽”：

“事实证明，vfio 是一头疯狂野兽，人们一直‘依赖’bind/unbind 调试功能作为将设备透传给客户机实例的一种处理方式。正因如此（https://xkcd.com/1172/），我们暂时回退该功能，直到我们能找到一种更[可接受]的方式来处理，使得正常工作流不会污染内核。

很可能 Uwe 在以下地址提出的方案：

https://lore.kernel.org/lkml/

将是最佳前进方向，并将在 7.4 之后重新审视。

该功能最初旨在遏制不必要的模糊测试报告——即随机设备被绑定到随机驱动上、当然事情出了错、报告‘驱动损坏’。主要的 syzbot 工具现在已不再这样做，希望没有其他人再启动它（但在如今 LLM 的疯狂中，你无法确定。）”

VFIO 依赖 bind/unbind 来将 PCIe 设备从 Linux 主机驱动分离，并附加到 vfio-pci 以便在虚拟机内使用。

Uwe Kleine-König 的提案是仅在 driver_override 的使用中使用 TAINT_DRIVER_OVERRIDE，并默认禁用 driver_override，同时允许 Linux 驱动选择允许自身进入。我们将看看这是否最终会被 Linux v7.5 采纳，但对 v7.4 来说已经太晚，合并窗口预计明天关闭。
