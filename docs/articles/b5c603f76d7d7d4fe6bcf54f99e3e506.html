Ubuntu 云镜像再次意外移除软件包

Ubuntu 26.04 LTS 最小云镜像再次意外丢失软件包，这次是用于以十六进制查看文件的 CLI 工具 xxd。这是继 8 月 curl 被误删后的第二起同类事件，原因均为 Canonical 移除 systemd 的 random-seed 工具后调整依赖链所致。Canonical 已恢复 26.04 镜像中的 xxd 和 curl，但已在 26.10 最小镜像中移除 xxd。无头服务器环境使此类缺失更难被发现。

Ubuntu 云镜像再次意外移除软件包 - OMG! Ubuntu

又一个软件包从 Ubuntu 26.04 LTS 的最小云镜像中消失了，这次是 xxd，一个用于以十六进制查看文件的 CLI 工具。

这是继我 8 月报道的 curl 意外消失之后的第二次此类事件。

两个软件包因相同原因消失。

当 Canonical 移除 systemd 的 random-seed 工具（该工具用于在启动期间生成“随机性”）时，它重新调整了镜像“seed”中的依赖链。原本被它拉入的软件包不再被包含。

xxd 并未出现在最初的镜像集中，但仍可从 Ubuntu 的归档中安装。

Canonical 此后已将 xxd（以及 curl）恢复到 26.04 的最小云镜像中。虽然 xxd 软件包对操作系统的运行远非关键，但 Canonical 表示“不想让那些已经习惯依赖它存在的人感到退步”。

对 xxd 而言，这仅仅是缓刑。Canonical 此后已从 26.10 最小镜像中移除 xxd（并非从归档中移除；它仍可使用 apt 安装）。

与桌面环境不同——在桌面上缺失的软件包很容易被发现——无头服务器设置使得判断某个工具是否存在更加困难，在这里更是如此，因为它并非操作系统关键组件或常见用例。

但尽管这件事溜了过去可能令人不安，知道就连 Ubuntu 开发者也会被纠缠的依赖链意外移除东西所坑，让我感到一种释然。

这些镜像通常用于安全和软件包安装受到严格管控的场合。并非每个人都能直接安装，即使大多数会使用它的人可以。这其实是一个更广泛的问题。
