XNULinux 让你无需虚拟机在 Linux 上运行 macOS

开源项目 XNULinux 将苹果的 XNU 内核作为模块加载到 Linux 内核中，使 macOS 桌面能在 ARM Linux 上原生运行，无需虚拟机。目前项目高度实验性，GPU 支持不完善，图形由 CPU 渲染，安装过程复杂，需要 ARM64 设备、至少 16GB 内存和 4KB 内存页的 Linux 内核，且需自行拥有 macOS 27 安装文件及装有 Xcode 的 Mac。

XNULinux 在 ARM Linux 上原生运行 macOS

一个新开源项目将苹果的 XNU 内核作为模块加载到 Linux 内核内部，使 macOS 桌面能够原生运行——无需虚拟机。

该项目是开源的、高度实验性的，苹果方面很可能不会乐见其成。不过他们倒不至于暴跳如雷，因为用户目前还不能轻易下载并自行运行——至少现在还不能。

在 GitHub 上，XNULinux 的开发者展示了 macOS 27 Golden Gate 桌面在 NVIDIA DGX Spark（其默认操作系统基于 Ubuntu 24.04 LTS）上运行的截图。

核心 Mac 应用和组件可以工作，网络功能也正常，但 GPU 支持尚未完善，因此图形由 CPU 渲染。它能在同一 CPU 上让 macOS 进程与 Linux 进程并肩运行。

面向大众？不，但很有趣

怎么做到的？它将苹果的 XNU 内核源代码构建为一个模块，加载到未经修改的 ARM64 Linux 内核中。第二个模块充当中间人，为苹果内核提供其所需的来自 Linux 的内存、CPU 时间和网络访问。

这不是兼容层，也没有任何系统间应用集成的迹象。它不会把 Mac 软件添加到 GNOME 应用选择器中，也不会在上下文菜单中显示 Linux 应用。不过，你可以从 macOS 内部通过 SSH 连接到 Linux 主机。

虽然已经可以在虚拟机中于 Linux 上运行 macOS，但 XNULinux 不依赖虚拟化或 hypervisor，这使得该功能更加令人印象深刻。

它是否会成为可用的东西，或许重振黑苹果社区，值得怀疑。该项目不得不修补或放宽 macOS 的一些安全功能才能工作，尽管开发者将其描述为“权宜之计”。

尝试 XNULinux 并不容易……

尝试这个项目不适合胆小的人，因为没有简单的下载双击安装程序或 bash 脚本。

你还需要一台 ARM64 设备、至少 16GB 内存以及使用 4KB 内存页的 Linux 内核。此外，你需拥有 macOS 27 安装文件、能访问一台装有 Xcode 的 Mac，以及耐心。实际上，需要极大的耐心。

最新的 macOS 仅支持苹果芯片（ARM64），因此这项工作无法在 Intel/AMD 硬件上运行。如果能的话会更有趣，而 macOS 26 是最后一个支持 x86-64 硬件的版本，目前仍受苹果支持——但愿如此。

如果你未被吓退，XNULinux 的 GitHub 上有大量（由 LLM 撰写的）细节，说明其工作原理、哪些部分尚不可用以及如何让它运行起来。如果你尝试了，记得回来告诉我你的看法。

如果你有 M1 Mac 或更新机型，也可以在虚拟机中安装合适的 Linux 发行版，然后努力进行设置来尝试。从这个意义上说，它确实使用了虚拟机，只是间接使用。
