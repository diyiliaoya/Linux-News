Gelly：一款适用于 Jellyfin 和 Navidrome 的 GTK 桌面音乐播放器

Gelly 是一款用 Rust 和 GTK4/libadwaita 编写的原生轻量级桌面音乐播放器，专为 Jellyfin、Navidrome/Subsonic 等自建流媒体服务器设计。它提供现代界面，支持浏览、播放和控制音乐，具备“播放相似”功能、MPRIS 支持、歌词显示、ReplayGain、无缝播放等特性。用户可通过 Flathub 在 Ubuntu 上安装，Arch 用户可从 AUR 获取。

如果你使用 Jellyfin 或 Navidrome/Subsonic 运行自己的音乐流媒体服务器，并且想要一个可靠的桌面播放器来浏览和流式播放你的音乐库，那么 Gelly 正是为此而生。它被描述为上述流媒体服务器（以及兼容服务器）的“原生、轻量级音乐播放器”。它使用 Rust 和 GTK4/libadwaita 编写，并且像任何优秀的播放器一样，让你浏览、播放和控制音乐播放。

而且它通过现代的设计和布局来完成所有这些。

最近我在树莓派 4 上设置了 Jellyfin（以替换其老旧的、积满灰尘和绒毛的安装），本周在 Flathub 首页看到 Gelly 感觉时机真是太好了。

一款现代的 Jellyfin 桌面播放器

“播放相似”功能很方便

Gelly 不是独立的桌面音乐播放器，所以在你将它指向你的 Jellyfin 或 Navidrome 服务器之前，它不会做任何事情。幸运的是，该应用有一个简单的设置向导来处理这些。

http://your-server-ip:8096

以及你的服务器凭据，经过短暂的加载屏幕后，你的音乐就会过滤进来。选项允许你触发服务器上的重新扫描（用于新文件、更新的元数据等）并刷新 Gelly 中的数据。

默认视图是专辑，以网格形式显示大型艺术图（我在播放器的设置中启用了紧凑模式，这就是你在我截图中看到的）。还有艺术家、播放列表和曲目视图。大多数视图中都提供排序选项。

我喜欢的一个功能是“播放相似”操作，你可以将其应用于选定的歌曲、专辑或艺术家。如果你正从 Spotify 等流媒体音乐服务迁移回来，这些可能是一种不错的舒适体验。

对主视图进行排序

由于这是一个前端，你不会找到许多高级设置（没有元数据编辑、Jellyfin 仪表板、插件等）。所有这些都通过你的 Jellyfin 或 Navidrome 设置完成。

Gelly 支持 MPRIS，因此你使用的任何媒体控制器（包括 Playerctl 等扩展）都可以从中转发和报告播放信息。

如果你喜欢跟着唱，Gelly 还可以显示歌词（如果可用，支持逐行同步）。

Gelly 支持实时歌词

其他功能包括 ReplayGain、无缝播放和曲目收藏。

选项允许你禁用“额外的视觉糖果”，取消模糊背景效果等花哨的装饰，并启用紧凑模式。你还可以防止系统在活跃播放期间挂起，并设置特定的转码设置（如果需要）。

我最近才开始使用 Jellyfin，所以我的需求很简单。我之前在本地使用 MPD，虽然我可以通过它远程运行和访问我的音乐，但专用的设置似乎更合理。

我相当适应 Gelly（别叹气）。如果你想看看你是否也适应，它可以从 Flathub 安装在 Ubuntu 上（Arch 用户会在 AUR 中找到它）。

设置 Jellyfin 也相当容易，只需几个命令和仔细阅读。与其他客户端相比，我并没有因为任何特定原因选择 Jellyfin；它是我第一个想到的。
