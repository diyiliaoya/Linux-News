AMD PerfOpt 性能提升代码在 Linux 7.4-rc2 中调整

Linux 7.4-rc2 对 AMD PerfOpt 功能进行了 IOMMU 相关代码调整。PerfOpt 允许集成 GPU 绕过 IOMMU 直接访问系统内存，默认在 AMDGPU 驱动中启用，可为 AI/LLM 等工作负载带来 iGPU 性能提升。此次修改将启用逻辑从 amdgpu 策略参数移至 IOMMU 驱动，并移除了 amdgpu.iommu_perfopt 模块参数。Linux 7.4 稳定版预计 12 月底发布。

在 Linux 7.4 众多令人兴奋的变更中，一项值得关注的开箱即用性能改进是针对带有集成 Radeon 显卡的 AMD SoC 的新“PerfOpt”功能。AMD PerfOpt 可以带来不错的 iGPU 性能提升，尤其是对 AI/LLM 工作负载。随着今天 Linux 7.4-rc2 内核的发布，IOMMU 区域的 PerfOpt 代码有一些调整。

AMD PerfOpt 允许集成 GPU 在直接访问系统内存时绕过 IOMMU。对于 iGPU，该功能在 AMDGPU 驱动中默认启用。该功能不仅限于最新最好的 Radeon iGPU，甚至能为前代硬件带来性能提升。

在 IOMMU 修复拉取请求中，PerfOpt 代码有一些调整。AMD Linux 工程师 Mario Limonciello 解释了现已合并到 Linux Git 中的变更：

“PerfOpt 可供集成 GPU 在 identity 模式下使用。从 IOMMU 驱动的域附加路径启用它，而不是要求 amdgpu 策略开关和导出的启用/禁用接口。

在选择默认 identity 域时，将受支持的集成 GPU 标记为符合 PerfOpt 条件。对于这些 identity 附加，跳过 GCR3 设置和 ATS/PRI/PASID 启用，然后在安装 DTE 后启用 PerfOpt。在将符合条件的 GPU 附加到转换域或阻塞域（包括 VFIO 使用的非托管域）之前，清除 PerfOpt。传播清除绕过失败，但如果可选的 PerfOpt 启用失败，则保持已完成的 identity 附加成功。

在初始化期间清除继承的 PerfOpt 状态，包括崩溃内核重用设备表时。直接从硬件读取功能支持，因为缓存的功能可能尚不可用，如果初始清除失败则停止初始化。

每个 IOMMU 最多有一个符合 PerfOpt 条件的 GPU，因此在 IOMMU 锁下用布尔值跟踪激活状态。在挂起和关机时清除硬件时保留此状态，并在恢复时仅在曾激活的位置恢复该位。不要在早期 IOMMU 期间无条件启用 PerfOpt。

移除 amdgpu 参数、驱动回调和导出接口。转换附加保留其正常的设备能力设置。”

对于错过了直接比较 PerfOpt 在其硬件上性能影响机会的用户，amdgpu.iommu_perfopt= 模块参数现已被移除。无论如何，请关注 Linux 7.4 中的这项有用改进，稳定版预计在 12 月底左右发布。包含此代码的 Linux 7.4-rc2 预计今天晚些时候发布以供测试。
