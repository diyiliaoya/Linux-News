Scrcpy 5.0 为 Android 镜像添加硬件解码支持

Scrcpy 5.0 发布，新增零拷贝硬件解码支持，默认启用并自动检测解码后端（如 Linux 上的 VA-API），可将主机 CPU 占用降低多达 10 倍。同时改进了音频捕获选项和视频色彩过滤，修复了 UHID 键盘模式及 OTG 模式下的若干问题。该工具免费开源，支持 Windows、macOS 和 Linux。

Scrcpy 5.0 为 Android 镜像添加硬件解码支持 - OMG! Ubuntu

这款用于从桌面查看和控制 Android 手机的开源工具，在其最新版本中新增了对零拷贝硬件解码的支持。

该功能是 v5.0 的新特性，利用你计算机的硬件来解码从 Android 屏幕发送的视频流，以便镜像到桌面（通过 USB 线缆或 IP/TCP）。它提升了性能；主机设备的 CPU 占用最多可下降 10 倍。

Scrcpy 默认启用硬件解码（无需传递标志），并自动检测可用的解码器后端，例如 Linux 上的 VA-API。

解码器可以通过标志手动选择，该功能支持

hwdec 使用更少的 CPU（截图：scrcpy）

在 Ubuntu 上，使用 VA-API hwdec 需要安装相应的软件包（如果尚未安装）。软件解码仍然可用，既可以强制选择，也可以在合适的 hwdec 不可用时作为回退方案。

Scrcpy 5.0 的其他改进包括：一个用于更广泛音频捕获的选项，以修复游戏音频缺失的问题（同时在未传递标志时保留现有的仅媒体行为），以及在缩放过程中对视频颜色进行一致的过滤。

错误修复解决了各种问题，包括在 UHID 键盘模式下使用按键时的异常行为，而 OTG 模式现在可以使用环境变量来选择特定设备。

Scrcpy 是适用于 Windows、macOS 和 Linux 的免费开源软件。请从项目 GitHub 下载最新版本。它本身没有“官方网站”，因此如果你使用 macOS 或 Windows，请仅从 GitHub 获取。

Linux 用户有更多选择，因为旧版本的 Scrcpy 可以从 Ubuntu 仓库安装。这些版本不具备上述硬件解码功能，但仍然可用。

Snap Store 上的非官方 Scrcpy snap 将很快更新到 v5.0。

音频转发仅在运行 Android 11 或更高版本的设备上可用。
