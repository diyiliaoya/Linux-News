Linux 7.4 将并行移除 NVMe 命名空间以提升速度

Linux 7.4 内核将合并一项 NVMe 优化：移除命名空间时改为并行处理。此前逐个移除每个命名空间需等待约 20 毫秒的 RCU 宽限期，64 个命名空间耗时超过一秒。新方案通过异步域并行移除，使宽限期重叠，显著缩短控制器断开等场景的耗时。

作为本周为 Linux 7.4-rc4 内核版本准备的块子系统修复的一部分，有许多错误修复，还有一项不错的 NVMe 命名空间优化。

本周的块修复并不太令人兴奋，延续了 AI/LLM 驱动的内核活动流。我觉得最有趣的是 Linux NVMe 代码的改动，现在可以并行移除命名空间。对于那些通过 NVMe 命名空间将 NVMe 存储设备分割为逻辑隔离存储卷的用户来说，移除命名空间将比现有内核版本更快。NVMe 命名空间代码对于多租户环境、工作负载隔离、安全性等非常有用。

到目前为止，Linux NVMe 命名空间移除代码只是一个接一个地移除命名空间，这在一些复杂的现代 Linux 服务器部署中可能成为瓶颈。

软件工程师 Qiliang Yuan 解决了 NVMe 命名空间代码中的这个缺陷。Yuan 解释说：

“nvme_remove_namespaces() 一个接一个地移除控制器的命名空间。每次移除都要在 del_gendisk() 中等待命名空间及其多路径头的 RCU 宽限期，总共约 20 毫秒。

因此，删除控制器（例如从 fabrics 目标断开连接）所需时间与其命名空间数量成正比，64 个命名空间需要超过一秒。扫描也有同样的问题，直到提交 4e893ca81170（“nvme_core: scan namespaces asynchronously”）使命名空间并行添加。

以同样的方式通过异步域移除命名空间，并在返回前等待所有命名空间。每次移除仍然等待约 20 毫秒，但等待现在重叠了：宽限期是系统范围的，因此同时等待的移除会被相同的宽限期释放，而不是每个都需要自己的宽限期。”

最终，这对使用 NVMe 命名空间的用户来说是一项有用的优化。

该变更已通过本周的合并进入 Linux 7.4 内核。
