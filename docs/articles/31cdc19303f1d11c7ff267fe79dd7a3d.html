AI 生成了大量“丑陋”代码，但发现了加速 Linux 编译的主要瓶颈

一位 ARM 工程师利用 AI/LLM 发现了显著加速 Linux 内核构建的方法。通过并行化内核构建过程中的多个单线程瓶颈，实现了全模块内核构建提速约 36%，增量构建提速高达 70%，noop 构建提速约 90%。该工程师承认 LLM 生成了大量“丑陋”代码，但经过人工审计和重写后，补丁已提交。涉及 Kbuild、kallsyms、modpost、objtool、mksysmap 和 Rust 构建系统等多个领域。

一位 ARM Linux 工程师利用 AI/LLM 帮助发现了一些“显著加速”Linux 内核构建时间的改进。在此过程中，LLM 生成了“大量代码，其中大部分很丑陋”，但最终被用来通过在内核构建过程的不同领域实现更多任务并行化，从而找到了显著节省时间的方法。

ARM 工程师、资深 Linux 开发者 Lorenzo Stoakes 今天发布了这组 23 个补丁，旨在“显著加速内核构建”。从根本上说，这是为了解决内核构建过程中在单线程瓶颈上花费的大量时间。最终，他发现启用所有模块的内核构建速度提高了约 36%，增量内核构建速度提高了高达 70%，noop 构建速度提高了约 90%。

Lorenzo 指出，使用了一个未命名的大型语言模型（LLM）来发现这些瓶颈并解决它们，随后他亲自审计和评估了这些代码。Lorenzo 写道：

“LLM 首先用于确定瓶颈所在，然后找出改进方法。

它生成了大量代码，其中大部分很丑陋。

我广泛地审计并重写了其中许多代码，并大量编辑了提交信息、封面信和注释。

LLM 还协调了构建运行、测试、调试和分析。

我已手动检查了应用此系列补丁后生成的内核在构建和运行时的正确性。

性能改进也已手动验证。

由于广泛使用了 LLM，每个提交都带有 Assisted-by 标签。”

这些补丁致力于并行化许多单线程任务，并提高构建过程的效率。Kbuild、kallsyms、modpost、objtool、mksysmap 和 Rust 构建系统等领域都受到了这项工作影响。
