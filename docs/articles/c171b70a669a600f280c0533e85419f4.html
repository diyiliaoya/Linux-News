Linux 7.3 将引入改进 vRAM 管理的初始代码，更多改进即将到来

2026年8月17日下午5:15（美国东部时间）

今年早些时候，Valve 的 Linux 图形团队工程师 Natalie Vock 提出了一些补丁，用于改善在 vRAM 受限系统上的 Linux 游戏体验。这些改进视频内存管理的内核工作将随 Linux 7.3 内核引入。虽然这本身已值得庆祝，但 Vock 仍在追求更多改进，以优化 Linux GPU 驱动程序的视频内存管理行为。

随着初始补丁已排队进入 DRM-Next，并计划在接下来的两周内合并到 Linux 7.13 合并窗口，Natalie Vock 今天发布了一篇新博客文章，概述了改进 Linux vRAM 管理的最新工作和成果，尤其是针对 AMDGPU 驱动程序。

Vock 的博客文章篇幅较长但内容详实，重点介绍了视频内存管理、驱逐处理以及使用《夺宝奇兵：大圆环》进行的测试中的诸多细节。测试中，她尝试将设置调至最高，以消耗 9GB 视频内存，而显卡仅有 8GB vRAM。即使超支 1GB，游戏在 8GB 显卡上仍然相当可玩。

Vock 在最新文章中总结道：

“当一切尘埃落定，vRAM 耗尽时的表现如何？

我认为相当不错！在许多情况下，即使驱逐 1GB 或更多的内存，你可能会惊讶于性能仍能保持多少！但话说回来，这当然是一个相当乐观的情况，如果错误的数据最终进入 CPU 内存，可能会很快导致非常显著的性能下降。驱逐要做到恰到好处是很棘手的，而且在某种程度上，性能总会受到影响。如果一款游戏即使在所有内容都在 vRAM 中时也难以达到 30fps，那么在此基础上还需要驱逐某些内容，有时可能不可避免地无法达到 30fps 的目标。

无论如何，我希望这篇博客文章能够证明，即使最终有一些内存被驱逐到系统内存，性能下降也是可以控制的。驱动程序（尤其是内核驱动程序）可以采取措施，使超支尽可能高效地工作，甚至应用程序也可以与驱动栈协调，以减轻其内存被驱逐的影响。当一切到位时，vRAM 超支其实并不像乍一看那么严重。”

这项工作已经应用于 SteamOS 内核的稳定版和预览版频道。除了 Linux 7.3 的初始上游化工作外，进一步的改进仍在进行中，以便在未来某个主线 Linux 内核版本中上游化。

相关补丁集名为“vramstuff-rebase”，包含所有补丁，供那些想在 SteamOS 之外立即测试的人使用。
