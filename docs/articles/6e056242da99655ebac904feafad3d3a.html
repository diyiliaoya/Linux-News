RBRD：用 Rust 编写的 RAM 后端 Linux 块驱动，安全性更好但性能较慢

Linux 内核邮件列表收到用 Rust 编写的 RAM 后端块驱动 RBRD 的补丁。与现有 C 语言编写的 BRD 驱动相比，RBRD 确保读写不会同时操作同一页面，避免未定义行为，但写入性能下降约 19%（单线程）至 22%（八线程），读取性能下降 2% 至 10%。开发者认为为页面完整性付出这一代价是值得的。

Linux 内核补丁于今晚发布，引入了 RBRD——一个用 Rust 编程语言编写的 RAM 后端块驱动。

Linux 目前已有 BRD 驱动，它用 C 代码提供 RAM 后端块设备驱动，用于提供虚拟块设备。RBRD 现在是这一“真正”的 RAM 块设备实现的 Rust 版本。诚然，考虑到当今的内存价格和供应情况，基于 RAM 的块设备使用可能有限，但对于模拟和快速测试仍然有用。

与基于 C 的 BRD 驱动不同，RBRD 驱动确保对页面的读和写复制永远不会同时发生，以确保在 Rust 世界中不会出现未定义行为。但反过来，这使得 RBRD 的写入比 BRD 慢，单线程性能下降约 19%，八线程下降 22%。由于这些 Rust 保证，读取性能也下降 2% 至 10%。

RBRD 开发者认为安全性值得付出性能代价：

“我们认为这对于页面完整性来说只是很小的代价：RAM 磁盘仍然比任何真实设备快得多，而块设备永远不应返回从未写入的数据。这一差距尚未进行性能分析，因此并非全部必然归因于锁。使用整个设备一把锁而不是每页一把锁时，8 线程读取比 brd 慢 20-28%。”
