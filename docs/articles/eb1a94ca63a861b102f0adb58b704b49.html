VLC被错误归咎于Microsoft Defender的笨拙

知名游戏开发者Jonathan Blow在推特上抱怨VLC在Windows上播放MP3需要33秒，并以此批评开源软件现状。VLC官方回应称这是Windows 11/Microsoft Defender更新隔离插件缓存所致，而非VLC核心问题。一位Linux用户提供视频证据显示VLC在Linux上秒开MP3，进一步证明问题源于Windows。解决方案包括重置插件缓存、重新安装VLC或在Defender中排除vlc.exe。文章认为将个别问题上升为“开源软件糟糕”的结论过于牵强，责任应在微软。

VLC被错误归咎于Microsoft Defender的笨拙

VLC在Windows上播放MP3需要很长时间？这要归咎于Microsoft Defender，而不是VLC。

作者：视频游戏设计师

. Blow是《Braid》和《The Witness》等游戏的开发者。

他提到，他已经停止在Windows上使用VLC，因为点击一个简单的MP3后需要大约33秒才能开始播放，他转而使用Microsoft Media Player。

“终于从VLC *换到* Microsoft Media Player，因为VLC现在点击后需要33秒才能开始播放mp3。

开源软件的一大块现在真的处于尴尬的境地……

pic.twitter.com/237aLdx2fG

— Jonathan Blow (@Jonathan_Blow)”

他还批评了开源软件，将其描述为大量开源软件状况不佳的标志。

“开源软件的一大块现在真的处于尴尬的境地……”

这迅速演变成一场激烈的讨论，双方都有人加入。

VLC的官方推特账号澄清说，这种延迟不是VLC核心回归，而是Windows 11 / Microsoft Defender更新隔离了VLC插件缓存的副作用。他们建议的解决方案是重新安装VLC或重新生成该缓存。

Jonathan认为修复是开发者的责任。他引用了自己在游戏《Braid》中修复AMD引起的问题的经验。

Linux用户带着确凿证据加入

一位使用X账号的Linux用户加入了讨论，提供了具体证据，表明这不是VLC核心问题，而是Windows问题。

，该用户分享了一段似乎是运行KDE的Linux发行版的录制视频。录制视频清楚地显示VLC在1-2秒内开始播放MP3文件。

“听起来像是Windows的问题，真的

pic.twitter.com/9Icp2Sf58M

— PRIZ ;] (@VoxelPrismatic)”

但有些人仍然不满意，因为VLC在Windows上打开MP3文件缓慢是一个真实问题，但他们一直归咎于VLC。

问题的解决方案

VLC建议以下修复方法：

重新生成插件缓存（例如使用 `vlc --reset-plugins-cache` 启动，或清除用户配置文件下的VLC缓存并重新启动）

从官方版本重新安装VLC

更好的建议来自一些用户，他们指出在Microsoft Defender中排除vlc.exe可以解决这个问题。我更喜欢这个建议，因为它似乎解决了问题的根源，即Microsoft Defender。而且如果缓存再次积累，VLC可能会再次变慢（我想）。

由几个人提出。所以这看起来是值得尝试的解决方法。

提出正确的问题

在所有讨论中，有人提出了真正的问题：为什么VLC对一个人不起作用就变成了“开源软件的一大块”处于尴尬境地？

归咎于Defender，而不是VLC

我理解这种沮丧。在现代系统上，等待半分钟才能播放MP3是不可接受的，即使是在Windows上。

当你不知道真实背景和根本原因时，归咎于VLC也是可以的。

但将其描述为“开源软件已破碎”的说法是非常牵强的。

我自己没有测试过。我不会仅仅为了这个而跳进Windows，但据我所见，修复的责任在微软那边。而且据我对微软的了解，他们不会做任何事情。
