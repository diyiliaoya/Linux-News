AMD 准备在 Linux 中默认启用 HDMI 2.1 FRL 支持

发布于 2026 年 8 月 27 日下午 3:45（美国东部时间）

今年五月发生了一件令人意外的事件：AMD 为其开源 AMDGPU Linux 驱动发布了 HDMI 2.1 FRL 补丁，作为其更广泛的 HDMI 2.1 支持工作的一部分。多年来，AMDGPU 中的开源 HDMI 2.1 支持一直受到 HDMI 论坛的阻碍，但无论是由于 Valve 还是其他事件，代码最终得以解禁。虽然该支持自 Linux 7.2 起已包含在内核中，但默认情况下一直处于禁用状态——不过这一情况即将改变。

在针对更高分辨率和更高刷新率的 HDMI 2.1 固定速率链路（FRL）补丁之后，又相继推出了显示流压缩（DSC）、VRR 和 ALLM 功能的补丁，这些功能对游戏玩家尤为重要。AMD 一直在将这些 HDMI 2.1 功能上游到主线 Linux 内核，但最初默认禁用，直到可变刷新率（VRR）功能准备就绪，以避免任何用户体验回退。

随着这些功能现已趋于完善，AMD 正准备根据今天的补丁默认启用 HDMI 2.1 FRL。AMD 驱动工程师 Fangzhi Zuo 发布了该补丁，通过反转逻辑来默认启用 HDMI 2.1 FRL。通过模块参数，可以在需要时禁用该支持，以便进行错误/回归测试等。

因此，对于今年晚些时候的 Linux 7.4，我们希望看到 AMDGPU VRR 和 ALLM 准备就绪，并且现在默认启用 FRL。对于当前的 Linux 7.3 周期来说已经太晚了，但对于 Linux 7.4，希望一切都能准备就绪。如果 Linux 7.3 和 Linux 7.4 按计划发布，Linux 7.4 应该会在 12 月的最后两周发布……这反过来将使其成为 2026 年 Linux 长期支持（LTS）内核版本，并且如果 HDMI 2.1 功能全部就绪，这将是 AMD Radeon Linux 用户的一份绝妙圣诞礼物。
