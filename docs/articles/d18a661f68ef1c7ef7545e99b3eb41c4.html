AI垃圾信息持续淹没GNOME扩展，他们转而编写机器人手册

GNOME扩展门户（EGO）持续遭受AI生成的低质量扩展提交的困扰，尽管12月更新了审查指南，问题仍未缓解。审查员Javad采取了新策略：直接为AI模型编写指令，要求其生成更规范的代码，包括清理资源、避免冗余错误处理、针对单一版本等。同时，AI生成的个人使用扩展需附带注释，禁止上传至EGO。此举旨在减轻人工审查负担，保护开源生态。

AI垃圾信息持续淹没GNOME扩展，他们转而编写机器人手册

GNOME Shell扩展通常来源于extensions.gnome.org，GNOME社区称之为“EGO”。该门户上的每个提交都经过人工审查，而这一审查流程数月来一直承受着巨大压力。

12月，GNOME在其EGO审查指南中新增了一条规则，拒绝AI生成的垃圾内容。他们允许使用AI进行学习和代码补全，但明确禁止生成整个扩展，除非开发者能够令人信服地解释和调试代码。

数月过去，AI垃圾信息的洪流并未减缓。Javad，即最初规则的制定者，尝试了一种不同的方法。他没有仅仅在事后拒绝糟糕的提交，而是编写了直接针对生成这些提交的AI模型的指令。

让机器人理解

鉴于审查队列仍被AI生成的扩展淹没，且大多数重复着完全相同的错误，Javad决定直接向AI模型发出指令。大部分指导涉及清理工作。扩展需要在`disable()`中按特定顺序移除超时、断开信号和销毁小部件。Javad还指出，AI模型会添加布尔标志（如`_isDisposed`）来防止不当调用，而实例应在`disable()`后直接置空，不再引用。AI模型倾向于将安全函数调用包裹在不必要的错误处理中，并为必然存在的方法添加检查。Javad将此归因于模型试图编写同时兼容多个GNOME Shell版本的代码，他的解决方案很简单：只针对一个版本，而不是覆盖所有可能的版本。

此外，指导还涉及保持代码组织性。将逻辑拆分到多个文件，而不是集中在一个臃肿的入口点；将相关函数放在一起，便于检查清理；不要提交包含空函数的占位代码，仅仅为了展示。

还有一条专门针对AI模型本身的规则。任何仅用于个人用途的AI生成扩展，必须附带一条注释，告知用户除非真正理解代码并能维护，否则不要上传至EGO。👇

```javascript

// 使用AI生成，仅供个人使用。

// 除非你理解JavaScript并能维护此代码，否则不要上传至extensions.gnome.org (EGO)。

```

机器人淹没开源贡献者并非新鲜事。我们已经看到足够多的证据，可以得出结论：如果不加以强力管控，这些机器人将拖垮开源生态系统。

GNOME的Javad所做的是一种损害控制。他和其他EGO审查员肩负重任。如果他们被毫无意义的AI垃圾信息淹没，那对我们这些通过安装扩展来改善桌面体验的GNOME用户来说，将是巨大的损失。
