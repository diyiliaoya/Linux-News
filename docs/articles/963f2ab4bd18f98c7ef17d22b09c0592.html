在 AMD Zen 6 上对 FRED 性能优势的基准测试

本文通过对比测试，量化了 AMD Zen 6 架构上 FRED（灵活返回与事件交付）带来的性能提升。测试使用 EPYC 9006 双路平台，在 Ubuntu 26.10 和 Linux 7.4 Git 内核下进行。结果显示，在 I/O 场景（网络或本地存储）中，FRED 默认启用可带来最高几个百分点的性能增益，是 EPYC 9006 出色表现的因素之一。

SP7 Venice 处理器现已出货，我一直想跟进的一个有趣基准测试是量化灵活返回与事件交付（FRED）的性能影响。FRED 在英特尔 Panther Lake 上首次亮相时表现出非常好的性能提升。此后，Linux 内核在支持的 CPU 上默认启用了 FRED，因此 Phoronix 上所有 EPYC 9006 的基准测试都已经使用了 FRED，而这里给出的是在 Linux 内核中强制关闭 FRED 后的一些数据。

FRED 是一种比传统 IDT 方法更高效、更现代的处理中断、异常和系统调用的方式。所有 AMD Zen 6 处理器都将支持 FRED，而针对已发布硬件的基准测试目前只能使用 EPYC 9006 SP7 处理器。

我很好奇 FRED 的性能影响，因此通过切换 Linux 内核支持，我运行了一些基准测试来展示在 AMD Zen 6 上禁用 FRED 的影响。需要注意的是，FRED 在 Linux 7.1 及更新版本中默认启用。

在 Ubuntu 26.10 上使用双路配置并运行 Linux 7.4 Git 内核构建进行测试时，鉴于时间限制，我运行了一些快速基准测试：

在 I/O 方面，无论是网络还是本地存储，AMD 第六代 EPYC 上都有高达几个百分点的增益，这似乎归因于 Zen 6 上 FRED 的存在及其在 Linux 7.1 及更新版本中默认启用。这只是 EPYC 9006 突出性能的促成因素之一，此外还有 MRDIMM-12800 内存支持、出色的 SMT 性能，以及相对于 Zen 5 甚至回顾 Zen 6 与 Zen 1 服务器性能对比的其他架构改进。这是一段狂野的旅程。
