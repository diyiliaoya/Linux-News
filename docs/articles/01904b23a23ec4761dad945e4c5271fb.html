Linux 7.3-rc4 发布前合并重要 x86 修复

在 Linux 7.3-rc4 发布前，一批重要的 x86/x86_64 修复被合并，主要解决 Intel Granite Rapids 服务器微码导致的机器检查异常、Panther Lake 上 Intel FRED 导致游戏崩溃或冻结，以及 CONFIG_X86_NATIVE_CPU 在支持 APX 的 Intel 平台上引发的问题。这些修复已进入 Linux 7.3 Git，并计划回移植到稳定版内核。

在即将于数小时内发布的 Linux 7.3-rc4 内核之前，一批重要的 x86/x86_64 修复已被合并，以解决若干遗留问题。

首先是一项针对 Intel Xeon 6“Granite Rapids”服务器的修复，旨在避免可能引发机器检查异常的问题微码。Intel Granite Rapids 微码版本 0x1000405 带来了后续版本所需的内部变更。因此，Linux 内核中现在加入了代码，当系统尚未更新到 0x1000405 时，阻止加载 0x1000405 或更高版本，无论是微码的早期加载还是后期加载。这一已合并到 Linux 7.3 Git 的变更也被标记为回移植到现有的 Linux 内核稳定版本。

在规范更新页面上，针对受影响微码版本可能引发 MCE 的情况，它被列为 GNR98。披露将内部变更归因于微码间通信接口。此外还有 GNR101，原因是 Granite Rapids 的 0x1000423 微码版本中最小运行时微码更新版本不正确。

x86 修复的一部分还包括解决 Intel Panther Lake 上的 Intel FRED 导致某些游戏在 Wine / Steam Play 下运行崩溃或冻结的问题。

还有一项针对 CONFIG_X86_NATIVE_CPU 的修复，该配置用于“-march=native”编译器优化的内核构建，会在即将推出的支持高级性能扩展（APX）的 Intel 平台上引发问题。Linux 内核尚未准备好利用 APX 中的扩展通用寄存器（EGPR）。但原生优化的内核构建会导致 APX 指令使用 R16 到 R31 EGPR，进而对 Intel 工程系统造成破坏。因此，Linux 内核现在在进行原生优化内核构建时，会明确阻止 APX/EGPR 的使用，直到内核准备好利用内核内的 APX 功能。
