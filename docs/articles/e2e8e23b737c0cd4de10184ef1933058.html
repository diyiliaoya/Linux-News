tlbi= 启动选项在 Linux 7.2 内核发布前提交

在 Linux 7.2 内核稳定版即将发布之际，一个最后一刻的 x86/urgent 拉取请求被提交，其中包含一个补丁，用于添加新的 tlbi= 启动选项。该选项控制 TLB 失效方法，目前仅支持 'ipi' 值，可让开发者或管理员切换回基于 IPI 的 TLB 刷新，以排查近期 AMD CPU 上 INVLPGB/TLBSYNC 问题可能导致的用户空间崩溃。该补丁已被标记为向后移植到稳定内核版本，并可能在未来扩展支持其他值。

在 Linux 7.2 内核稳定版预计于未来几小时内发布之前，一个最后一刻的“x86/urgent”拉取请求被提交，其中包含一个补丁，用于添加新的 tlbi= 选项。该选项已及时提交给 Linux 7.2 稳定版，并标记为向后移植到稳定的 Linux 内核版本。此选项控制 TLB 失效方法，目前是唯一受支持的值。使用 tlbi=ipi 启动内核将切换回基于 IPI 的透明后备缓冲（TLB）刷新。

由于最近在内核版本中，AMD CPU 上使用 INVLPGB 进行广播 TLB 刷新时发现了一些 INVLPGB/TLBSYNC 问题，因此添加了此选项，允许开发者/管理员切换回旧的基于 IPI 的 TLB 刷新，以排除其作为用户空间崩溃的潜在原因。

因此，目前这只是一个调试选项，如果你想排除 Linux 系统上的任何 INVLPGB/TLBSYNC 问题，可以使用它。未来，如果当前默认行为发生变化，该选项可能会扩展为支持其他值。

该补丁正在通过 x86/urgent 拉取请求等待合并，应该很快就会进入 Linux 内核主线。
