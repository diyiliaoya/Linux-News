Intel Coral Rapids 与 Razor Lake 型号 ID 已提交至 Linux 7.4-rc4

Intel 为即将推出的 Coral Rapids 服务器处理器和 Razor Lake 客户端处理器提交了型号 ID，作为 Linux 7.4-rc4 的 x86 修复的一部分。这些处理器预计最早 2028 年发布，此举旨在让后续 Linux 7.5 的依赖补丁能更顺利提交，避免回归风险。同时，Granite Rapids D 处理器也被加入支持 SNC 的 CPU 列表。

今天作为进入 Linux 7.4-rc4 的每周 x86 修复的一部分，提交了用于识别即将推出的 Coral Rapids 服务器处理器和 Razor Lake 客户端处理器的型号 ID。

正如本月早些时候我所写，Intel 已开始为 Coral Rapids 和 Razor Lake 启用 Linux 支持，这些处理器至少要到 2028 年才会亮相。启用的第一步是添加新的型号 ID，以便其他 Linux 驱动代码可以依赖它来检测这些 CPU。今天在 Linux 7.4-rc4 之前发出的正是这最初的基本步骤。

这并不会神奇地让 Razor Lake 和 Coral Rapids 平台与 Linux 7.4 配合工作，但现在提交是作为一个“修复”，以便从 Linux 7.5 开始更容易提交依赖补丁。与其在合并窗口期间先等待 x86 拉取请求落地，然后再提交任何利用 INTEL_CORALRAPIDS_X 或 INTEL_RAZORLAKE / INTEL_RAZORLAKE_L / INTEL_RAZORLAKE_U / INTEL_RAZORLAKE_S 的其他 PR，不如现在就在当前 Linux 7.4 周期提交，因为它不会带来回归风险，并使流程更顺畅。

这些 ID 将会就位。今天的 x86 修复还包括将 Granite Rapids D 处理器添加到支持子 NUMA 集群（SNC）的 Intel CPU 表中。
