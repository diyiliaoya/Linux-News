GCC 17 编译器新增 "-m128bit-atomic" 选项，支持 128 位原子内存操作

GCC 17 编译器新增了 "-m128bit-atomic" 选项，用于在支持该特性的 Intel、AMD、兆芯（Zhaoxin）和 Hygon 处理器上生成 128 位原子内存操作的指令，从而避免使用 libatomic 库带来的开销。该选项已在 GCC Git 代码中合并，并在 64 位模式下默认启用（如果目标处理器支持）。此功能基于 Intel、AMD、Hygon 和兆芯对 128 位原子加载和存储的硬件支持保证，预计将在明年春季发布的 GCC 17.1 稳定版中提供。

GCC 17 编译器新增 "-m128bit-atomic" 选项，用于 128 位原子内存操作

发布于 2026 年 8 月 12 日下午 2:40（美国东部时间）

今天合并到 GNU 编译器集合 Git 代码中的是明年 GCC 17 功能版本的新选项。该选项用于让 GCC 在支持的 Intel / AMD / 兆芯 / Hygon 处理器上生成 128 位原子内存操作的指令。这个 GCC 内置选项可以避免使用 libatomic 库带来的开销。

除了添加 -m128bit-atomic 本身之外，新的 GCC Git 代码现在还在目标处理器支持的情况下（通过或类似方式）默认启用该选项。添加此选项是在 x86_64 CPU 厂商确认其对 128 位原子加载和存储的支持之后进行的。

x86-64：添加 -m128bit-atomic

凭借 Intel、AMD、Hygon 和兆芯在以下链接中提供的硅厂商保证：

https://gcc.gnu.org/bugzilla/show_bug.cgi?id=104688

许多软件开发人员会乐意在他们的程序中使用内联的 128 位原子加载和存储，因为他们只针对兼容的 CPU。添加 -m128bit-atomic 以生成 128 位原子加载和存储，避免调用 libatomic 的开销。在 64 位模式下，如果目标处理器支持，则默认启用 -m128bit-atomic，这些处理器包括支持 x86-64-v3 的处理器以及来自 Intel、AMD、Hygon 和兆芯的支持 AVX 的处理器。

该支持已通过合并。请期待明年春季发布的 GCC 17.1 稳定版中的这一功能。
