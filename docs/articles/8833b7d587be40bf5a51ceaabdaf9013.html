Linux 7.3 看起来将上游合并 FailFS

2026年8月3日下午2:46 EDT。

在 Linux 7.3 中合并了 NULLFS，作为一个“完全僵化的最小伪文件系统”。现在预计 Linux 7.3 将合并它的兄弟：FailFS。

NULLFS 提供了一个永久为空且不可变的目录，其中查找操作以 ENOENT（无此文件或目录）错误码失败。对于即将到来的 FailFS，到达文件系统的每个操作都会返回 EOPNOTSUPP，即 Linux 中“操作不支持”的错误码。

Christian Brauner 在将 FailFS 排入 VFS.git 的“vfs-7.3.failfs”Git 分支时解释道：

“在早期启动期间，通过 kern_mount() 挂载了一个 FailFS 实例，使其在逻辑上区别于每个挂载命名空间。

由于该挂载不属于任何挂载命名空间，因此无法在其上挂载其他东西。它不能被 OPEN_TREE_CLONE 克隆，也不会出现在 statmount()/listmount() 或 /proc/<pid>/mountinfo 中。该文件系统未注册，因此不会出现在 /proc/filesystems 中，也无法从用户空间挂载。

这允许任务完全摆脱其文件系统状态。根目录或工作目录位于 failfs 中的进程必须将每个路径查找锚定在显式文件描述符上，否则任何查找都将失败。绝对路径、绝对符号链接和 AT_FDCWD 相对查找都会失败。后续补丁将通过一个新的 FD_FAILFS_ROOT 文件描述符哨兵将其暴露，该哨兵可被 fchdir() 和新的 fchroot() 系统调用使用。

有趣的是，由于动态二进制执行与 PT_INTERP 的工作方式，这目前也阻止了动态二进制的执行，因为加载器使用绝对路径（参见 selftests）。”

FailFS 无法被克隆，无法从用户空间挂载，也无法在其上挂载任何东西。FailFS 驱动程序的驱动部分代码不到两百行。

Brauner 已将 FailFS 排入 VFS.git 分支，并标记为“7.3”，预计 FailFS 将在本月晚些时候的 Linux 7.3 合并窗口提交——前提是 Linus Torvalds 或其他著名内核开发者没有反对意见。
