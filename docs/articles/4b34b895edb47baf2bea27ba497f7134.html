Linus Torvalds 在 Linux 7.4 中移除不安全的 __get_user() 和 __put_user() 函数

Linus Torvalds 合并了移除内核中历史遗留且不安全的 __get_user() 和 __put_user() 函数的代码分支。这些函数因缺少指针验证检查而存在安全隐患，且性能不如现代替代方案。大部分使用点早已转换，此次清理完成了 x86/x86_64 架构的最终移除，其他架构仍有少量残留。Torvalds 透露在此过程中使用了 Claude 作为高级 Coccinelle 脚本辅助转换。

Linus Torvalds 继续他近期亲自提交内核补丁的趋势，部分工作借助了 Claude Code 的 AI 辅助。今天合并的补丁移除了历史遗留且不安全的 __get_user() 和 __put_user() 内核函数。

Linus Torvalds 合并了他的代码分支，移除了 Linux 内核中的 __get_user() 和 __put_user() 函数。这些函数是 get_user() 和 set_user() 的更快但安全性较低的版本，因为安全检查较少。__get_user() / get_user() 函数用于将单个简单变量从用户空间复制到内核空间，而 __put_user() / put_user() 用于将单个变量从内核空间写入用户空间。被移除的版本缺少指针验证检查，因此不安全。Linus 在 Git 合并中描述了移除原因：

“这早就该做了：__get_user() 和 __put_user() 函数完全是历史遗留产物，再也不是应该使用的东西。而且当被误用时（读作：所有情况），它们不仅比正确的做法更慢，而且不安全，因为它们不检查用户地址范围。

大多数使用点很久以前就已转换，但各种遗留仍然存在。所以这最初是我写的一个补丁，作为‘向人们展示如何将 __{get,put}_user() 转换为现代代码’的示例。

特别是，Thomas 去年实现了非常好的新作用域用户访问区域辅助函数（见提交 e497310b4ffb：‘uaccess: Provide scoped user access regions’），使得现代接口特别易于使用，真正消除了使用旧式恐怖接口的任何借口。”

Torvalds 接着描述了 __get_user() 和 __put_user() 的问题和恐怖之处。

这些函数已从所有通用 Linux 内核代码中移除，并完成了 x86/x86_64 整个接口的最终移除。由于一些非平凡的情况，其他一些 CPU 架构移植中仍有残留，或者像 ARM64 那样，其函数已经映射到 get_user() 和 put_user()。

对于那些想知道 Linus Torvalds 是否使用 AI 编码的人——考虑到他上周使用 AI 破译 bug、用 Claude Code 进行性能改进的工作——这次 __get_user() 和 __put_user() 的移除确实有一些 AI 活动。Torvalds 评论说，他使用 Claude 作为一种高级的 Coccinelle 脚本，Coccinelle 用于静态分析和源到源转换。
