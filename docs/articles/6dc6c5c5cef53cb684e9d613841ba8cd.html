Linux 7.3 引入 KCFI 优化，惠及旧款 Intel CPU

Linux 7.3 合并窗口即将迎来一项内核控制流完整性（KCFI）优化，旨在提升不支持 CET/IBT 的旧款 Intel 处理器的性能。该优化由 Intel 工程师 Peter Zijlstra 提出，通过替换 KCFI 检查序列中的条件跳转指令，减少分支预测开销，从而提高吞吐量。Intel 工程师 Scott Constable 的基准测试显示，该补丁在旧平台上可带来显著性能提升。目前补丁已进入 tip 树，预计将在 Linux 7.3 合并窗口中被合并。

Linux 7.3 引入 KCFI 优化，惠及旧款 Intel CPU

2026年8月10日，美国东部时间下午1:26。

在即将到来的 Linux 7.3 合并窗口中，预计将合并一项内核控制流完整性（KCFI）改进，旨在惠及旧款 Intel 处理器。

Intel 的 Peter Zijlstra 为不支持 CET 的旧平台开发了一项 KCFI 改进。Peter 在待合并补丁中解释道：

“正如提交 85a2d4a890dc（"x86,ibt: Use UDB instead of 0xEA"）中所指出的，Jcc 应被视为不跳转，然而标准的 kCFI（ABI）会生成以下序列：

addl -15(%r11), %r10d

1: cs call __x86_indirect_thunk_r11

（当与 -mretpoline-external-thunk 结合使用时）。

值得注意的是，这里的 Jcc 总是被跳转，导致吞吐量低于理想水平。在启动时将其替换为以下序列：

addl -15(%r11), %r10d

cs call __x86_indirect_thunk_r11

这会跳转到测试指令中用作立即数字节的 UDB 指令。测试指令会破坏 eflags，但这无关紧要，因为 eflags 已经被前面的 addl 改变了。

Intel 建议在支持 IBT 的平台上使用 FineIBT 序列；旧平台仍被广泛使用，并会从这一优化中受益。”

FineIBT / CET 与间接分支跟踪（IBT）出现在 Intel 第11代酷睿“Tiger Lake”及更新的 CPU 中。

Intel 工程师 Scott Constable 在补丁的早期版本上运行了一些基准测试，以评估 CFI 优化的收益：

该补丁已进入 tip/tip.git 的 x86/core Git 分支。随着该代码现在位于 TIP 分支中，预计将在即将到来的 Linux 7.3 合并窗口中被提交。
