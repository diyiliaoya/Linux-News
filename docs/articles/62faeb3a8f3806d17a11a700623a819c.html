来自英特尔或AMD以外某实体的又一份x86公告

2026年8月29日，美国东部时间下午12:24。

去年十月，我重点介绍了一篇关于Linux内核邮件列表上的有趣帖子，内容涉及一个英特尔或AMD以外的x86企业实体，留下了神秘的悬念。那位开发者在七月详细描述了那些x86操作码/CPUID/MSR分配，随后又详细描述了16核和32核AMX实现，再次涉及当前英特尔/AMD处理器范围之外的内容。今天，来自那个“英特尔或AMD以外的企业实体”的另一条消息被转达出来。

x86专家Christian Ludloff今天在Linux内核邮件列表上转达了关于WBINVD指令上x86前缀的详细信息。WBINVD用于写回并使缓存无效。新的披露涉及一个英特尔或AMD以外的组织使用WBINVD指令的新跳过提示。这些跳过提示允许跳过L0i/L1i缓存、跳过L0d/L1d缓存、跳过无效化操作以及跳过LLC缓存。还定义了其他新提示。

“截至2025年，以下内容已被英特尔或AMD以外的企业实体积极使用；因此不应重新定义。

0x67 = 无CODE提示 => 跳过L0i/L1i缓存

0x66 = 无DATA提示 => 跳过L0d/L1d缓存

0xF3 = 无INVD提示 => 跳过无效化操作

0xF2 = 无LLC提示 => 跳过LLC缓存

虽然CODE和DATA提示操作应跳过代码和数据缓存，LLC提示操作应跳过最后一级缓存，而INVD保持不变。

此外，六个实现特定的提示根据特定处理器选择最多六种或2^6=64种行为。

0x26 = ES实现特定提示

0x2E = CS实现特定提示

0x36 = SS实现特定提示

0x3E = DS实现特定提示

0x64 = FS实现特定提示

0x65 = GS实现特定提示

一个特定实现可能使用这些来针对CODE与DATA与STREAMING STORES，以及缓存级别L1与L2与L3。

另一个特定实现可能使用这些来针对可编程行为。

所有十个前缀可以组合，产生最长12字节的指令。”

完整消息可在Linux内核邮件列表上找到。至于这个实体是谁，以及这些x86更改（最近围绕WBINVD提示）的幕后主使，仍然不清楚。

几周前有消息称，初创公司RosaicLabs据报道获得了英特尔Atom处理器设计的访问权限。时间上的巧合增加了该实体可能是RosaicLabs的可能性，但仍有待确认。
