GNOME Boxes 焕然一新，告别陈旧外观

GNOME Boxes 的独立开发者 Felipe Borges 展示了该应用作为仅限 Flatpak 的测试版，进行了全面重写，迁移至 GTK4 和 Libadwaita，并改进了 Windows 11 支持。新版本不再依赖宿主发行版，而是自带完整的虚拟化栈，并采用新的显示组件，界面焕然一新。测试显示 Windows 11 安装无需手动调整，但需微软账户登录。新界面包含七个设置分区，支持端口转发、快照等功能。目前测试版可通过 Flatpak 安装，但存在一些稳定性问题。

GNOME Boxes 焕然一新，告别陈旧外观

全面重写使其迁移至 GTK4 和 Libadwaita，并完善了 Windows 11 支持。

GNOME Boxes 的独立开发者 Felipe Borges 展示了该应用作为仅限 Flatpak 的测试版，其界面基础焕然一新。

在兼顾 Red Hat 日常工作与常规维护职责的同时，Felipe 表示过去两年他一直在独自开发此项目，并在社区活动中分享了相关进展。

第一个设计决策是自包含。Boxes 是 libvirt 的前端，因此其许多行为取决于宿主发行版提供的内容。对于单一维护者而言，为每个发行版维护独立的代码路径并不现实，因此新版本不再依赖宿主，而是自带完整的虚拟化栈。

第二个决策是你最先注意到的。Boxes 已迁移至 GTK4，弃用了基于 GTK3 的 SPICE 组件，改用名为 libdisplay-info 的新显示组件。至此，过时的视觉风格终于消失。

Windows 11 支持方面，重写后的 Boxes 现在可以成功安装，无需任何手动变通或特殊技巧，因为它会自动配置安全启动和虚拟 TPM 设备。

新版本绕过了 Flatpak 沙箱限制，只要客户机运行 systemd v256 或更高版本，即可直接通过 SSH 进入。早期端口转发支持也已加入，目前涵盖 SSH 和 HTTP。

注意到区别了吗？忽略标题栏右侧的栏。

在翻新后的 Boxes 中，你看到的每一处都是新界面组件的结果。尽管如此，应用从启动那一刻起就让人感到熟悉。作为 Boxes 的常客，我清楚地知道该点击哪里。

虚拟机创建流程完美地印证了这一点。我开始安装 Windows 11，Boxes 自动预填了内存和存储值，并设置了 UEFI 作为首选启动方式，我无需触碰任何设置。

安装过程本身一帆风顺，但 Windows 随后坚持要求我使用微软账户登录才能进入桌面，所以我只能到此为止。

不过，在此之前，虚拟机窗口右上角的三个点菜单给了我很多操作空间。我可以截图、发送组合键，并打开完整的控制台。

顺便说一句，这些界面与当前 Boxes 提供的完全不同。

上面的视频展示了新的属性对话框。以前是带有标题菜单的单一窗口，现在变成了带有侧边栏的对话框，包含七个部分：常规、资源、网络、设备、快照、日志和配置。

资源部分允许调整内存和调整存储大小；设备部分处理启动顺序和可移动介质；日志部分显示 Boxes 在底层运行的命令；网络页面允许将主机端口转发到虚拟机，并提供 SSH 和 HTTP 的开关。快照页面允许你捕获虚拟机在某一时刻的确切状态，然后可以恢复或删除。

与当前 Boxes 提供的功能相比（压缩到三个标签页，功能实用但非常笨重），这无疑是一次巨大改进。

不过，也存在一些瑕疵。Windows 11 虚拟机在我创建快照后不久就崩溃了。我无法确定确切原因，但当时我弹出 ISO 镜像可能是罪魁祸首。

在此之前，我还尝试安装 Fedora，但无论我尝试什么，都不断遇到不支持的配置错误。切换操作系统类型（如 Generic 和 Windows）以及固件（如 UEFI 和 BIOS），都无法解决问题。

还有一些小改动。退出虚拟机窗口现在需要按下 Ctrl+Alt 组合键，而当前 Boxes 使用的是 Ctrl+Alt+Delete。也没有专门的全屏按钮，F11 键也不起作用。

如果你使用 Ubuntu 或其他基于 Debian 的发行版，只需几个终端命令即可运行测试版。你需要先设置 Flatpak。如果你尚未安装，可以按照相关指南完成整个过程。完成后，添加 nightly 仓库：

flatpak remote-add --if-not-exists gnome-nightly https://nightly.gnome.org/gnome-nightly.flatpakrepo

然后，在安装任何内容之前，你可以查看该仓库中实际包含的内容：

flatpak remote-ls -
