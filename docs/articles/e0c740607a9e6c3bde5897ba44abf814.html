Warp 推出 Factories，让工程团队构建自己的云软件工厂

Warp 发布了名为 Factories 的新平台，旨在帮助工程团队构建和运行自己的云软件工厂。该平台允许团队使用自己的模型、工具和计算资源，而 Warp 负责编排。Factories 通过代理集群处理从分诊、规格编写、实现到审查的整个开发流程，仅在关键决策点引入人工干预。它支持任何模型或工具，并提供内置指标跟踪所有运行。目前处于封闭测试阶段，需申请早期访问。

组织内软件的构建方式多年来已经发生了很大变化。早在 AI 出现之前，工程团队就已经将开发转变为一系列可重复的操作，这些操作汇集了共享组件和定义好的流程，同时最大限度地减少了重复发明。

这种方法使团队更快、更一致。在 AI 时代，它需要再次转型。

Warp 确信自己已经找到了下一步的方向。

该公司推出了 Factories，作为一个开放的基础设施产品，旨在帮助工程团队构建和运行自己的云软件工厂。在这里，编码代理集群负责工作，而不是局限于开发者笔记本电脑上的单个代理。

简而言之，这是 Warp 尝试将“在云端运行代理”转变为真正的流水线，具有清晰的步骤、可跟踪的真实数据，并且人类仅在关键时刻介入。

开发流水线

Warp Factories 充当一个编排层，用于在整个软件开发生命周期中运行编码代理集群。按照 Warp 自己的说法，这使其成为一个云软件工厂，一个自动化循环，代理从接收请求到交付结果全程处理。

代理负责分诊、编写规格、实现更改、审查工作、验证结果并监控结果，而人类仅在真正需要人工验证的决策点介入。

可以把它想象成汽车装配线。一个工位焊接，另一个喷漆，另一个进行最终检查，车辆在前一个工位签字确认之前不会向前移动。Warp 的版本将同样的逻辑应用于代码。

一个代理对传入的工单进行分诊，如果更改足够复杂，另一个代理起草规格，另一个实现修复，另一个在人工批准合并之前进行审查。

Warp 大力强调“自带”的概念，以解释为什么这需要作为基础设施存在。

团队可以自带托管环境，并且每个代理对话、评估和记忆记录都可以保存在公司控制的基础设施上，而不是 Warp 的。

通过零数据保留选项，数据也可以完全排除在任何训练流程之外。

Warp 的创始人兼 CEO 进一步指出：

“我们的愿景是为你们提供核心组件，以便尽快达到这一目标。在一个交付时间可以说是你最重要的竞争优势的时代，你应该今天就建立并运营一个工厂，而不是六个月后。”

更多功能

Factories 还附带一个仪表板，公司称之为“控制室”，基本上是一个控制室，你可以在其中观看实时和过去的代理运行，检查待处理事项，并在一个地方审查所有自动化。

你也不会被锁定在 Warp 自己的模型或代理上。Factories 支持任何模型，包括开放权重模型，以及任何工具，因此 Claude Code 或 Codex 可以坐在实现的位置上，而不是 Warp 的代理。

所有这些活动都会自动测量，成本、吞吐量和代码质量指标会输入到评估和基准测试工具中，跟踪工厂性能随时间的变化。

Factories 目前不对所有人开放。如果你或你的组织想要试用，则需要通过 Warp Factories 申请访问权限。
