Linux 7.3 将更激进地使用 TTM 内存管理以优化图形性能

本周提交的 DRM-Misc-Next 功能补丁中，TTM 内存管理代码在分配低于保护限制时变得更加激进。该改进由 Valve 的开源 Linux 图形团队贡献，旨在解决当 VRAM 稀缺且应用竞争时，受保护的内存分配可能落入 GTT 的问题。通过引入特殊处理，受 cgroup 保护的分配将尝试驱逐未受保护的缓冲区，以确保应用能充分利用系统授予的内存保护。此外，DMEMCG 支持已扩展到 AMDGPU 和 Xe 驱动，Nouveau 驱动也新增了 DMEMCG 支持，UDMABUF 移除了人为的 64MB 限制，Allwinner Sun4i 驱动则改进了 YUV 和 4K 支持。

本周，DRM-Misc-Next 的最终一批功能材料已提交给 DRM-Next，以便在 Linux 7.3 合并窗口于本月晚些时候开启前排队。最值得注意的是，TTM 内存管理代码在分配低于保护限制时现在变得更加激进。这一改进得益于 Valve 的开源 Linux 图形团队。

自去年以来，Valve Linux 图形团队的 Natalie Vock 一直在研究当 VRAM 稀缺且应用程序/游戏开始竞争视频内存空间时，设备内存保护无法阻止分配最终落入 GTT 的情况。经过八轮修订，这些对通用 TTM 内存管理代码和 cgroup 设备内存代码的改进现已确定将合并到 Linux 7.3 中。

Vock 在补丁中总结了情况：

“我一直在研究一些情况，当 VRAM 变得稀缺且应用开始激烈竞争时，dmem 保护无法阻止分配最终落入 GTT。简而言之，这是因为其他（未受保护的）应用程序在受保护应用程序之前填满了 VRAM。这导致 TTM 退缩，并尝试在 GTT 中分配，而最终分配就落在了那里。现有的驱逐保护无法防止这种情况，因为从未尝试过驱逐（尽管你可以将退缩视为立即驱逐到 GTT）。

本系列试图通过添加一个特殊情况来缓解这个问题：当分配受 cgroup 保护时，TTM 不会立即退缩，而是会尝试从域中驱逐未受保护的缓冲区，为受保护的缓冲区腾出空间。这确保了应用程序能够真正使用系统授予的所有内存保护，而不会容易发生乒乓效应（只有受保护的分配可以驱逐未受保护的分配，反之则不行）。”

Vock 一直在致力于改善内存容量有限系统上的 Linux 游戏体验。

这些补丁是本周 DRM-Misc-Next 的一部分。它还包括 DMEMCG 对驱逐的支持，并已为 AMDGPU 和 Xe 驱动启用。UDMABUF 代码还移除了一个人为的 64MB 限制，该限制是 Xaver Hugl 在最近改进 KDE 多 GPU/eGPU 体验时发现的。Allwinner Sun4i DRM 驱动也改进了 YUV 和 4K 支持。Nouveau 驱动现在也支持设备内存控制组（DMEMCG），该支持由 Natalie Vock 作为其他改进的一部分编写。
