Linux 可能为 AI 代理技能设立新家

内核稳定版维护者 Sasha Levin 提议在内核源码树中新增 agents 目录，用于存放面向 AI 编码助手的技能、提示词等资源。首个技能将帮助验证内核补丁中 Fixes 标签所指的引入 bug 的提交，避免错误标签导致修复被应用到错误分支或遗漏。该提案仍在讨论中，文件存放位置尚未确定。

Linux 可能为 AI 代理技能设立新家

一个提议中的 agents 目录将存放面向编码助手的技能及其他资源，首个技能用于找出 bug 背后的提交。

内核补丁中的 Fixes 标签指向引入 bug 的提交，但最后触及有问题的代码行的提交可能只是把代码移到了新文件。

Sasha Levin 是稳定版和长期支持内核树的共同维护者，他希望 AI 编码助手在给 bug 分配 Fixes 标签之前，先验证是哪个提交引入了该 bug。上周他在邮件列表中提出了这一想法，建议在内核树中新增一个 agents 目录来存放实现该功能的技能。

该提案在内核源码树顶层新增一个目录，用于存放面向编码助手的技能、提示词及其他资源。同时还会新增一个 MAINTAINERS 条目来覆盖该目录。

每个技能在 agents 目录下拥有自己的文件夹，并以 SKILL.md 文件作为入口点，使用 Markdown 编写。助手被要求直接从仓库中的路径读取资源，技能内部的链接相对于该技能所在文件夹。内核编码助手文档中新增的一节将描述这一布局。

Fixes 标签验证技能随第二个补丁一起提交，将成为该目录中的第一个技能。

为什么 Fixes 标签会出错？

Levin 表示，这一系列补丁源于 Ted Ts'o 关于稳定树工作中不正确标签的提问。他提到了帮助找到正确提交的 LLM 工作流。

他还提到这一请求来自与 Hannes Reinecke 的一次交谈，后者估计有 15% 到 20% 的 Fixes 标签是错误的。

这不仅仅是记录问题，因为稳定版维护者和发行版正是通过该标签来确定哪些内核需要特定的修复。错误的标签可能导致修复被发送到错误的分支，或者让 bug 得不到修补。

该技能读取 Git 历史并返回一个带有证据的 Fixes 标签建议，同时不改动提交本身。

SKILL.md 文件指出，没有任何单一线索能确定 Fixes 标签应该指向哪个提交，即使是已有的标签也不行。该代理会解释 bug 是如何失败的，追踪候选提交，并将每个候选与其父提交进行比较。

它会区分添加代码的提交、使代码产生缺陷的提交，以及后来仅仅暴露该缺陷的变更。

对于向后移植的修复，它会检查 bug 是来自原始变更，还是来自该变更为适配旧内核所做的调整。合并、回滚和不完整的历史记录都有各自的处理方式。

当无法确定来源时，它不返回标签，而是列出候选提交和缺失的信息，修复保持草稿状态，直到有人解决为止。

仍在进行中

第二个补丁将在内核的编码助手文档中新增一节，说明助手在最终确定 bug 修复或其提交信息之前，以及在审查现有标签时，必须遵循该指南。

文档中提交修复的步骤将要求提供经过验证的标签，而目前只要求提供 Fixes 标签。请注意，该技能不会编写提交信息、应用标签，也不会决定修复是否应进入稳定版。

这一系列补丁延续了 Levin 此前推动内核 AI 编码助手政策的努力，该政策包括一项内核终止开关的提案。

文件应该放在哪里仍未确定。介绍性补丁信息中说他不确定它们应该放在 Documentation 下，还是放在根目录下单独的 agents 目录中。

Greg Kroah-Hartman 询问该系列补丁是否会修复因缺少 MAINTAINERS 文件而跳过内核指南的工具。Sasha 回复说这是另一个独立问题。
