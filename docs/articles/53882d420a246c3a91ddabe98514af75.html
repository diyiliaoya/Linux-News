AMD 为 EPYC 虚拟机准备 Linux 增强型 SMT 保护 "ESMTP"

AMD 工程师向 Linux 内核邮件列表提交补丁，开始为 EPYC 服务器处理器上的 SEV-SNP 虚拟机启用增强型 SMT 保护（ESMTP）。该功能通过硬件强制确保 SMT 兄弟线程要么处于主机空闲状态，要么运行同一虚拟机的 vCPU，以缓解侧信道攻击风险。ESMTP 需配合 QEMU 和 OVMF 补丁，且因性能开销默认不启用，预计将用于 EPYC 9006 "Venice" 系列。

AMD 工程师今日在 Linux 内核邮件列表上发送了补丁，开始为在搭载 SEV-SNP 的 EPYC 服务器处理器上运行的虚拟机启用增强型 SMT 保护（ESMTP），以提升安全性。

这是 Linux 内核邮件列表上首次出现增强型 SMT 保护。搜索发现，今年早些时候 AMD.com 上发布了一份 ESMTP 白皮书，但并未引起太多关注。鉴于这项启用工作的时间点，增强型 SMT 保护大概是 AMD EPYC 9006 "Venice" 服务器处理器的一项功能。

虽然 Linux 上已有核心调度等机制来确保一个 CPU 核心及其兄弟线程属于同一虚拟机，但 ESMTP 相当于一种基于硬件的机制，确保 SMT 兄弟线程要么在主机模式下空闲，要么运行客户机自身的 vCPU。其目的是缓解过去几年围绕同时多线程/英特尔超线程出现的潜在侧信道攻击。

该文档将增强型 SMT 保护总结为：

“增强型 SMT 保护（ESMTP）允许 SEV-SNP 虚拟机要求：当其某个 vCPU 处于客户机模式时，该物理核心上的每个 SMT 兄弟线程要么在主机模式下空闲，要么运行客户机自身声明为合法兄弟的 vCPU。这缓解了与不可信主机线程或另一客户机共享核心资源的侧信道风险。

与核心调度不同——核心调度中的共驻留是主机内核策略，通过 cookie 表达——ESMTP 由硬件强制执行。兄弟掩码位于 VMSA 中。当某个 ESMTP vCPU 在该核心上活跃时，主机不被信任在兄弟线程上运行任意内核、用户空间或中断处理工作。

KVM 和客户机都完全设置 VCPU_SIBLING_MASK，将客户机的每个 vCPU 放入一个组，使其中任意两个可以共驻留。结合 ASID 检查，处于客户机模式的 vCPU 的兄弟线程便始终要么是同一客户机的另一个 vCPU，要么是主机模式下空闲的线程。”

除了 Linux 内核补丁外，还需要针对 QEMU 和 OVMF 的上游补丁。此 ESMTP 功能仅在启用安全加密虚拟化（SEV-SNP）功能时可用。

同样值得注意的是，ESMTP 会带来一定的性能开销，因此默认不启用，仅面向那些希望确保更好的 SMT 兄弟线程安全性的用户，例如公共云部署或运行不可信工作负载：

“ESMTP 是选择性启用的，因为它会带来性能开销，VMRUN 会停顿，直到兄弟线程运行来自可信 vCPU 的工作或处于主机空闲状态。”

该系列仅包含两个补丁。同样，这大概将成为 AMD EPYC 9006 系列产品线的一部分。
