Agent Name Service 现已加入 Linux 基金会

Agent Name Service (ANS) 正式成为 Linux 基金会项目，旨在为 AI 代理提供可验证的身份标识，类似域名与证书之于网站。GoDaddy、Cloudflare、Salesforce 和 DigiCert 等 11 家组织参与其中。ANS 通过将代理与其运营者拥有的域名绑定，并颁发证书、公开注册日志，使接收系统能验证代理身份。项目设有技术指导委员会，首年内将举行选举，并规定代码许可从 MIT 过渡到 Apache 2.0。

Agent Name Service 现已加入 Linux 基金会

Agent Name Service (ANS) 现在在 Linux 基金会有了归宿。发布会在盐湖城举行的 KubeCon 北美站上举行，你可能还记得，基金会早在六月就为该项目的启动做了铺垫。

GoDaddy、Cloudflare、Salesforce 和 DigiCert 等组织现已参与 ANS，使参与组织总数达到十一家。

ANS 的早期部署之一是在该基金会下的另一个项目中进行，其 AI 代理目录现在可以检查代理的 ANS 身份。

在宣布这一变动时，Linux 基金会 CEO Jim Zemlin 分享了以下内容：

自主 AI 代理正在全球系统中进行交易和操作，但如果没有可验证的身份，它们就无法成功。在 Linux 基金会的中立治理下，ANS 提供了一个整个行业可以共同采用、实施和改进的通用信任基础。

各平台以自己的方式识别 AI 代理，而接收到某个代理请求的服务没有标准化的方式来确认该代理代表谁。ANS 通过将每个代理与其运营者拥有的域名关联来解决这个问题，就像网站与其域名绑定一样。每个版本的代理都有自己的名称，例如 ans://v1.4.2.travel.example.com

要注册代理，运营者首先必须证明其控制该域名。然后为代理颁发证书，每次注册都会进入一个任何人都可以阅读的公开日志。

ANS 还在互联网的地址簿中发布每个代理的详细信息，其他系统则可以使用它们已有的工具进行查询。

主要的 DNS 记录使用来自一个名为的独立项目的格式。ANS 添加了自己的一条记录，指向代理在公开日志中的条目。

当代理发送请求时，接收系统可以检查其注册是否存在、是否未被撤销，以及代理是否确实持有与之关联的密钥。

ANS 只涵盖代理是谁。决定它能做什么则留给接收系统，平台必须自行添加检查。

一个技术指导委员会现在。它最初有五个席位，由来自的三人和来自的 Michael Kantor 担任。

这一阵容只是一个起点。首次选举必须在 12 个月内举行，之后，规定任何一家公司不得持有半数或以上席位（以确保供应商中立性）。

章程还提到，会议应向公众开放，讨论和决定应对所有人可见。

至于项目中的所有代码，Go、Rust 和 Java 库目前使用 MIT 许可证，但从现在起贡献的新代码必须使用 Apache 2.0 许可证。

ANS 始于 2025 年，当时是发送给互联网标准组织 IETF 的一份草案，十月份又有一份草案出台。此类草案在 IETF 没有正式地位，也不受其认可。

目前，Linux 基金会称该规范已正式化。参考代码和本地演示在项目的上，规范在上。
