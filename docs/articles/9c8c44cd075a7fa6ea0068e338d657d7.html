GnuPG 的 GPGME 受严重安全漏洞影响，进而波及邮件客户端与 Flatpak

GnuPG 的 GPGME 库被曝存在严重安全漏洞，影响所有现有版本。攻击者可通过构造超长用户 ID 触发双重释放，进而从应用中窃取数据，甚至可能实现远程代码执行。该漏洞波及多数邮件客户端、XMPP 客户端、Flatpak、Samba 等软件。GPGME 2.3.1 是首个修复版本，建议用户立即升级。

Werner Koch 在周五下午晚些时候宣布了一个影响 GnuPG 的 GPGME 库（GnuPG Made Easy）的“严重安全漏洞”。不幸的是，这反过来又影响了 GPGME 的用户，如大多数电子邮件客户端、大多数 XMPP 客户端、Flatpak、Samba 以及其他软件。

今天公开的这个严重安全漏洞影响 GPGME 的所有现有版本。一个精心构造的超长用户 ID 可以触发双重释放，进而可通过发送例如已签名的数据来从应用程序中提取数据。该漏洞也有可能被利用来发动远程代码执行（RCE）攻击，但尚未得到确认。

Wener Koch 建议 GPGME 用户立即将其 GPGME 更新到今天的版本。

“通过使用包含精心构造的超长用户 ID 的 OpenPGP 密钥，可以触发双重释放。这种双重释放可用于通过发送例如已签名的数据来从应用程序中窃取数据。不能排除利用此漏洞发动远程代码执行攻击（RCE）的可能性。因此强烈建议立即更新。

该漏洞的根本原因是 GPGME 内部用于从 gpg 读取状态行和密钥列表的两个函数。最初分配一个 1024 字节的缓冲区，如果需要更多空间则重新分配。重新分配时，函数使用了指向新缓冲区的指针，但该指针仅在函数结束时才被赋值回上下文对象。因此，如果函数由于读取错误或其他事件而提前返回，上下文就不会被更新，并保留指向已释放内存的陈旧指针。最终上下文被释放，内存被第二次释放。由于其间存在其他分配，内存分配器的常见双重释放检查可能不会被触发。”

所有使用现有 GPGME 版本的应用程序，无论是作为共享库、DLL 还是静态链接版本，都会受到影响。
