Nginx 现在存在严重漏洞

Nginx 1.30.7 和 1.31.9 修复了十个漏洞，其中五个被评为严重级别（CVSS 9.2），可导致攻击者在特定条件下执行代码。这些漏洞涉及 HTTP/2、HTTP/3、解析器和邮件代理等模块，最早可追溯至 nginx 0.5.33。管理员需根据服务器启用的功能判断受影响范围，并尽快升级至稳定版 1.30.7 或主线版 1.31.9。

Nginx 现在存在严重漏洞

修复程序已在 1.31.9 和 1.30.7 版本中发布，最早受影响的代码可追溯到 nginx 0.5.33。

Nginx 是一个开源 Web 服务器和反向代理，位于应用程序前端并将流量传递给它们，是使用最广泛的 Web 服务器之一。

正是这种广泛的部署，使得 nginx 1.30.7 和 1.31.9 中修复的十个漏洞意义重大；其中五个甚至允许攻击者在服务器上执行代码。

稳定分支在 1.30.7 中获得修复，主线分支在 1.31.9 中获得修复；两者均于昨日发布。

此外，这五个漏洞中的大多数仅在使用特定功能时才有影响。作为系统管理员，您需要做的第一件事是确定哪些漏洞与您的服务器运行配置相匹配。

每个漏洞都是 nginx 不同部分中的独立缺陷。nginx 将其中两个评为严重级别，并表示其中两个可能导致工作进程崩溃或产生其他影响，而拥有 nginx 的 F5 公司表示，攻击者在特定条件下可以执行代码。

F5 在 CVSS 4.0 中给这五个漏洞都打了 9.2 的严重评分。

其中两个位于 HTTP/2 中。一个是 HTTP/2 流控制中的内存缺陷，可追溯到 nginx 1.9.5，被评为严重级别。如果您不了解，流控制限制了服务器一次发送的数据量。这意味着代码在内存释放后仍继续使用它。当使用 HTTP/2 且配置不足时，可能在工作进程中发生。它被评为严重级别。

另一个是 HTTP/3 相关的漏洞。它是另一个条件性问题，被评为严重级别。受影响范围可追溯到 nginx 1.25.0。

一个位于解析器中，也是一个条件性问题。当使用 resolver 指令且子请求中同时解析相同名称时可能发生。

一个影响邮件代理，仅在将 nginx 作为邮件代理运行时才有影响。它被评为严重级别，并且是五个中受影响范围最老的，始于 nginx 0.5.33。

F5 的 CVE 记录将 NGINX Plus 也列为受影响。

修复方法是：如果您使用主线分支，请更新至 1.31.9；如果您使用稳定分支，请更新至 1.30.7。两者均可从官方渠道获取。

同一版本还修复了另外五个漏洞，包括通过 TLS 1.3 读取请求体时的无限循环，nginx 将其评为重要级别。
