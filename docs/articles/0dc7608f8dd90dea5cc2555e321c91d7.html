Intel 为 Battlemage 在 Linux 7.4 中带来重大改进

Intel 为即将进入 Linux 7.4 的 Xe 内核驱动提交了最后一批改进，核心是在迁移队列上实现 CPU binds 和 ULLS（超低延迟调度）。该改进可让 Battlemage 独显在持续处理 GPU 缺页时，拷贝任务快约 30–40µs，冷启动加速更明显，页错误基准测试持续提升数 GB/s。代价是功耗增加，但 ULLS 会在无缺页时自动退出以缓解。该补丁还修复了 Crescent Island 的 ULLS 并新增 Panther Lake 设备 ID。

Intel 为 Battlemage 在 Linux 7.4 中带来重大改进

发布于 2026 年 10 月 2 日下午 02:34（美国东部时间）。

周四发出了最后一批计划中的 Intel Xe 内核驱动改进，目标针对即将到来的 Linux 7.4 周期。其中有一项重大改进将惠及 Intel 独立 GPU，至少 Battlemage 会从中获得不错的收益。

本轮 Intel Xe 驱动的主要新增内容是在迁移队列上实现 CPU binds 和 ULLS。虽然听起来不像什么吸引人的功能，但它带来了相当可观的性能收益。Intel 工程师 Matthew Brost 解释道：

“在 BMG 上，测量显示当 GPU 持续处理缺页时，与在迁移队列上启用 SLPC 的传统 GuC 提交相比，使用 ULLS 的拷贝任务运行约快 30–40µs（取决于测试用例）。从冷 GPU 启动时加速幅度更大。鉴于缺页性能的关键性，ULLS 似乎是一项值得拥有的功能。

除了驱动遥测之外，UMD 计算基准测试一致显示，在启用 ULLS 后，页错误基准测试持续提升数 GB/s。

ULLS 会消耗更多功耗（尚未测量），因为分页引擎上会持续运行一个批次。然而，计算 UMD 已经在暴露给用户的引擎上这样做了，因此这似乎是一个值得的权衡。为缓解功耗问题，ULLS 会在一段时间内没有处理任何缺页后退出。

CPU binds 是 ULLS 正常工作所必需的，因为迁移队列需要对分页硬件引擎的独占访问。因此，这里包含了 CPU binds。

除了作为 ULLS 的必要条件之外，CPU binds 还应能降低 VM-bind 延迟，提供更清晰的多 tile 和 TLB 失效分层，在缺页风暴期间减轻 GuC 的压力（因为绕过了它），并将内核 bind 与无关的拷贝/清除任务解耦——在缺页被并行处理时尤其有益。在一个并行缺页测试用例中，平均 bind 时间减少了约 15µs。在最坏情况下，2MB 拷贝时间（约 60–140µs）×（页错误线程数 − 1）的延迟原本会加到单个缺页上。降低这一延迟可提高缺页处理程序的整体吞吐量。”

总体而言，迁移队列的 ULLS 加上 CPU binds 最终看来是一个不错的胜利。此处的 ULLS 指的是

超低延迟调度（Ultra Low Latency Scheduling）

这个新的 Xe pull request 还包括针对 Crescent Island 的 ULLS 修复。该 pull 还包含一个新的 Panther Lake 设备 ID 0xB0A1。

它正在前往 DRM-Next，以便在 10 月下旬 Linux 7.4 合并窗口之前排队。Linux 7.4 稳定版则应在 12 月下旬左右发布。
