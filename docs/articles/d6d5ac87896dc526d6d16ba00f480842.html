Linux 7.4 内存管理变更：一项指标提升 22904539.81%，其他方面收益温和

Linux 7.4 内核合并窗口将引入一项内存管理优化，允许预填充 sheaf 从 barn 中补充对象，避免 full 列表饱和。该改动仅新增 81 行代码，却在 will-it-scale mmap1 测试中带来 24% 的整体提升，其中 barn_get 性能暴增 22904539.81%，barn_put 提升 21422544.07%，其他指标也有两位数增长。

MM Change Slated For Linux 7.4 Yields +22904539.81% In One Metric, More Modest Wins In Others

2026年9月26日 11:07 AM EDT。

本周已排队进入 slab/for-next Git 分支，为下个月的 Linux 7.4 合并窗口做准备。这是一项内存管理变更，用于从 barn 中重新填充预填充的 sheaf。在某些情况下，这为特定的合成基准测试带来了惊人的改进。

sheaf 是 Linux 内核内存分配器的每 CPU、基于数组的缓存层。自去年引入内核以来，sheaf 已经经历了大量工作，而 Linux 7.4 还有更多优化工作正在进行。

Hao Li 解释了这项从 barn 重新填充预填充 sheaf 的内存管理代码变更：

“目前，当预填充 API 重新填充一个非满的 sheaf 时，它从部分 slab 中获取对象，而从不从 barn 中的满 sheaf 获取，因此一旦 barn 的满列表饱和，它就会保持饱和。

对于通过 kfree_rcu() 释放的对象，每个 RCU sheaf 随后都必须刷新到 slab，因为 barn 的满列表没有空间。

为了解决这个问题，让 sheaf 首先从 barn 重新填充，并在 barn 中引入一个部分 sheaf，用于存放剩余的对象。

只有预填充路径需要这个部分 sheaf。通用分配路径（__pcs_replace_empty_main()）用一个空 sheaf 从 barn 换一个满 sheaf，因此不会留下剩余对象。预填充路径重新填充的 sheaf 不一定是空的，因此从 barn 取对象通常会留下剩余对象，而部分 sheaf 就是存放它们的地方。refill_sheaf() 只从部分 slab 取对象，从不涉及部分 sheaf。

sheaf 的重新填充方式是：先从部分 sheaf 复制对象，如果仍未满，再从 barn 中取一个满 sheaf 复制。被复制对象的 sheaf 如果仍然持有对象，就作为部分 sheaf 留在 barn 中；如果为空，则进入空列表。被重新填充的 sheaf 永远不会被替换。

收益来自两个方面：每个取出的满 sheaf 都为未来的 RCU sheaf 在 barn 的满列表上腾出空间，而且在 list_lock 下从 barn 重新填充比从部分 slab 重新填充更便宜。”

在 will-it-scale mmap1 测试中，整体提升了 24%。barn_get 性能的影响为 +22904539.81%，barn_put 为 +21422544.07%，其他指标相比基线往往有两位数的百分比提升。

81 行新代码就能产生如此大的影响。

该变更将进入 10 月下旬的 Linux 7.4 合并窗口。
