Linux Zswap 新补丁显示重大改进

Linux 开发者 Usama Arif 提交了两项 Zswap 补丁，旨在减少加载请求争用。补丁将压缩与解压缩的请求、等待和互斥锁分离，并在同步算法下使用栈上请求进行解压缩，从而避免加载路径获取 Zswap 锁。测试显示，单 vCPU 下最慢读取从 22.3 毫秒降至 0.97 毫秒，8 vCPU 下从 314 毫秒降至 7.0 毫秒，超过 10 毫秒的读取几乎消失。

在 RAM 价格高企之际，Linux 内存管理领域正在推进多项创新，周一发布的一组新补丁旨在提升 Zswap（用于交换页的压缩 RAM 缓存）的性能。

Linux 开发者 Usama Arif 发布了两项 Zswap 补丁，致力于减少 Zswap 加载时的请求争用。继 zRAM 完成类似工作之后，Zswap 代码正在被调整，以解决当前存储和加载共享每 CPU acomp 请求和互斥锁的缺陷。当前这种处理方式最终被证明是瓶颈，而这两个补丁有助于减少加载时的争用。

Usama Arif 进一步解释道：

“存储和加载共享每 CPU acomp 请求和互斥锁。一个低优先级存储在压缩器释放其流锁之后、但仍持有 zswap 互斥锁时可能被抢占，而该 CPU 上更高优先级的加载随后会等待该存储再次运行。这延续了 Sergey Senozhatsky 的 zram 系列工作，后者出于相同原因进行了拆分。

补丁 1 为压缩和解压缩提供了独立的请求、等待和互斥锁，因此加载不再等待存储，尽管它们仍可能互相等待。补丁 2 在算法为同步且不需要请求上下文时，使用栈上请求进行解压缩，这涵盖了所有树内软件压缩器，因此这些加载不会获取 zswap 锁。异步算法则保留每 CPU 请求和互斥锁。对于软件压缩器，该系列分配的请求数量与之前相同；每个每 CPU 上下文增加 72 字节，在 x86-64 上加载路径加深约 270 字节。”

Usama 在补丁系列中进一步解释：

“以下数字是每次运行中最慢的读取，取 5 次运行的中位数（最小值-最大值）。每次运行在 zstd 虚拟机中进行 12 秒，启用惰性抢占，vm.page-cluster=0，交换位于 /dev/ram0。在 1 个 vCPU 下，四个 nice +10 的工作进程将内存换出并读回，同时一个 nice 0 的任务空转。一个 nice -19 的读取者换出自己的缓冲区，并测量每次读取所需时间。在 8 个 vCPU 下，有 16 个工作进程、8 个空转任务和 8 个读取者。

系列之前（毫秒） 系列之后（毫秒）

1 vCPU 22.3 (21.6-22.6) 0.97 (0.72-1.4)

8 vCPU 314 (97-2542) 7.0 (5.0-98)

在 1 个 vCPU 下，超过 10 毫秒的读取从每次运行 26-35 次降至零；在 8 个 vCPU 下，从每次运行 3-18 次降至最多一次。基准测试和测试程序是在 LLM 的帮助下编写的。”

总体而言，这看起来是对 Zswap 的一次非常好的改进，目前正在 Linux 内核邮件列表上接受审查。
