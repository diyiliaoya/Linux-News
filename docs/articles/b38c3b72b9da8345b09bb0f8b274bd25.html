Radeon RADV Vulkan 驱动采用 LLM 政策

Mesa 的 RADV 驱动为 AMD Radeon GPU 提供 Vulkan 支持，现针对 AI/大语言模型代码贡献制定了宽松政策。该政策不禁止 AI/LLM 贡献，但 discourages 使用，并允许维护者自行决定关闭 AI 生成的合并请求。Valve 的 Samuel Pitoiset 发起此政策，原因是外部贡献者提交的 LLM 合并请求增多，希望在开发者不堪重负前明确规则。

为 Linux 上的 AMD Radeon GPU 提供 Vulkan API 支持的 Mesa RADV 驱动，已针对 AI/大语言模型（LLM）的代码贡献制定了自己的政策。

在 Mesa 拥有自己的 AI/LLM 政策之后，Radeon RADV 驱动也针对 AI/LLM 制定了一项宽松政策。Valve Linux 图形团队的 Samuel Pitoiset 是 RADV 驱动的多产贡献者之一，他主动推进并添加了这项 RADV 专属政策。

最终这是一项宽松的政策，并未完全禁止基于 AI/LLM 的贡献，但不鼓励使用，并保留了关闭 AI 生成的合并请求的可能性。新政策如下：

“如果你在 RADV 中发现 bug 或缺陷且无法自行解决，请在跟踪器上提交 issue。LLM 辅助的 MR 需要对代码库有良好的理解，而审查它们有实际成本。审查者/维护者可自行决定关闭此类 MR。

不鼓励 LLM 编写的 issue：它们往往冗长且难以阅读。请用自己的话描述问题。LLM 生成的复现器只要经过你的审查并能证明该 bug，是可以接受的。”

Pitoiset 解释了这项 RADV 政策的必要性，因为他开始看到更多 AI 生成的补丁，希望在开发者不堪重负之前提前应对。他在该政策的合并请求中写道：

“如今我们开始收到稍多来自外部贡献者的 RADV LLM MR，似乎最好现在就表明这一点，以免被淹没。”
