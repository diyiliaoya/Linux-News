OpenAI Codex 协助发现并修复近 20 年历史的 Radeon Linux 驱动 Bug

发布于 2026 年 11 月 12 日 20:41 EST。

今天发出了最新一批 AMD 内核图形/计算驱动补丁，目标是在年底开放的 Linux 7.5 合并窗口。除了大量修复以及围绕即将推出的 GPU 的新 IP 启用工作外，甚至还有一项针对旧 ATI/AMD Radeon R600 时代硬件的修复，这得益于 OpenAI 的 Codex 的帮助。

在面向 Linux 7.5 的 AMD 内核图形驱动补丁中，有一项让我感到意外：该补丁旨在修复 R6xx 时代 GPU 上的统一视频解码（UVD）IP 块……这些是来自 Radeon HD 2000/3000 时代的近二十年历史的显卡。

AMD 多年来一直没有官方维护对 R600 GPU 的支持，但一位开源贡献者在遇到视频解码问题后，借助 AI 承担了这项任务。Ted Bullock 在解释扩展 UVD 处理检查以覆盖更多 RV6** GPU 时表示：

“我调查了我较旧的 iMac7,1（RV610/M74，设备 ID 1002:94c8）上的视频损坏问题。当解码器从系统内存读取压缩视频而 GPU 同时进行绘制时，会损坏视频帧。将输入移至 VRAM 后，帧可以正确解码。禁用图形绘制也停止了损坏。

这里提出一个建议：为这一系列设备将 UVD 缓冲区保留在 VRAM 中，正如驱动已经为其他一些芯片所做的那样。该补丁覆盖 RV610、RV620、RV630、RV635 和 RV670。这些芯片共享 RV6xx 解码器路径和旧版 R600 固件，因此我认为它们很可能有相同的硬件要求。拥有其他硬件的人需要验证这一点。

我在 Debian 上测试了这个补丁。

我使用 Codex 协助调查、测试和打补丁。”

果然，这位新开源贡献者的补丁被接受了，并通过今天的拉取请求正在前往 Linux 7.5 内核。

该拉取请求还带来了各种其他修复和更改，不过并不特别引人注目或令人兴奋：

- 错误处理修复

- IMU 固件清理修复

- TLB fence 处理修复

- 启用 JPEG type4 数据包支持

- CS IB 解析修复

- vcn/uvd/vce/jpeg 空闲工作处理程序清理

- MES 调试扩展支持

- 更多显示 KUNIT 测试

- 移除 fence ops->release()

- 文档修复

- DC PSP footer 大小修复

- 修复 WPTR BO 驱逐 fence 处理

- dma-buf 处理修复

- 添加对非连续和无 CPU 的 NUMA 拓扑的支持

- 在分析器活动时处理 perfmon 时钟

- 分析器锁定修复

- 从 SCDS 解析 HDMI 2.2 FRL 速率的 EDID 支持

- ATRM 边界检查

- 更新 KFD 分析器版本号以注明 perfmon 时钟修复”

我们将在未来几周看到更多面向 Linux 7.5 的 AMD 内核图形/计算驱动材料。本周拉取请求中未包含的是新的 AMD GFX13（RDNA5）补丁，所以也许下周会出现。
