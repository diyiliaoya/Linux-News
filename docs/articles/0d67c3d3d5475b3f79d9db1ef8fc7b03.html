Systemd 创造者的初创公司开放其 Linux 系统私人预览报名

Systemd 创造者 Lennart Poettering 联合创立的 Amutable 公司推出 Amutable Foundations，这是一个只读、基于镜像的 Linux 系统，每台机器会生成自身状态的签名报告。系统采用不可变设计、签名统一内核镜像和测量启动，无包管理器和 SSH。公司同时提供镜像、更新仓库和控制平面服务，但未说明开源范围。现开放私人预览报名，首批合作伙伴将在未来几周内加入。

Systemd 创造者的初创公司开放其 Linux 系统私人预览报名

Amutable Foundations 是一个只读、基于镜像的系统，每台机器都会生成自身状态的签名报告。

在宣布这一基于 Linux 的实现之前，Amutable 已发布了两款开源工具：基于 Buck2 的构建系统，用于组合操作系统镜像，采用 MPL-2.0 许可；以及基于 TUF 的工具，用于将镜像分发到机器，采用 Apache-2.0 许可。

Amutable Foundations 带来的是一项服务：Amutable 为运营自有系统的组织和个人运行镜像、更新仓库、控制平面和漏洞修复。这些由公司运营的部分尚未声明许可证，且预览公告未说明 Foundations 除 tine 和 Quarry 之外有多少会开源。

系统包含什么？

该产品来自 Amutable，这家初创公司由 Lennart Poettering 今年早些时候与 Christian Brauner 和 Chris Kühl 共同创立。

该系统是不可变的，只读系统卷受保护，使用签名的统一内核镜像和测量启动。软件和配置均以签名镜像形式交付，机器只启动已签名的内容。

没有包管理器，也没有 SSH 或交互式 shell。变更意味着为集群中的每台机器提供新的签名镜像。

其镜像可复现，附带 SBOM，并从所选发行版的固定输入构建，tine 能够从 Fedora 或 CentOS Stream 导入软件包。

机器如何证明其状态

每台机器发送一份签名报告，记录其启动内容，从固件和引导加载程序到内核和操作系统，以及其运行的配置。

报告在启动时和定期发出，签名由 TPM 或支持机密计算的 CPU 支持。没有该硬件的机器可以回退到软件密钥。

Amutable 的控制平面验证来自 systemd 260 中一个实验性命令的报告，该公司帮助构建了该命令。它将每份报告与声明状态进行比较，并标记偏离的机器。

只有当机器能够证明处于良好状态时，部署才会继续。操作员通过结构化界面工作，而不是登录。

更新来自可相互链接的每机器仓库，下载会根据签名元数据检查篡改、重放和回滚尝试。

同样的证明旨在决定访问权限，例如集群加入和机密。Amutable 提供的示例是拒绝向运行过时配置的机器提供数据库凭据。

Amutable 正在寻找管理 Linux 集群并需要展示每台机器状态的团队。它预计在未来几周内开始引入首批“合作伙伴”。

这些合作伙伴将获得早期访问权、与开发者的直接联系渠道，以及对后续构建内容的发言权。申请需要填写姓名、工作邮箱、公司、角色、国家、行业和公司规模。

还计划下一步针对 Kubernetes，如果您想了解更多相关信息或 Foundations，团队将出席 KubeCon North America。
