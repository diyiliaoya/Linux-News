Linux 7.3-rc2 调度器修复：混合 CPU 上缓存感知负载调度的失配问题

2026年9月6日 上午09:32 EDT

在 Linux 7.3-rc2 内核于今天晚些时候发布之前，一组调度器修复已为本周的测试内核版本发送。最值得注意的是，这些调度器修复处理了在混合 CPU（如 Intel Core (Ultra) 处理器）上缓存感知负载调度可能出现的失配问题。

缓存感知调度是一个出色的 Linux 内核特性，它可以将相关任务分组到能够共享相同最后一级缓存（LLC）的 CPU 核心上。缓存感知调度可以带来更好的缓存局部性，进而降低延迟并避免缓存乒乓的开销。但在具有大小核架构的混合 CPU 情况下，如果分组任务最终全部被限制在 E 核/小核上，则可能存在权衡取舍。

Intel 工程师 Tim Chen 针对混合处理器上缓存感知调度的失配问题提出了一个修复方案。他在补丁中解释道：

“缓存感知负载平衡将任务偏向其首选的 LLC。在非对称 CPU 容量系统（例如 big.LITTLE）上，目标 LLC 可能包含容量过小、无法运行该任务的 CPU。将任务拉取到那里会使其成为失配任务，用缓存局部性的收益换取容量损失，而容量损失对性能的损害更大。

针对这两个缓存感知迁移入口点进行防护：

- can_migrate_llc_task()：当任务适合其源 CPU 但不适合目标 CPU 时，禁止 LLC 迁移。

- alb_break_llc()：在相同条件下否决主动平衡，以免可运行任务被推送到无法容纳它的 CPU 上。

两个检查都通过混合处理器检查进行门控，因此对称系统不受影响。已经不适合其源 CPU 的任务则保留现有的 LLC 策略，因为迁移不会使其适合性变得更差（这也保留了失配任务向更大 CPU 的上迁移）。

此外，如果在负载平衡分类阶段发现失配任务，则在非对称系统上优先进行失配任务迁移，而不是 LLC 负载聚合。一个更合适的 CPU 将比更好的缓存局部性带来更大的性能提升。”

这对整体系统性能有利。该修复补丁是今天调度器拉取请求的一部分。
