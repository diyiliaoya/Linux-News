Windows 11 天气应用占用约 1GB 内存，Linux 应用仅为其零头

据报道，Windows 11 自带的天气应用占用内存超过 1GB，引发关注。经测试，Linux 上的天气应用内存占用远低于此，例如 Mousam 仅需约 250MB。尽管测试非科学严谨，但凸显了微软应用的低效，其采用 WebView2 框架并嵌入广告，导致资源浪费。相比之下，Linux 应用更注重效率，这反映了微软对用户体验和硬件资源的忽视。

Windows 11 的天气应用占用约 1GB 内存，Linux 应用仅为其零头 - OMG! Ubuntu

我读到一篇关于微软 Windows 11 天气应用内存占用的报告时感到困惑——它仅为了渲染一个看似花哨的统计表格，就占用了超过 1GB 内存。

更不令人意外的是，Linux 上的天气应用完成同样的任务仅需 Windows 报告数值的五分之一，而我常用的天气应用 Mousam 的内存占用约为微软应用的三分之一（而且设计更美观）。

并非所有 Windows 11 用户都会看到像病毒式帖子中给出的 1.1GB 那样高的内存占用。但当我检查我那台低功耗的 Chuwi 笔记本时，该应用的内存占用超过 900MB——考虑到复杂应用能以更少资源做更多事，这个数值高得离谱。

Windows 11 上的天气应用占用 918MB 内存

微软使用 WebView2 框架构建其许多自有应用，而非原生 WinUI。该框架由 Microsoft Edge 的 Chromium 引擎驱动（任务栏的新闻和天气面板也是如此，同样因占用大量内存而受到批评）。

桌面天气应用还包含赞助内容和广告，遵循微软标准的“广告优先，功能其次”的设计理念。

高端游戏电脑不会因使用该应用而感觉到响应速度下降，但在内存有限的设备上，打开它可能会导致内存压力增加（RAM 先被压缩，然后页面文件被调入），从而导致系统卡顿。

Linux 天气应用相比之下如何？

我喜欢的 Linux 天气应用 Mousam——不是面板小程序，尽管那些更流行——与 Windows 相比如何。我打开了在 Ubuntu 26.04 LTS 上安装的应用，检查它们的内存占用。

这不是科学测试。

请将其视为出于好奇而非经验数据。微软的天气应用仅限 Windows；不同操作系统管理内存的方式不同；每个测试应用的功能集也不同；等等。

我的笔记本配置不算高端：低功耗 Intel m3-8100y 处理器，8GB 内存和 250GB NVMe SSD。但这是唯一运行 Windows 11 的设备，因此似乎是理想的测试平台：

内存数值是活跃使用期间 3 次运行的平均值。微软的天气应用内存占用波动很大（跨 9 个子进程），取决于加载内容、加载位置、是否聚焦等。

Linux 应用更高效这一事实不会让新闻界震惊。但我对微软应用的低效感到震惊。我没有达到测试者看到的 1.1GB 峰值，但已经足够接近了。

仅为了知道是否下雨，就占用 Windows 11 最低内存要求（官方仅为 4GB——“是啊，没错！”——全世界都这么说）的四分之一，坦率地说，这令人震惊。

对于 Linux 用户来说，看到 Windows 软件运行得如此糟糕，是对确认偏误的慰藉。虽然很容易将这些数据视为 Linux 默认更好的证据，但实际上这证明了微软并不在乎去尝试优化。

这就是为什么性能基准——无论是经验性的还是轶事性的——并不是真正的关键，关键在于意图。

微软宁愿发布一个带有广告的浏览器标签页来充实自己的腰包，也不愿构建一个既尊重用户又尊重硬件的优化应用——这比天气应用的低效更能促使用户转换系统。

Mousam 是一款用 Qt 编写的跨平台应用。在 Linux 上，报告称其使用内存低于 4MB，但一个属于它的 Python 进程占用约 250MB。该报告一并给出了这个数字。
