Linux 7.3 为 systemd 和 BPF 程序新增“bpf_sock_read_xattr”特性

Linux 7.3 内核合并了新的 bpf_sock_read_xattr() 函数，允许 BPF 程序无锁读取套接字扩展属性。该特性由 Christian Brauner 开发，主要服务于 systemd 等用户态管理器，用于套接字限速、标签标记及 Varlink 注册表实现。新函数仅对 BPF LSM 程序注册，并受 KF_RCU 保护，确保在 sockfs 中安全访问。该补丁已合入 Linux 7.3 内核。

Linux 7.3 为 systemd 和 BPF 程序新增“bpf_sock_read_xattr”特性

发布于 2026年8月18日 下午3:38（美国东部时间）。

今年早些时候合入 Linux 7.1 的是套接字上的扩展属性支持，这是 GNOME 和 systemd 等所寻求的特性，用于帮助 Varlink IPC 使用及其他目的。该功能的一个限制是，BPF 程序没有高效的方法来读回这些用户扩展属性标签。但在 Linux 7.3 中，新的 bpf_sock_read_xattr() 内核函数解决了这一问题。

Christian Brauner 实现了 bpf_sock_read_xattr() 的支持，允许 BPF 程序无锁地从套接字的 sockfs inode 中读取扩展属性。他解释了新功能：

“systemd 使用套接字上的 user.* 扩展属性来实现套接字限速，并用于其他目的（例如实现 varlink 注册表）来标记套接字。目前 BPF 程序没有高效的方法来读回这些标签。新的辅助函数允许在 bind/connect 期间读回带有扩展属性的监听套接字，然后对 connect() 的套接字采取行动。扩展属性使得非特权用户管理器（如 systemd --user）能够从用户空间标记套接字，然后重新发现它们或实施策略。

kfunc 注册为 KF_RCU，且仅用于 BPF LSM 程序。只有当 LSM 套接字钩子提供 struct socket 时，它才保证在 sockfs 中存活，这正是保持 SOCK_INODE() 有效的原因。在 sockfs 之外嵌入 struct socket 的套接字（如 tun、tap）只能从跟踪程序访问，并通过注册排除。（顺便说一句，为了保持一致性，最好强制从 sockfs 分配 struct socket，而不是简单地将其嵌入例如 struct tun_file，这会使 SOCKFS_I() 模式变得危险——至少在 sockfs 函数之外。）

读取操作从不休眠，也不加锁。对于 sockfs，该值存在于 inode 的内存 xattr 存储中，simple_xattr_get() 通过 RCU 保护的 rhashtable 查找来解析它，既不获取 inode 锁，也不获取任何 xattr 锁。因此，该 kfunc 可用于可睡眠和不可睡眠的 LSM 钩子。”

该 bpf_sock_read_xattr 支持现已通过合并，进入 Linux 7.3 内核。
