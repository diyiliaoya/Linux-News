全局菜单扩展将应用菜单放入GNOME顶部面板

一款新的GNOME Shell全局菜单扩展发布，为292款知名应用提供菜单支持。对于不导出传统菜单的应用，扩展利用键盘快捷键生成菜单；对于支持D-Bus菜单的应用，可通过可选伴生守护进程显示完整菜单。该扩展支持GNOME 48至51，在Ubuntu 26.04 LTS及更高版本上可用。

本周发布了一款适用于GNOME Shell的全局菜单扩展，与你过去可能尝试过（并放弃）的扩展不同，这款似乎运行良好。

早期的全局菜单尝试因Wayland、API变更以及许多现代Linux应用不再“导出”菜单而受阻，导致大多数应用在顶部面板中留下空白。

这款扩展为292款知名应用提供了菜单，并且通过安装可选的伴生工具，允许像Firefox这样的应用也显示其完整的应用菜单。

对于超过290款知名应用——那些在Linux（或Wayland）上不暴露传统应用菜单的应用——该扩展使用应用文档化的键盘快捷键来创建菜单：

没有菜单的应用的应用菜单

这是一种非常巧妙的方法，因为无论应用是什么类型（没错，甚至是Electron），只要应用有针对关键操作的键盘快捷键，它们就可以在菜单中暴露并通过点击触发。

对于确实有传统应用菜单（并通过D-Bus导出）的软件，你可以安装一个可选的伴生守护进程包。它会将真实的完整应用菜单发送到全局菜单（并在可能的情况下从应用中移除菜单）。

你可以看到安装伴生工具与不安装时方法的差异。后者提供完整菜单，并根据你正在进行的操作实时显示不可用（灰色；不可选择）的操作。

伴生工具必须从源码构建。在Ubuntu上，这并不像听起来那么难。运行以下代码块，在需要时按提示操作，它会为你完成繁重的工作——之后你必须注销并重新登录，以便加载伴生工具。

sudo apt install git make python3-setuptools

git clone https://github.com/Unmade760/orbit-global-menu.git

sudo apt install ./global-menu_*.deb

即使有伴生工具，事情也并不完美；有些应用，如Firefox，在显示完整菜单之前需要调整。该项目的文档涵盖了如何以及为何这样做——为了获得完整体验，值得一做。

最后，如果当前聚焦的应用不被两种方法覆盖，它不会让你面对空白面板，因为它由简单的窗口、工作区和会话操作覆盖。

菜单默认使用不透明背景（有一个模糊选项，但只在我启用某功能时才有效），并且当此功能激活时，工作区切换器圆点会从顶部栏消失，但你可以选择显示它们。

聚焦应用的标题以粗体显示，但可以以常规字重显示或完全隐藏。

如果你愿意，可以通过设置面板查看和编辑该扩展自带的292个现代菜单。也可以创建自己的快捷键映射，为未覆盖的应用提供更完整的菜单（预计覆盖范围会随着未来更新而扩大）。

在Ubuntu上安装Global Menu

Global Menu支持GNOME 48 – 51，因此如果你使用的是Ubuntu 26.04 LTS或更高版本，可以尝试一下。用它来唤起你对Ubuntu Unity桌面的回忆（Unity曾添加了一个全局菜单）。

记住：要获得完整的应用菜单，你确实需要安装伴生守护进程。我在Ubuntu 26.10上没有遇到任何问题。
