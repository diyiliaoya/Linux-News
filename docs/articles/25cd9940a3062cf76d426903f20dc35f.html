Linux 7.3 将更好地处理 Intel 混合 CPU 上的集群负载均衡

发布于 2026 年 8 月 8 日下午 1:27（美国东部时间）。

一组来自 Intel 的补丁将被合入即将到来的 Linux 7.3 合并窗口，以增强集群感知调度代码，使其在现代 Intel Core (Ultra) 混合 CPU（包含 P 核和 E/LPE 核）上更好地处理负载均衡。

早在 2021 年，内核引入了集群感知调度支持，旨在为共享 L2 缓存或其他中级资源的 CPU 核心集群提供更好的调度支持。当时合并后，我指出了这种新调度在 Intel 混合 CPU 上导致的性能回退，尽管此后进行了一些改进，但集群感知调度在 Intel 混合处理器上仍然不够理想。不过，对于 Linux 7.3，看起来它将得到更好的改善。

Intel Linux 工程师 Ricardo Neri 领导了最新的修复工作，以解决非对称容量处理器的集群调度问题。他解释道：

“集群调度旨在通过将负载分散到共享中级资源的 CPU 集群之间来最大化性能。它在统一系统上运行良好，但在由大小核组成的集群拓扑上会失效。因此，它已经在几代已出货和即将推出的 Intel 处理器上失败。

在部分繁忙的系统上（存在空闲 CPU；繁忙 CPU 各有一个任务），非对称容量调度确保不匹配任务落在大型 CPU 上。其余任务，无论是否不匹配，都在小型 CPU 上运行。当启用 CONFIG_SCHED_CLUSTER 时，这些剩余任务本应均匀分布在小型 CPU 集群之间。但如今，这并未发生。

这些问题共同导致在非对称 CPU 容量系统上无法进行集群级负载均衡。

本系列补丁解决了每个问题并恢复了预期行为。每个补丁中详细说明了细节、理由和代码更改。

我在 Alder Lake（具有 SMT P 核和 E 核集群）上测试了这些补丁，分别测试了 SMT 禁用和启用的场景。我还在 Lunar Lake 和 Panther Lake（具有未连接到 L3 缓存的 E 核集群）上进行了测试。我使用 CONFIG_SCHED_CLUSTER 禁用时重复了相同的实验。负载均衡器表现符合预期。”

这些补丁现已进入 tip/tip.git 的 sched/core Git 分支。由于补丁已进入 TIP 分支，它们应该会在即将到来的 Linux 7.3 周期中合并。

补丁中没有共享性能数据，但一旦 Linux 7.3 周期开始，我将在一些 Intel Core Ultra 处理器上运行基准测试，以观察不同工作负载下的性能影响。
