Rocky Linux 创始人借助 AI 在 11 天内构建全新“非 Linux”内核

Rocky Linux 创始人 Gregory Kurtzer 利用 OpenAI Codex AI 代理，在 11 天内开发出一个名为 Ginux 的独立 Rust 优先 x86-64 内核。Ginux 并非 Linux 分支，但实现了 Linux 二进制接口，能启动 Rocky Linux 10 至 systemd。AI 生成了约 13.9 万行代码，项目采用“人类指导的代理工程”模式，目前仅为研究原型，仅支持 QEMU 虚拟机。

Ginux 并非 Linux 分支，却能启动 Rocky Linux 10 直至 systemd。一个 OpenAI Codex 代理编写了约 13.9 万行代码。

Gregory Kurtzer 对 Linux 世界并不陌生。他创建了 CentOS，并在其转向后作为社区替代品出现。他还联合创立了 CIQ，这家公司围绕 Rocky 提供企业支持。

然而，他的最新项目与重建另一个 Linux 发行版无关。他构建了一个全新的操作系统内核，而且大部分代码并非他自己编写。一个 AI 代理完成了这些工作。

认识 Ginux：没有 Linux 底层的 Linux 用户空间

该项目名为 Ginux。它是一个独立的、Rust 优先的 x86-64 内核。这简单意味着它并非 Linux 内核的分支。

它拥有自己的内存管理、调度器、进程模型、文件系统、网络和设备支持，全部从零编写。

最有趣的部分是，尽管它不是 Linux，但它与 Linux 兼容。Ginux 实现了 Linux 二进制接口（编译程序与内核通信所用的二进制接口），因此现有的 Linux 二进制文件可以在其上未经修改地运行。

用项目自己的话说，Linux 是 Ginux 暴露的一种“个性”，而非底层运行的内核。

现在，Ginux 这个名字听起来像是 GNU 和 Linux 的混合。很遗憾让你失望了，这里并非如此。

Ginux 中的 G 代表 GPT。Greg Kurtzer 在 README 中开玩笑说，为了控制自己的自负，G 正式代表 GPT。为什么是 GPT？因为它完全由 (Chat) GPT 5.6 Sol 编写。

Kurtzer 在 X（原 Twitter）上宣布：

11 天内，我构建了一个新的 Linux 兼容操作系统内核，能启动带有 systemd 的 Rocky Linux 10，全部使用人类指导的代理工程（HDAE）。

我称之为 Ginux。它是一个独立的、Rust 优先的 x86-64 内核（非 Linux 分支），拥有自己的内存管理、启动……

—— Gregory M. Kurtzer (@gmkurtzer)

Ginux 目前能做什么

Ginux 构建为单个镜像，直接通过 UEFI 启动，不涉及 Linux 宿主内核。

它运行隔离的“域”，每个域有自己的进程、地址空间、文件系统和生命周期。该项目称这些边界比 OCI 容器或 Linux 命名空间更强。

它还能拉取并验证 OCI 容器镜像，并用它们组装域的根文件系统。这就是它让 Rocky Linux 10 启动至 systemd 的方式。选定的 Alpine Linux 程序（如 musl 和……）

不过别太兴奋。目前，Ginux 仅在 QEMU 虚拟机中运行，没有物理硬件配置文件，不支持 GPU 或 NVMe，也没有独立的安全审计。

Ginux 是一个根据 Apache 2.0 许可证发布的研究原型。它不适用于生产环境，也不作为 Linux 的替代品。

什么是人类指导的代理工程？

HDAE 是 Kurtzer 给这种开发方法起的名字，老实说，这才是真正的故事。他在 Zenodo 上的一份技术报告中记录了它。

其理念是明确分工。人类决定架构、约束、里程碑、验收标准以及何时停止。AI 代理运行实现循环：编写代码、启动、测试、诊断故障、修改，并针对这些可执行检查重复。

对于 Ginux，这意味着一个持续的 OpenAI Codex 任务运行 GPT-5.6 Sol 十一天。它产生了约 13.9 万行保留的实现和测试代码，跨越 1000 多次提交。架构文档让代理保持对齐，而像 Rocky Linux 这样的真实用户空间发现了合成测试遗漏的错误。

“人类指导”的部分很重要。这不像在聊天机器人中输入“给我写个内核，别出错”那么简单。这是一个拥有数十年系统经验的人在引导。
