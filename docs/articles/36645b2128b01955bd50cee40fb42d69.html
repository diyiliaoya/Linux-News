Broadcom 关闭 VDDK 公开访问，加强对 VMware 的控制

Broadcom 悄然下架了 VMware VDDK 的公开下载页面，导致依赖该工具进行备份和无代理迁移的用户无法获取新副本。现有副本仍可使用，但 Red Hat、Microsoft Azure Migrate 等均受影响，用户被建议联系 Broadcom 支持或转向授权合作伙伴方案。此举被视为 Broadcom 收购 VMware 后收紧控制、推动订阅制与捆绑销售策略的延续。

Broadcom 关闭 VDDK 公开访问，加强对 VMware 的控制

现有副本仍可使用；但获取新副本则是另一回事。他们似乎“忘记”宣布这一变化。

Broadcom 已下架 VMware 虚拟磁盘开发工具包（VDDK）的公开下载页面。VDDK 8 和 9 的页面，以及相关链接，现在均返回通用错误信息。

迄今为止，Broadcom 尚未发布任何正式公告。

此次移除发生在上个月的某个时候，因为 Reddit 和厂商论坛上的用户从 8 月中旬开始报告链接失效。Apache CloudStack 服务公司 ShapeBlue 于 8 月 25 日记录了这一变化。Red Hat 几天后也为其虚拟化迁移工具包发布了支持说明。

虽然现有副本仍可正常使用，这意味着当前使用 VDDK 的实现将继续照常工作，但那些想要获取新副本的人则无计可施。

为何引发争议？

VDDK 是一个库，允许备份和迁移工具从 hypervisor 外部读取 VMware 虚拟磁盘。VMware 将其作为易于访问的 SDK 提供给构建磁盘工具的客户，它很快成为映像级备份和无代理迁移的支柱。

但其许可证让事情变得复杂。该库不可再分发，因此没有 Linux 发行版提供它，也没有开源项目能将其捆绑给用户。所有人都必须指向 Broadcom 的下载页面，而该页面现已消失。

方便，不是对用户而言，而是对 VMware 的所有者 Broadcom 而言，它成功切断了许多人依赖的、用于迁移离开该平台的工具的公开访问。

陷入困境者

Microsoft 的 Azure Migrate 就是这种沉默造成混乱的一个例子。它告诉管理员从 Broadcom 门户下载 VDDK 8.0 或 9.0 以进行无代理迁移，而其中嵌入的链接指向一个无法访问的页面。

文档建议如果 VDDK 无法访问，则回退到基于代理的迁移。

Red Hat 也处于同样境地。其支持说明报告客户在尝试访问 VDDK 公开下载链接时遇到“404”错误，并进一步指出它无法托管或再分发该工具包。

他们引导客户联系 Broadcom 支持，同时 Red Hat 工程团队正在寻找替代的长期出路。

在 Reddit 上，一位用户 bobdrakken 联系了 Broadcom，他收到的回复应该能让你了解 Broadcom 的立场。👇

来自 Broadcom 客户关怀的问候。

为确保最高标准的安全性、可靠性和产品功能，虚拟磁盘开发工具包（VDDK）不再可供使用或下载。

Broadcom 继续积极维护各种 API 和 SDK，以使授权技术联盟合作伙伴能够构建经过验证和授权、可与 Broadcom 产品集成、互操作或兼容的备份和恢复软件解决方案。

对于所有备份和恢复需求，客户应依赖 Broadcom 授权技术联盟合作伙伴提供的此类解决方案。

希望这对您有帮助。

请联系您的合作伙伴以获得更好的协助，因为我们这边没有待处理的操作，因此此案例现在将被归档。

如果您有其他支持请求，我很乐意协助您。

此次下架符合自 Broadcom 于 2023 年 11 月以 690 亿美元收购 VMware 以来的一贯模式。几周内便进行了仅订阅制的全面改革，终止了永久许可证，并将独立产品并入捆绑包。

欧洲客户后来报告续订价格大幅上涨，足以引起行业机构的正式投诉。

并非完全是从 VMware 身上榨取最大价值；Broadcom 一路上也抛出了一些善意。

Workstation Pro 和 Fusion Pro 于 2024 年 11 月对所有人免费，并在 2025 年以有限形式回归。

每一步都可以单独辩护；许可证改革和价格变动是正常的商业行为。
