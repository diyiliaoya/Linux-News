Epic Games 向 Linux 玩家示好，正为《堡垒之夜》重建 EAC

Epic Games 正在为 Linux 平台重建反作弊系统 EAC，新版本名为 EAC Linux v2，将依赖 systemd 服务和 Secure Boot、TPM 2.0 等安全机制，而非内核驱动。《堡垒之夜》将成为首个测试该系统的游戏。同时，Epic Games Launcher 已推出原生 Linux 预览版，但需依赖兼容层运行 Windows 游戏。Epic 正与社区和发行版维护者合作，推动 Linux 游戏支持。

Epic Games 向 Linux 玩家示好，正为《堡垒之夜》重建 EAC

反作弊软件正在为该平台做准备，同时原生客户端已作为预览版提供。

Linux 玩家已经习惯了听到又一款多人游戏因各种原因放弃该平台，尽管他们的理由在我看来通常很牵强。

以育碧为例。他们最近让某款游戏无法在 Linux 和 Steam Deck 上运行，声称无法为该平台部署保护措施。

现在，Epic Games 却反其道而行之，正在以新名称重建其 Linux 反作弊系统，同时为长期被呼吁的原生 Epic Games Launcher 提供预览版。

Linux 上的反作弊并非白日梦。EAC 自 2014 年起支持原生 Linux 游戏，自 2021 年起支持通过 Wine 或 Proton 运行的 Windows 游戏。Epic 现在正将该 Linux 实现重建为 EAC Linux v2，旨在借助 Linux 已有的安全功能，更接近 Windows 的体验。

在 Windows 上，EAC 依赖一个仅在游戏期间激活的内核驱动。在 Linux 上，EAC Linux v2 不会在系统最敏感的部分之一运行此类模块。

内核级反作弊是一个常见的症结。

EAC Linux v2 运行一个 systemd 服务，仅在受保护的游戏会话期间保持活动，同时还有 Epic 编写的程序来监视篡改和作弊行为。

对玩家而言，这意味着更严格的启动设置，因此需要开启 Secure Boot 和 TPM 2.0，内核必须用 Epic 认可的密钥签名，还有其他一些启动和内核设置也会发挥作用。

EAC 仅在受保护游戏启动时检查所有这些，检查失败会显示错误，而不是封禁。玩家还可以为受保护游戏保留单独的启动项，并在其他地方使用自己的密钥。

《堡垒之夜》是首个测试 EAC Linux v2 的游戏，计划在系统验证后向其他开发者开放。已有 Linux 版 EAC 游戏的开发者可以继续使用旧版本或切换。

让《堡垒之夜》本身登陆 Linux 取决于发行版支持。一旦有足够多的维护者满足安全要求，它将通过 Flatpak 到来。

Epic Games Launcher（预览版）

该预览版官方支持 Ubuntu 24.04 或更新版本，其他发行版可能可用但未经过官方测试。

启动器本身是原生运行的，但许多游戏仅限 Windows，因此可能需要像 Proton 这样的兼容层。

社区需要介入

Epic 正在联系 Linux 社区领袖，并邀请发行版维护者取得联系，因为受保护游戏只会在使用受信任列表中的密钥启动的系统上运行。

目前该项目由内部维护，目标是未来某个时候开源。

他们似乎已经与 Fedora 取得了联系，今年晚些时候的一个小组讨论会已将 Fedora 项目负责人列为联合主持人，讨论主题是在 Linux 上实现公平竞技游戏。

SteamOS 是下一个显而易见要提到的名字，但 Steam Deck 尚未满足要求。与 Valve 的谈判正在进行中，目标是稍后支持该掌机。

虽然还为时过早，但这对 Linux 玩家来说是个好消息，因为这是一个在游戏方面不断被竖中指的平台。
