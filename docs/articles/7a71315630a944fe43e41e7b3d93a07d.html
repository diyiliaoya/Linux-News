Chrome 向官方 Flatpak 迈进一步

谷歌为 Chromium 构建系统添加了生成 Flatpak 包的支持，但开发者强调这并不意味着官方 Flatpak 支持即将到来。该更改由谷歌工程师 Tom Anderson 提交，添加了必要的打包脚本和构建标志，但默认关闭。此举旨在促进受限沙箱配置的测试和改善 XDG 门户支持，而非承诺官方支持。目前 Flathub 上的 Chromium 和 Chrome Flatpak 包均为社区维护，非谷歌官方构建。

谷歌为官方 Chrome Flatpak 添加构建支持

如果你通过 Flatpak 安装了 Chromium 或 Google Chrome，你安装的是由社区维护的非官方包，与这家搜索巨头无关——这种情况可能即将改变。

Chromium 的构建系统现在能够生成浏览器本身的 Flatpak 包，不过其开发者提醒，这一变化并不意味着官方 Flatpak 支持即将到来。

谷歌的 Tom Anderson 本周提交的更改添加了必要的打包脚本和一个构建标志（），用于生成 .flatpak 包，而不是 .deb 或 .rpm，但该标志目前默认关闭。

如果启用，谷歌的构建还将跳过生成 Flatpak 原生处理的内容（如符号链接、桌面文件等），生成的 Flatpak 构建将拥有自己的应用 ID，Chromium 对应 org.chromium.Chromium*。

Anderson 的提交信息指出，这“并非承诺官方支持 Flatpak 包”，而是旨在“促进受限沙箱配置的测试”并改进浏览器的 XDG 门户支持。

你可以在 Flathub 上找到 Chromium 和 Google Chrome 的非官方 Flatpak 构建，它们均由社区独立维护，并从源代码打包。这些是 Flatpak，但不是谷歌在其基础设施上构建的 Flatpak。

这一更改将相关的 Flatpak 打包工具添加到 Chromium 的内部构建系统中，以便如果——仍然是一个“如果”——谷歌确实决定进行官方构建，它可以轻松生成它们。

但谷歌不太可能正式将 Chrome 添加到 Flathub，原因与我们在 Snap Store 上找不到它的原因相同：这家搜索巨头不需要别人的基础设施成为其向用户推送更新的瓶颈。
