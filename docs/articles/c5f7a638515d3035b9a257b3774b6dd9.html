Google 工程师 Carlos Llamas 提交补丁，计划在 Linux 7.4 内核周期中移除约 1.1 万行旧版 Binder C 驱动代码，全面转向已成熟的 Rust 实现。Rust Binder 驱动自 Linux 6.18 上游化后，已在 Android 设备上稳定运行，功能与性能均达到或超越 C 版本，维护更简单。该移除补丁已被 Greg Kroah-Hartman 收入 char-misc-next 分支，即将提交合并窗口。

Google 的“维护痛苦”的 Binder C Linux 驱动将被移除，改用 Rust

2026 年 9 月 18 日下午 12:26 EDT。

用 C 语言编写的驱动长期以来一直是主线内核的一部分，作为 Android 上使用的进程间通信（IPC）机制。过去几年，Binder 驱动被用 Rust 重写，成为 Rust 语言中首批“真正的”驱动之一。Rust Binder 驱动已在 Linux 6.18 中上游化，而现在对于即将到来的 Linux 7.4 内核周期，旧的基于 C 的 Binder 驱动将被淘汰。

如今 Rust Binder 驱动已经足够成熟，并证明了其更易于维护和扩展新功能的实用性，旧的 Binder C 代码将被移除。Rust Binder 驱动还证明其在性能上具有竞争力——甚至更快——与原始 Binder 驱动相比。

Google 工程师 Carlos Llamas 在移除 1.1 万行旧 Binder C 代码的补丁中写道：

“这一天终于来了。我们正在放弃 Binder IPC 驱动的旧 C 实现，转而采用其 Rust 版本。

15 年多来，C 驱动变得越来越复杂，维护起来极其痛苦，在不触发漏洞的情况下添加新功能更是难上加难。Rust 实现缓解了大部分这些问题，所以是时候做出改变了。

Alice Ryhl 在过去几年里为 Rust binder 付出了辛勤努力，不仅实现了完整的功能对等，还证明它可以匹配并经常超越 C 版本的性能。它已经在 Android 设备上成功运行了一段时间，我们不能再称之为‘实验’了。

是时候继续前进了，撤掉 C 代码，将所有新功能和优化集中在 Rust 驱动上。

新的 Rust Binder 王万岁！”

告别旧的 Binder 驱动。Greg Kroah-Hartman 将这个移除补丁收入了 char-misc-next Git 分支。由于他将其排入 char/misc 代码的“-next”队列，该补丁将被提交到 Linux 7.4 合并窗口。
