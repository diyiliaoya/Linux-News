Portainer 切断免费版与付费版之间的纽带

免费社区版（CE）被冻结在 2.x，所有新开发都投入到一个 Kubernetes 优先的闭源实现中。

Portainer 开源已有十年，如今这一历程遇到了瓶颈。

Portainer 3.0——即将围绕 Kubernetes 从底层重建的平台——将不会成为 CE 的基础。

这一消息由公司 CEO 宣布，他表示 CE 将继续基于 Portainer 2.45 LTS，即 2.x 系列的最后一个版本。而此后的一切，如新控制台、新架构等，都不会移植到 CE。

相反，CE 将获得安全修复、错误修复以及 3.x 功能的后向移植，但仅限于存在匹配的 Docker API 可供对接的情况。功能对等无法保证，因为 3.x 中的一些功能依赖于 Kubernetes。

这是一个维护问题，而非战略转向。每次团队想要添加策略或 API 能力时，都必须分别构建三次该功能，分别为 Kubernetes、Swarm 以及 Docker 和 Podman 各一次。

Portainer 3.0 完全放弃了这种模式。取而代之的是五个独立的控制台，每个都围绕特定任务构建，而非一个界面处理所有事情。

他接着表示，CE 根本不适合这种新方式，Portainer 3.x 的策略模型、操作 API 和面向企业的控制台从一开始就假定用户是企业用户，“将其作为 CE 发布将歪曲它的本质和面向对象”。

这对你意味着什么

如果你已经在运行 Docker，今天没有任何变化。2.x 继续如常工作并持续获得安全补丁；保持现状是完全受支持的选择。

但如果转向 3.x，Docker、Swarm 和 Podman 环境仍可作为原生连接使用。对于希望在 Kubernetes 底层上继续使用 Docker 风格工具的用户，提供了兼容层，允许 Docker Compose 及类似工具在 Kubernetes 集群上部署和管理应用。

无论 Portainer 接下来为可观测性、GitOps 或其策略工具构建什么，都会首先面向 Kubernetes 环境，而原生 Docker 设置在界面中位置更低，且无法获得这些功能。

如果你想在不迁移到 Kubernetes 的情况下获得新功能，实际上没有办法免费获得并保持开源。唯一免费进入 3.x 的途径是通过 Portainer 现有的节点数受限的闭源商业版许可证，而非 CE 构建。

如果你想切换，有哪些替代方案

如果永远停留在 2.x 并不吸引你，以下是目前实际在开发中、可以考虑的方案：

Dockge，一个基于 Rust 的构建和部署平台，旨在管理多服务器工作负载。它没有人为的服务器数量限制，如果你习惯更偏向部署/自动化的方式，会特别感兴趣。

Arcane，一个使用 Go/SvelteKit 的 Docker 管理平台，具有现代 UI。它采用 BSD-3-Clause 许可证，提供容器、Compose、镜像、卷、网络、远程主机和 Swarm 管理等功能。

两者都不是每个 Portainer 工作流的直接替代品，尤其是如果你严重依赖 Portainer 更广泛的 Kubernetes 功能。但对于家庭实验室或小型 Docker/Swarm 环境，主要想要一个功能强大的自托管 UI 而不需要付费功能层，两者都是值得研究的可靠替代方案。
