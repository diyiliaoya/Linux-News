Linux 7.3-rc4 将修复 Btrfs 两个不幸的 Bug

Linux 7.3-rc4 合并了本周的 Btrfs 文件系统修复，包含两个重要 Bug 修复。一是自 Linux 7.2-rc1 引入的 fs_fsid 标识符推导方式变更导致向后兼容性破坏，影响依赖稳定 FSID 的应用（如 NetworkManager OpenConnect 的 VPN 密钥文件加解密），现已恢复从文件系统 UUID 推导。二是修复了 Linux 7.3 开发周期中 Btrfs 根文件系统在无 initramfs 时 GRUB2 无法检测根设备的问题。

Linux 7.3-rc4 将修复 Btrfs 两个不幸的 Bug

2026 年 9 月 19 日 20:26 EDT。

今天合并了本周针对 Linux 7.3-rc4 内核的 Btrfs 文件系统修复集，其中包含两个值得注意的 Bug 修复。

首先是 Linux 7.2-rc1 中引入的一个回归问题，由于 fs_fsid 标识符推导方式的变更，该问题一直存在至今。但这反过来破坏了向后兼容性，包括对用户空间应用的影响，因为 f_fsid 在内核更新后可能发生变化，并在重启之间发生偏移。对于期望稳定 ID 的应用来说，这破坏了依赖 FSID 来加密/解密 VPN 密钥文件的程序。例如，当使用 Btrfs 的用户升级到 Linux 7.2 后，NetworkManager OpenConnect 因此无法再访问 VPN。因此在 Linux 7.3-rc4 中，FSID 恢复为从文件系统 UUID 推导。

本周另一个主要的 Btrfs 修复仅存在于迄今为止的 Linux 7.3 开发周期中，它破坏了 GRUB2 对无 initramdisk 系统启动的处理检测。在 Linux 7.3 中，使用 Btrfs 根文件系统时，GRUB2 在没有 initramfs 的情况下无法检测到根文件系统设备。

这些修复以及一些更常规的 Btrfs 文件系统修复已于今天合并，赶在周日 Linux 7.3-rc4 发布之前。
