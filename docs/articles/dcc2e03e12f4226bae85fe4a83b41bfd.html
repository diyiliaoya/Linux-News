Linus Torvalds 表示他喜欢使用 AI，而他的新内核分支致谢 Claude Code

Linus Torvalds 在其内核仓库中创建了一个名为 noref-filemap-read-with-llm 的新分支，包含八个补丁，旨在优化多线程读取同一文件时的性能。该补丁跳过了引用计数步骤，使八线程读取性能从约每秒1000万次提升至3000-3300万次。提交信息致谢了 Claude Code 在其指导下完成代码、测试及审查。Torvalds 在布拉格开源峰会上表示他喜欢使用 AI，认为将其视为工具时效果良好，并称 AI 让编程更有趣。

Linus Torvalds 表示他喜欢使用 AI，而他的新内核分支致谢 Claude Code

他的八补丁系列利用 AI 辅助，减少了内核在许多线程读取同一文件时所做的额外工作。

Linus Torvalds 在自己的内核仓库中有一个新分支，名为 noref-filemap-read-with-llm。

它包含一个基于 Linux 7.3-rc6 加修复的八补丁系列，并且没有给出合并的内核发布目标。

虽然提交信息很长且技术性强，但这一改动本身很容易描述。

当许多线程读取同一文件时，内核从页面缓存（最近读取数据的内存副本）中为它们提供服务。如今，每次读取都会持有缓存数据，然后释放它。

每个线程都为此更新同一个计数器，导致线程相互干扰。该问题可追溯到 2024 年，当时 Matthew Wilcox 标记了它，并引用了客户的工作负载。

Linus 的补丁系列跳过了这一步。为了确保安全，离开缓存的内存在一小段时间过去之前不会被分配用于重用，因此读取者可以直接复制数据而无需持有任何东西。

代价是更多内存会闲置片刻。

在他自己的笔记本电脑上，关闭一些安全保护后测得的收益是：八个线程读取一个文件从每秒约 1000 万次读取提升到 3000 万至 3300 万次之间。

Linus 亲自进行了测量，但其余部分，提交信息致谢了 Claude Code，在其指导下工作。这包括提交信息本身的草稿、代码和测试程序，以及其已知问题列表背后的审查。

这不是他第一次在内核工作中使用 AI。八月份，他在 Intel Xe 图形驱动中使用了它。

他在布拉格说了什么

Linus 在布拉格开源峰会上与他的老朋友、爱立信软件技术负责人 Dirk Hohndel 进行了交谈。

ZDNet 的 Steven Vaughan-Nichols 在场，他引用 Linus 的话说：“我实际上真的很喜欢使用 AI。”

他说他过去认为 AI 不太好，但已经改变了想法。在他看来，只要将其视为工具，它就能很好地工作，并且让编程对他来说更有趣。

他提到了一个吉他踏板项目，其界面是他用 C 语言编写的。他想要更现代的外观，并尝试用 AI 来实现，他说：“我用 AI 做我不擅长的事情。”

他还为 vibe coding 辩护，称其为“一种在编程中寻找乐趣的绝妙方式”，主要面向新手，并表示虽然 AI 正在改进代码库，但它给维护者带来的负担已成为一个真正的问题。

这再次表明 Linus 在 AI 问题上的立场发生了多大变化。2024 年，他称 AI 行业“90% 是营销，10% 是现实”。

他正在积极使用它。
