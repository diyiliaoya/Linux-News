Linux 7.4 中 XFS 校验和的性能与资源占用得到改进

Linux 7.4 的 VFS IOmap 拉取请求引入了针对校验读取的惰性反弹缓冲，改变了 XFS 此前对所有直接读取无条件使用反弹缓冲的做法。新方案先将数据读入用户缓冲区，仅在校验失败时才分配反弹缓冲并重读，从而避免了几乎不必要的 DRAM 带宽和 CPU 拷贝开销，并消除了因反弹缓冲导致的更小且未对齐的 I/O。

在作为开发中 Linux 7.4 初始材料的众多 VFS 拉取请求中，VFS IOmap 拉取引入了针对校验读取的惰性反弹缓冲。这一改进使 XFS 上的校验和受益，提升了性能并降低了资源占用。

Christian Brauner 描述了当前问题以及现已合并到 Linux 7.4 的 IOmap 代码的改进方案：

“主体是针对校验读取的惰性反弹缓冲。XFS 会对需要稳定页面进行校验和的设备上的每次直接读取都使用反弹缓冲，这样用户空间在读取进行中修改缓冲区时就不会破坏数据并导致校验和失败。这会消耗 DRAM 带宽和 CPU 进行几乎从不需要的拷贝，而且由于反弹缓冲是 bio_vec，会产生更小且未对齐的 I/O，使用 4k 页面，即 1 MB 减去 4k。现在读取先进入用户缓冲区，只有校验失败时才分配反弹缓冲并再次读取。完整性验证从 iomap 移到文件系统，以便文件系统能以自己的方式处理错误。”

此前 XFS 在使用校验和时无条件使用反弹缓冲。那个 DRAM 带宽和 CPU 周期的消耗者现在不复存在。在该补丁系列上，我没有看到任何量化由此产生影响的数字。
