Ubuntu 26.04 虚拟化 HWE 堆栈提供更新的 QEMU 和 libvirt

Canonical 为 Ubuntu 26.04 LTS 推出了虚拟化硬件启用（HWE）堆栈，通过每6个月更新一次的方式，向后移植新版 QEMU、libvirt 及相关固件，让用户在不依赖第三方仓库的情况下获得更新的虚拟化功能。该堆栈特别适用于机密计算工作负载，支持 AMD SEV-SNP 和 Intel TDX 技术。用户可通过安装 ubuntu-helper-virt-hwe 工具包并运行相应命令来启用和切换 HWE 版本。

Ubuntu 26.04 虚拟化 HWE 堆栈提供更新的 QEMU 和 libvirt

Ubuntu 的硬件启用（HWE）工作已扩展至包括将更新的虚拟化技术向后移植到当前 LTS 版本的用户。

来自 Canonical 的虚拟化 HWE 堆栈将让用户在其现有 LTS 安装基础上受益于更新版本的 QEMU、libvirt 及相关固件，每6个月刷新一次，持续2年，无需通过第三方仓库寻找。

或者，引用 Canonical 的话：“LTS 版本的操作信心，加上在需要时获得更新虚拟化能力的路径”。

如果你不熟悉 HWE，它就是将当前 Ubuntu 版本中更新的 Linux 内核、GPU 驱动程序和其他一些基础组件带到较旧 LTS 版本，使其能够在较新硬件上工作并启动。

HWE 更新每6个月推出一次，向后移植来自中间版本的“经过实战检验”的软件包。例如，即将发布的 Ubuntu 26.10 版本中的内核和 GPU 驱动程序集将包含在 2027 年初的 Ubuntu 26.04.2 HWE 更新中。

Ubuntu 虚拟化 HWE 包含什么？

软件包（如果你想知道）包括 qemu-system-data（它捆绑了 OVMF 固件）和 libvirt-clients。这些在 Ubuntu 26.04 LTS 上均未预装，因此只有那些主动寻找的人才能受益。

而肯定想要寻找的人正是那些运行机密计算工作负载的用户。

Ubuntu 26.04 已经支持 AMD SEV-SNP 和 Intel TDX——这些技术用于加密虚拟机的内存，使其在运行时连宿主机也无法窥探内部——但正如 Canonical 所指出的，“机密计算功能很少同时出现在所有相关组件上”。

如果堆栈的其余部分尚未跟上，仅靠内核支持作用不大。等待两年直到下一个 LTS 版本推出并不总是可行，切换到中间版本也会带来其他方面的变动，影响生产工作负载。

如果这些新闻对你毫无意义，或者你使用的是 Virtualbox 或 VMware Workstation 而非 KVM/QEMU，那么不必担心；这不会影响你。

但如果你觉得“有点意思”，以下是在 Ubuntu 26.04 LTS 上设置它的方法。

在 Ubuntu 26.04 上启用虚拟化 HWE 堆栈

Canonical 提供了一个辅助工具包，用于在 Ubuntu 26.04 LTS 中启用新的虚拟化 HWE。这有助于确保 HWE 和非 HWE 软件包之间没有不匹配。

该辅助工具可以从 Ubuntu 26.04 'resolute' 仓库安装：

sudo apt install ubuntu-helper-virt-hwe

安装完成后，单独运行 ubuntu_virt_helper 它会告诉你当前使用的是哪个版本——例如“virt: stock”（如果你只是为了好玩而尝试，你会看到后者）。

要在 HWE 和非 HWE 版本之间切换：

sudo ubuntu_virt_helper switch

确保你也安装了内核 HWE 堆栈：

sudo apt install linux-generic-hwe-26.04

需要重启后新软件包才会生效，但仅此而已。

Ubuntu LTS 版本构成了该发行版在桌面、云和企业领域的大部分安装基础。对于运行机密虚拟机的那一小部分用户，这个新堆栈在可靠的基座上，以可靠的节奏提供了对更新版本的可预测访问。
