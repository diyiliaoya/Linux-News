openEuler 与构建亚洲 AI 基础设施的竞赛

openEuler 是由开放原子开源基金会孵化和运营的开源项目。该社区正通过本地用户组、行业合作伙伴关系以及参与全球开源活动来扩展国际合作。

谈到开源和 AI，我们几乎总是把目光投向西方。虽然美国发生了很多事情，欧洲也有一些，但东方也没有落后。

在最近结束的会议上，多家初创企业和公司齐聚一堂，展示他们的创新并分享他们正在构建的东西。

其中，openEuler 因其对开源 AI 的关注而引起了我们的注意。

展示了其 SuperPoD OS，该系统扩展了对基于 UnifiedBus 的 SuperPoD 计算系统的操作系统支持。

可以把 SuperPoD 看作是一组强大的计算机集群，它们需要像一台巨型机器一样运行。运行 AI 工作负载需要计算能力，而在数百台这样的机器上运行则非常混乱，因为它们需要共享内存、快速传递数据，并且不能相互冲突。

是 openEuler 生态系统中的开源软件层，它使这些机器之间的协调真正发挥作用。它为基于 UnifiedBus 的 SuperPoD 提供五个集群级系统服务：引擎、内存、通信、I/O 和虚拟化。

引擎在整个集群中池化内存和 DPU 资源，并动态调度它们。它还处理自动故障转移，以便在节点宕机时系统仍能继续运行。

内存组件允许基于 UnifiedBus 的 SuperPoD 内的机器使用统一内存编程来共享和池化内存，这意味着软件可以将分布式内存视为单个可寻址空间。

通信组件通过 UnifiedBus 提供高性能网络，同时保持与标准 Socket 和 Verbs 接口兼容，因此现有应用程序无需重写即可受益。

I/O 服务在高层处理全局数据读写缓存，这对于像 AI 推理这样反复访问大型共享数据集的工作负载很重要。

虚拟化组件涵盖虚拟化池化，决定实时迁移策略（何时以及如何将运行中的虚拟机移动到另一台机器），支持灾难恢复，并提高虚拟机和容器之间的通信效率。

这五项服务共同为 SuperPoD 集群提供了像单个组织良好的系统一样运行所需的协调能力，据称比传统架构性能提升 30-50%。

据 openEuler 称，UB Service Core 可以利用点对点 UnifiedBus 互连架构将应用程序性能提高 30-50%。

这个 SuperPod 或 UB Service Core 在 openEuler 旗下完全开源。

openEuler 正在向 AgentOS 模式演进。在 openEuler 24.03 LTS SP4 中，DevStation（openEuler 的桌面变体）包含 openEuler Intelligence，这是一个桌面 AI 助手，使用代理运行时和基于 MCP 的工具来支持开发和系统操作。

如今，操作系统中预构建的代理利用并不罕见。openEuler 24.03 的内置 AI 代理可用于控制 Linux 系统。

因此，无需手动通过鼠标点击来操作，你可以直接让代理调暗亮度、降低音量或更改壁纸。内置 AI 代理具有自定义技能，可以控制 openEuler 的 UKUI 桌面环境中的系统设置。

这项工作仍在进行中。但方向是明确的。AI 代理应该很快就能让你控制系统，而不是手动操作。

扩展为基于社区的生态系统

openEuler 已启动 openEuler 香港用户组，旨在汇聚香港的开发者、研究人员和组织，共同联系、分享经验并探索开源创新。
