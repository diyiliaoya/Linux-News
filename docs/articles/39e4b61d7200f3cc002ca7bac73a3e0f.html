Ubuntu 26.10 将采用基于 Rust 的 GnuPG 替代品

Ubuntu 26.10 将预装基于 Rust 的 Sequoia PGP，提供 sq 和 sqv 命令，与现有的 gpg 和 gpgv 并存。Canonical 计划最终用其替换 GnuPG 作为默认 OpenPGP 工具链，但这一转变尚未发生。Sequoia PGP 由前 GnuPG 开发者于 2017 年创建，支持新的 RFC 9580 标准，目前仍处于早期阶段。

Ubuntu 26.10 将采用基于 Rust 的 GnuPG 替代品

基于 Rust 的 OpenPGP 工具进入 Ubuntu 26.10 的主归档，sq 和 sqv 将与 gpg 和 gpgv 一同提供。

你已经知道，Canonical 一直在选择性地用 Rust 编写的等效组件替换 Ubuntu 中基于 C 的系统组件，且功能上毫不妥协。

现在看起来，该发行版的 OpenPGP 实现将是下一个目标，Sequoia PGP 将在 Ubuntu 26.10 中预装。Canonical 希望它最终取代 GnuPG 成为默认工具链，不过这一转换尚未发生。

在深入了解 Sequoia 之前，有必要知道 OpenPGP 究竟是什么。它不是工具，而是一个被广泛采用的标准。Phil Zimmermann 于 1991 年创建了最初的 PGP，如今 IETF 维护着这项工作的开放版本。该规范定义了软件应如何加密、解密、签名和验证数据，以便任何两个遵循该规范的实现都能互操作。

GnuPG 一直是该标准的主导实现。它用 C 编写，在平台上实现了 gpg 和 gpgv 命令，处理从加密、密钥管理到独立签名验证的一切事务。

Sequoia PGP 则不同。

它由三位前 GnuPG 开发者于 2017 年发起，他们选择用 Rust 构建新的 OpenPGP 实现，而不是继续演进 GnuPG 的现有代码库。

Sequoia 被设计为一个库，供其他软件直接使用，而非独立的命令行工具。sq 在其之上提供加密、解密、签名和密钥管理，sqv 处理签名验证，填补 gpgv 的角色。

Sequoia 还实现了 RFC 9580，即 2024 年修订的 OpenPGP 标准，而 GnuPG 则继续沿袭 RFC 4880 分支，追求自己的新扩展和 LibrePGP 规范，而非将 RFC 9580 作为主要标准。

Ubuntu 26.10 “Stonking Stingray” 已作为默认安装的一部分从 rust-sequoia-xx 拉入 Sequoia PGP。我在 Ubuntu 26.10 的开发版本上运行了 sq 和 sqv，两者均正常工作。sq 充当加密、解密、签名和密钥管理的主要接口，而 sqv 处理签名验证。输入 gpg 仍然路由到 GnuPG，因此这两个 OpenPGP 实现并存。

如果 Sequoia PGP 成为默认，你可以预期这些命令和其他 GnuPG 命令将路由到 Sequoia，类似于我们在 sudo-rs 上看到的情况。

仍有很长的路要走

最近的一则公告明确提到，Sequoia PGP 成为 Ubuntu 默认 OpenPGP 工具链是一个未来目标，而非已经默认的体验。过渡始于 2025 年，直到 26.10 才达到 100%。切换在成为默认之前就已提前展示。每个组件都必须经过多个发布周期才能赢得自己的位置，然后才会对用户产生任何变化。

Sequoia PGP 正处于这一过程的起点。进入主归档是第一个里程碑。它最终能否取代 GnuPG 成为默认还有待观察。

Canonical 尚未分享具体的纳入时间表。鉴于他们在其他所有 Rust 过渡上如此谨慎，对于像 OpenPGP 这样基础性的东西，这种谨慎不太可能消失。
