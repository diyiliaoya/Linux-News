Ubuntu 将另一个系统 Deb 包转换为 Snap

Ubuntu 正在将其另一个核心系统 Deb 包转换为沙盒化的 snap 格式，以提升安全性并改善桌面集成。该包为 hwctl，是一个预装在 Ubuntu 桌面和服务器上的小型命令行工具。Canonical 工程师 Sergio Costas 表示，为了将 hwctl 与 gnome-control-center 及其他前端集成，并增强安全性，hwctl 包将仅以 snap 形式提供。在 Ubuntu 26.04 LTS 上，用户将自动迁移至 snap 版本，现有系统通过更新将 Deb 包替换为自动安装 snap 的虚拟包。Ubuntu 26.10 及更高版本将直接默认包含该 snap。

Curl 被误从 Ubuntu 26.04 最小云镜像中移除

Ubuntu 26.04 LTS 的最小云镜像中意外缺失了 curl 工具，该工具常用于脚本和 CI 流程中下载文件。Canonical 已确认这是错误，并已将 curl 重新加入镜像。此前，curl 作为 pollinate 的依赖项被包含，但 pollinate 在 26.04 中被移除，导致 curl 也随之消失。现在 curl 已明确加入最小云镜像种子，并正在推送更新，现有安装将在下次更新时恢复。不过，Canonical 正在讨论是否在未来的 26.10 版本中正式移除 curl，以保持最小镜像的极简性。

GCC 编译器禁止 AI 代码贡献，但方式合理

GCC 指导委员会本周通过了新的 AI 政策，计划于 2027 年初进行审查。该政策规定，若贡献具有法律意义且部分内容源自大型语言模型，GCC 将不予接受。但允许维护者接受法律意义不大的 AI 生成贡献，前提是明确标记并符合项目标准。测试用例可豁免。政策仅适用于 GCC 本身，从其他项目导入的代码不受影响。AI 辅助贡献需在提交信息中添加“AI”标签。该政策比 Codeberg 的全面禁令更宽松，但比 Linux 内核的披露政策更严格。

Linux暂存区将拒绝LLM生成的补丁，真正的安全修复除外

Linux内核的暂存区（staging area）将不再接受由大语言模型（LLM）生成的补丁，除非这些补丁是针对真实安全问题的修复。Linux内核维护者Greg Kroah-Hartman表示，暂存区的主要目的是让新开发者学习内核开发，而LLM生成的补丁违背了这一初衷。他警告说，LLM生成的补丁很容易被识别，且其中至少三分之一是错误的或有害的。对于声称是安全修复的补丁，提交者必须在真实硬件上测试并描述测试过程。
